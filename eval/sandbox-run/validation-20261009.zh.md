2026-10-09。本记录属于开发验收，正式留出题仍为 **0/24**。机器计数见[验收记录](validation-20261009.json)，固定执行口径见[协议](protocol.zh.md)。本轮未重启日常 3080，也未覆盖此前冻结结果。

## 已实现的交接

主 Agent 在原生 Standard 模式创建 Task 并提交计划。审查者独立读取快照、制定检查、执行检查，之后才对照主 Session。插件控制器负责裁决应用、节点调度及有限恢复；Python 监控器只按冻结协议批准、交付指定修订、续期、停止与收集。夹具或官方评分器在 Agent 结束后独立评分，不回传失败提示。

每次运行使用持久租约、动作预留与原运行身份。响应未知时核对原动作，不重复投递或增加授权。任务截止包含 Host 启动、规划、批准、审查及恢复；沙盒续期只延长资源存活，不改变截止。完成记录若出现在最后一个轮询间隔内，在停止后核对持久原生记录，不凭模型声称完成。

## 资源与收集边界

主环境 2 CPU／8 GiB，独立检查 2 CPU／8 GiB，管理员 1 CPU／1 GiB。新投递前核对 Docker 30 GiB、宿主 8 GiB 余量及 5 CPU／17 GiB 容量。主写层 20 GiB、检查存储 4 GiB 每 60 秒采样并停止超限；不是硬配额，瞬时峰值仍可能超限。检查 CPU 时间没有可靠记录，保持 null。

产物包括未提交、未跟踪文件用于诊断；正式提交只取 Agent 已 commit 的 base..HEAD 二进制补丁。检查源、副本和输出在资源停止后归档，校验压缩文件完整性及摘要，再释放本次拥有的卷。响应丢失后验证原导出，不运行第二次导出；不完整导出保留为故障。fault-3 收集发现管理员状态变量被检查容器变量覆盖，管理员虽停止仍残留；已分开变量，从原现场核对清理账本后释放，保留原记录及追加修复凭据。只有产物与检查存储均收集完成后才允许评分。

15 个已封口旧 P2 停止容器已保存基线镜像身份、改动归档、删除路径及私有配置后释放，原结果摘要保持不变。恢复材料仅存在私有缓存；不能把私有容器配置提交到公开仓库。
