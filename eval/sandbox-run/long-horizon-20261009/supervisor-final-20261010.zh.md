# Supervisor 公开题评测：八次运行收尾

## 范围与结论

四道 DeepSWE 留出题、每题两次重复，**Supervisor 8/8 个原位置均已封口**。用户随后要求以 Supervisor 完成为本轮终点，停止 Goal／Plan 后续评测。[范围封口记录](scope-closure-supervisor-only-20261010.json)保留原 24 个位置的处置：8 次 Supervisor、此前 5 次 Plan、1 次已启动后取消的 Goal，以及 10 个未投递位置。取消的 Goal 已停止、收集并销毁原沙盒，不运行官方评分，不记产品失败；已有结果不覆盖。

**本冻结版本能独立检查和保留恢复证据，但没有稳定完成整题实施、验收与结束。** 六次取得官方评分：一次 reward=1、五次 reward=0；另两次执行基础设施异常 reward=null。严格成功为 **0/8**。这是四道题上的观察，重复运行不是八道独立题；Goal／Plan 未完成配对，不能据此宣称 Supervisor 更好或更差。

结果与成本由[机器报告](supervisor-final-20261010.json)绑定[第十三份正式结果快照](reports/20261010-102010Z/summary.json)及每份原始 result.json 摘要。报告处理未改变冻结插件、输入、批准、绝对截止、产物或官方成绩。

## 逐题重复结果

官方评分只接收 Agent 自己已 commit 的 base..HEAD 补丁。未提交改动用于诊断，评测器不代为提交。严格成功还要求截止前控制器完成，且没有执行、收集或评分异常。

| 题目 | r1 官方 reward／首次停止 | r2 官方 reward／首次停止 | 严格成功 |
|---|---|---|---:|
| Geo | 0／任务截止 | 1／恢复预算耗尽 | 0/2 |
| Koota | 0／内部审查故障 | 0／内部审查故障 | 0/2 |
| Superjson | 0／内部审查故障 | 0／内部审查故障 | 0/2 |
| Updo | null／基础设施异常 | null／基础设施异常 | 0/2 |

Geo／r2 的 Agent 已提交补丁通过全部 623 项官方测试，但控制器在新尝试的审查中耗尽恢复预算并暂停，没有完成整体验收。官方产物通过和任务完成必须分别报告；这条轨迹本身不证明暂停错误。

两次执行基础设施异常与一次额外收集所有权异常合计影响三个位置。收集异常发生于 Superjson／r2，修复后从同一原产物取得 reward=0；因此异常位置数与实际评分数有重叠。未评分位置不能被补为零，也不能从分母消失。六次实际评分的一次满分是 1/6 的观察比例，不能视为完整八次的产品成功率。

## 最后一个位置发生了什么

Superjson／r1 的首节点 `core-modules` 在一次内部超时后，以同一作业、审查 Session、要求版本、节点尝试、证据截止和快照恢复。旧读取资格保留，裁决只应用一次，主 Agent 随后实际开始 `integration`，详见[恢复与交接证据](supervisor-superjson-recovery-applied-v10.json)。

第二节点[审查失败记录](superjson-integration-review-failure-r1.json)显示：两次尝试各达到自身 600 秒截止；累计 12 次命令检查、6 项持久独立发现、14 次工具错误，已进入对照阶段，却没有调用 `task_review_decision`，也没有持久裁决或放行。读取范围按同一身份、总长度及范围覆盖核对；原先 8 份文件及 9 条检查输出读取资格在恢复和终态仍保留，追加范围不等于资格丢失。

其中一次检查修改了检查副本内的 Vitest 结果缓存，引用时被现有证据资格校验拒绝；其余错误包括提前读取对照证据、未完整读取产物及参数校验。机器报告保留错误序号与摘要，无法可靠归类的错误明确标为未分类。检查副本变化不直接证明产品错误；本轮没有为了通过而放宽校验。

两次节点审查的重试上限耗尽后，Task 暂停；整题累计确认两次内部恢复，没有新增批准或救场。Agent 尚未产生新 commit，正式补丁为空。官方独立评分为 **reward=0，F2P 0/80，P2P 116/116**；未提交实现没有进入这份成绩。

## 独立检查与成本

六个位置实际执行了独立命令检查。八次累计 **234 次命令检查、74 项持久独立检查结果、2,165 次模型请求**。审查工具调用 2,428 次，全部 Session 工具调用 3,172 次、工具错误 253 次，审查工具约占 76.5%。执行检查、形成发现、提交裁决和有效应用分别统计，不能互相替代。

八次执行窗口累计约 **11.45 小时**，包含规划、实施、审查、重试和等待；这是跨位置相加，不是 CPU 时间，也不能推算审查全程阻塞主 Agent。记录了 11 次 Task 故障恢复预留、1 次截断恢复预留、53 次审查读取失败及 29 次完全重复读取；预留数不等同于成功恢复数。全部位置人工救场为零，原始投递和协议批准仍另计 14 次动作。

全部 Session token 总量保持 null：部分请求缺少用量。已报告下界为 uncached-input **6,711,976**、output **4,627,749**、cache-read **153,876,093**、cache-write **0**。跨请求 cache-read 累计不代表单个上下文长度，额外检查 CPU 时间也为 null。实际日志记录上下文压缩 0 次；长时限不能代替长轨迹或压缩机制的证据。

四个独立题目不足以推断总体表现。重复运行存在相关性，本轮不按八个独立样本计算置信区间；未完成条件配对，条件差异和优越性指标保持 null。没有盲审或人工因果标签，误验收、误暂停及纠偏收益也保持 null。“宣布完成但官方失败”记录为零，只表示没有匹配到此机械事件，不能证明不存在其他误判。

## 已确认的修复优先级

以下是后续开发事项，本轮冻结条件内没有实施。

1. **规划修订后的续行校验。** Geo／r1 的已应用 `revise` 没有增加计划版本，后续门禁却要求新版本，规划因此停住直到绝对截止。应按 pass、revise、needs-user 各自语义校验，仍不得由修订意见生成实施授权。
2. **裁决提交、持久化与应用的交接。** Koota／r2 出现 recorded:true 回执后无持久裁决；需要复现审查截止与记录刷新之间的竞争，明确回执含义并保证有效提交只应用一次，不能以回执直接放行。
3. **取证协议的收敛。** Koota／r1、Superjson 两次运行都在审查内耗尽时间。应减少重复取证，提供明确的阶段、字段与证据资格错误，并用正反夹具验证同作业纠正；保留两阶段隔离和有界恢复，不靠延长截止或弱化验收取得通过。
4. **交付状态与成本可见性。** 区分已实现、已 commit、已审查及整题完成；显示当前剩余要求、停止原因和自动恢复余额。官方评分要求已提交补丁，本轮评测器没有替 Agent 处理提交。

[七次阶段分析](supervisor-interim-20261010.zh.md)保留先前捕获与具体故障链接；[最后一次失败证据](superjson-integration-review-failure-r1.json)补充同作业读取资格没有丢失，却未完成裁决的案例。存储采样及收集器所有权修复是运行框架修复，不能计作插件能力提升。

## 封口与保留环境

原串行批次控制器和其 Goal 监控进程已停止；取消位置通过公开 Session 取消及 Host 退出完成静默收集，原沙盒已销毁。[资源核对](resources-closed-supervisor-only-20261010.json)确认全部 14 个启动位置的原沙盒已销毁，所属网关没有残留运行容器或存储卷。所有 Supervisor 位置已保存原产物、日志摘要和官方结果。不得按原 24 位置脚本继续投递，也不得将取消／未投递位置自动重跑。

冻结包、协议、原顺序、运行器修复版本及私有证据保留在登记环境，日常 3080 未改动。本轮未发布 npm 新版本。未来运行需新的授权及独立批次；已投递或用于诊断的题不得重新标为未见题。
