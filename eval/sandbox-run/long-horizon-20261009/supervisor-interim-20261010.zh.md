## 审查实际做到了什么

五个位置实际执行了独立产物检查。累计 217 次命令检查、61 项持久独立检查结果、2,147 次审查工具调用；全部 Session 累计 2,811 次工具调用，其中 210 次工具错误。读取、运行和结果持久化分别计数，执行检查不自动代表要求已满足。

[Koota／r2 证据](supervisor-first-independent-stage-v6.json)记录先制定检查方案、再读取交付物、持久化独立发现后才展开主日志。[Geo／r2 证据](supervisor-first-applied-independent-v6.json)还证明一次独立节点裁决有效应用后，主 Agent 实际开始下一节点。这些结果支持已实现独立检查和交接能力，不证明整题验收可靠或纠偏收益为正。

[Superjson／r2 证据](superjson-node-review-failure-r2.json)记录 11 项计划检查、9 个已读取文件、10 次命令检查及 11 项持久发现。第一次裁决首先被 K3 引用的检查结果拒绝：该结果记录了一项检查副本变化，未满足现有运行证据资格；另有 read 标准混用日志引用。第二次提交缺少 verdict。最终没有有效裁决，不能把独立 Session 或模型自述当成完成验收。

## 后续修复优先级

以下是本批结束后的开发建议，未在冻结条件内实施。

1. **恢复后的规划续行。** 按实际裁决区分 pass、revise 和 needs-user 的版本关系；revise 不增加计划版本时应能继续规划，仍不得产生实施许可。已有 [实际记录与源码复现](supervisor-planning-recovery-terminal-v6.json)支持该缺口。
2. **裁决回执与持久应用。** 记录成功回执应准确指明已提交还是已应用；验证提交、停止审查、刷新日志和快照新鲜度之间的截止竞争。不得仅凭 recorded:true 放行下游，也不能丢失一个已经满足持久提交条件的裁决。
3. **取证与裁决收敛。** 针对缺失字段、证据方法不匹配和修改过的检查副本给出可定位错误；用正确及错误夹具验证修正路径。保留证据资格、两阶段隔离和有限预算，不通过放宽验收或延长截止获得通过。
4. **提交产物的可见性。** 在任务进度中明确区分已实现、已 commit、已审查和已完成；及时暴露仍未提交的交付物。先确认产品对目标产物的要求，再决定如何提示，不能由评测器替 Agent 提交。

运行环境故障已有独立的 [存储采样修复](supervisor-storage-observation-fault-v6.json)和 [收集所有权修复](repair-v10.json)。后续位置从未投递身份继续，原失败保留；这些修复不能算作 Supervisor 的能力改进。

## 接续评测

当前最后一个 Supervisor 位置使用原 Session 和冻结 v10 运行器。控制器保持单实例、一次初始批准、原官方截止、不救场及不可覆盖结果；正常产品失败后继续剩余 Goal／Plan 位置。确定的运行器、资源或评分故障才暂停新投递并单独记录修复版本。
