# 审查恢复与观察频率审计

本目录提供原生日志统计，不替代外部任务评分。运行 `python3 summary.py <主 Session jsonl> <新的输出 JSON> [--labels <标注 JSON>]`。输出路径已存在时拒绝覆盖；原 NodeBB/Navidrome 冻结结果保持不变。

## 实验设置

`progressReviewMode` 支持 `current`（默认）、`configured`、`required-only`。前两者均使用实际配置的结果数量、时长、连续错误与轮次阈值，`configured` 是明确的实验标签；当前默认分别为 24、300000 毫秒、3 次、3 轮。`required-only` 关闭轮次及轮内额外进展观察，不关闭计划覆盖、节点和完成审查。已有 `observeLongTurns` 和阈值配置兼容保留。每个审查作业持久记录实际参数，不能只依赖实验名称推断运行配置。

对三个策略使用相同公开任务、固定模型、审批规则、补交上限、总时限和独立干净工作区。`configured` 的稀疏实验可先固定 48 条结果、600000 毫秒、3 次连续错误、6 轮；这是一组比较条件，不是被证明更好的默认值。冻结版本、题目、环境与完整分母后再开始正式比较。开发回归不计入正式未见样本。

## 指标边界

统计分母为日志里的唯一作业，补交和重试不会算作新的独立作业；通过记录之后失败的结束回调不把成功决定改成故障。协议缺失既包括最后失败，也包括已补交成功的先前轮次。手动等待时间与模型审查等待分开，旧日志没有单次恢复起点时不编造耗时。原审查 Session ID 可用于追溯 Token 和原始失败。

标注文件按 jobId 记录 `drift`（是否真实偏离）与 `correctionEffective`（纠偏是否被之后证据证实）。没有标注时误暂停率与纠偏效果返回 null；正常探索的 needs-user 判断需人工复核。遗漏偏离需要另外标注未触发审查的区间，不能由该工具推断。外部 reward、按时结束、全 Session Token 从独立评分器与原生 tokenUsage 另行采集。

Python 独立夹具覆盖成功补交、服务错误后手动恢复、无数据和旧记录未知耗时；通过 Vitest 宿主门禁运行。真实模型与公开题回归证据在 [A–F 执行记录](../../docs/10-plans/conversation-and-review-recovery/evidence/)。

后续四题、五组、三次重复的运行前冻结条件见[频率比较协议](frequency-p2-protocol.zh.md)。60 次计划尝试未运行；本轮 NodeBB 仅为开发回归。
