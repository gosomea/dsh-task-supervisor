# 后续观察频率比较协议

**2026-09-28，运行前冻结；本协议的 60 次计划尝试尚未执行。** 机器清单见 [frequency-p2-protocol.json](frequency-p2-protocol.json)，统一研究问题、数据集和长期路线仍以[评测设计](../../docs/evaluation.zh.md)为准。

## 为什么单独比较

协议恢复、可追溯故障和持续对话解决可用性问题，不能证明进展审查越频繁越好。既有 NodeBB、Navidrome 已用于调试和结果分析，留作开发回归；比较频率时不能把这些已见题当成留出成绩。本轮新 NodeBB 运行单列为开发回归，原冻结成绩保持原样。

## 固定条件

从原六题清单保留尚未投递模型的 Open Library、qutebrowser、Flipt、Ansible 四题，题目 ID 和指令哈希沿用原冻结清单。每题三次配对重复，比较 Goal、Plan、Supervisor 当前频率、稀疏频率、仅必要审查，共计划 60 次。稀疏组为 48 条新工具结果、600000 毫秒、连续三次错误或六轮；仅必要组保留计划、节点及完成审查。三种 Supervisor 条件采用同一代码版本、协议补交一次及审查总时限，阈值是实验条件，当前默认不修改。

首次模型运行前再冻结精确宿主/插件源码哈希、解析模型及有效配置；若此后需要修代码，结束该批并新建协议，不覆写成绩。各题必须先在同一官方镜像通过空补丁 0、参考解 1、零评分异常门禁。未过门禁的题单列基础设施原因，不临时替换成更容易的题。

所有 Agent 使用相同模型、权限、1 CPU / 4 GiB 与 3000 秒上限，各条件独立干净容器。模型运行顺序按清单中 seed/题目/重复/条件的 SHA-256 排序，按配对重复逐个运行。Plan/Supervisor 只提供规定的一次初始批准，不追加救场提示。独立评分器保留官方测试原字节，隐藏测试与参考解不进入 Agent 环境。

## 指标和分母

主成功必须同时满足按时结束、独立 reward=1、评分异常=0；超时补丁通过只能算诊断成绩。报告已准入尝试的完整分母，内部故障暂停与超时计入失败，基础设施异常另列。记录主/审查/Worker/咨询 Session 的实际 Token、总时长、审查等待、协议缺失、补交成功/耗尽、手动恢复、有效用户决策及人工介入。

误暂停、纠偏收益和遗漏偏离需要盲审标注；无标注时保持 null。过期而未应用的 needs-user 不算实际暂停。比较逐题配对结果和不确定性；四题仍属接入与机制实验，不能直接支持优越性结论。多任务 Session 在公开单题比较之后另立 P3 协议，不把不同基础仓库的题硬拼成同一工作区。
