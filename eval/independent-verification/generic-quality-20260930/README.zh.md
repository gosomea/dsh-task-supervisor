## Kea 冻结与边界

题目已用于此前分析，只作开发回归，不是未见题，不用于宣称优于 Goal 或 Plan。新主模型只收到原始题目，没有隐藏测试或失败提示。插件 `0a92ba1`、运行器 `fbbab67`、原题、镜像与 profile 已冻结；一次初始授权、10800 秒固定截止、暂停封口不救场，只评分 Agent 已 commit 的补丁。

第一次准备位置的控制命令在 30 秒被取消，原生日志证明没有模型步骤，独立封口为投递前基础设施故障。修复后分配新位置，不复用其 Session，不覆盖原记录。命令预算增加为 660 秒，任务总截止保持不变。

浏览器/视觉独立执行器仍不可用。读取和运行只证明各自覆盖范围；已有测试全绿、文件存在或运行退出码为零不能单独推出要求满足。没有盲审的误暂停、纠偏收益和误验收率保持 `null`。检查语义质量及长程优势仍需外部评分和更大样本验证。

## 完整原生任务与后续修复

`a859b43` 修复了正式评测暴露的两项通用协议错误：实际读取的原始用户消息现在获得引用资格；仅规划观察作业具有 `planning` 字段，正式计划及产物审查工具不再暴露它。上下文显示作业种类，引用错误显示已读和未读序号。新版通用协议也不再把主 Agent 标注的 `evidenceKind: runtime` 当成必须运行的理由；旧协议保持原有行为。

[完整静态任务](full-static-task.json)使用正常 `/task new` 与控制器，初始执行由 profile 预授权，没有人工救场。主 Agent 创建 `brief.md`；节点与最终审查各自制定检查并读取当前产物，随后任务真正进入 `complete`。外部读取确认标题为“摘要”、正文仅为“天气晴朗。”，工作区没有其他产物。两次独立产物审查共 8 项检查结果、0 次命令；主 Agent 的回答仍原生展示。

耗时 374.087 秒，审查工具调用 89 次、相同参数重复读取 2 次。全部关联 Session 的 token 已报告：非缓存输入 139091、输出 39538、缓存读取 928768、缓存写入 0。71 次真实 HTTP 请求均匹配 CodeBuddy `deepseek-v4.1-flash` 路由。

能力匹配仍有开销：前两份计划审查错误地认为列出文件需要命令运行器，准备检查拒绝批准；主 Agent 自行改为只读计划，第三次才获准实施。没有静默降级或人工救场，但本例不能证明能力选择总是准确。正式计划审查依旧读取日志，节点与最终验收才使用独立产物协议。一次更早的静态任务准备夹具因权限切换留下未消费的 inbox 而被准入拒绝，模型未投递；保留为准备故障，不算成功任务。
