# 独立检查公开题接入

## 摘要

本目录记录增强审查的无模型接入校准。新模型评测按[评测主文档](../../docs/evaluation.zh.md)的 Terminal-Bench 控制题、DeepSWE 工程题顺序推进。本目录的代表镜像探针不构成正式题通过或模型准入。

## 快照链接回归

[机器证据](snapshot-20260928.json)保留默认容量失败、扩容后截止、仍超项数及真实 fixture 捕获结果。合法内部悬空链接现在保留原始目标字符串；展开目录链接后继续检查边界，默认拒绝绝对、外部、排除内容与循环链接。管理员可通过 `runtimeLinkTargets` 声明检查镜像自身提供的绝对链接目标；仅保留原字符串，不读取宿主目标，未声明目标仍拒绝。POSIX 反斜杠文件名在捕获和审查读取中都按文件名处理。

- Node 24：12 项快照与 4 项两阶段审查回归通过；Host/Client 严格类型检查和构建通过。
- 实际 Docker：6 项运行、隔离、超时与清理检查通过，使用单独 `colima` context 和 VM 可挂载缓存路径。首次直接挂载 macOS TMP 失败，保留为配置故障。
- Navidrome 镜像中的 `/app/tests/fixtures`：40 项、326507 字节、3 个链接，基线和检查副本均保真。
- 完整 `/app`：显式配置 200000 项、512 MiB、300 秒后，捕获 131003 项、433449713 字节和 83 个链接，全部保真。插件默认容量保持不变；完整捕获通过不代表检查运行器准入。
- 容器内的本次原生检查仍因没有 Docker CLI/管理路径而失败；`modelAdmitted=false`。插件默认资源和原生 DSH 沙箱均未改动。

## 复用探针

`topology-probe.ts` 调用实际插件快照和原生 subprocess 检查路径；`probe_topology.py` 仅创建、核对并移除自己带唯一标签的容器。不挂载凭据、评分文件或 Docker socket，不发送模型请求。管理员显式传入已有镜像 digest、冻结 Linux runtime、Linux Node 与已构建 probe；结果独占创建，不覆盖旧记录。参数可指定容量、截止和工作区，子树成功不能视为完整任务成功。

## 管理员检查通道

[通道证据](gateway-20260928.json)记录 28 项定向回归，其中网关 6 项；真实 Docker 检查覆盖租约、私有副本、取消确认、恢复和产物改写拒绝。Host/Client 严格检查、构建、打包入口检查通过。通过 DSH 的 `plugin add link:` 安装后，管理员 profile 实际加载新入口并执行检查，收到退出码 0、完整输出、原产物未改和容器清理确认；没有模型请求。

管理员入口的配置包括 `socketPath`、客户端 `storageRoot`、分离的 `privateStorageRoot`、绝对 `deadlineAt` 和固定 `container`，可显式调整命令时限、输出与快照容量。客户端仅配置 `checkGatewaySocket`；双方使用相同镜像和 context，响应必须匹配请求。socket 位于产物租约之外。管理员持有本地 Docker 管理能力，主任务只能发送受限检查请求；检查容器不挂管理 socket、主目录或原任务工作区。

首次回归中，小输出预算截断完整 Docker inspect，使三个自有容器未清理。已按标签和挂载核对身份后移除，仅查询清理所需字段。原生控制 HOME/TMP 位于检查容器不可写目录；后续探针写入会重新核对目录和文件。子代理提出目录替换问题，其复现轮次中断；该问题的修复由本轮真实负例验证，不记为最终子代理签字。首次 profile 手工夹具权限不匹配被拒绝，修正夹具后另存第二次结果。

macOS profile 与同进程 socket 回归不能证明 Linux 官方任务的分离容器已部署。Unix socket 不能跨 macOS 与 Linux VM 内核直接共享；公开题的管理 profile 和任务客户端必须处于同一 Linux VM，并隔离管理目录与 Docker socket。后续 Linux 分离容器校准见下一节；此前 macOS 成绩单保留，不被新成绩覆盖。

## Linux 官方产物与生命周期校准

`gateway-probe.ts` 是无模型 DSH profile，`probe_gateway.py` 通过受支持 CLI 分别运行管理员和任务容器。只有管理员挂 Docker socket；任务和检查容器均不持有它。两者使用同一 Linux VM 的 Unix socket，管理员重新捕获客户端快照到分离的私有存储后才运行检查。全工作区包含未提交、未跟踪文件；只排除 `.git`。

Helm 全量产物含测试用绝对链接，默认拒绝两次后，校准显式声明 `/dev/null` 与 `/non/existing/file`，没有删除对应测试目录。完整捕获 2691 项、3922972 字节，实际运行四项公开 Go 测试，退出码 0；后台 HTTP 服务检查通过，且取消在确认命令已经运行之后触发并收到清理确认。插件默认容量与 DSH 原生沙箱保持原值。

Kea 首次使用 macOS 共享存储时，专用 VZ VM 进入 error 状态，Docker/SSH 不响应；两个原租约容器退出码 255、`OOMKilled=false`，没有命令结果。开始记录、宿主错误和恢复记录保留，按原租约核对清理后封口为基础设施中断。具体诱因未确定。后续无模型校准使用独立 Linux volumes 存放大快照，volumes 带租约标签且保留为私有证据；这不是正式模型尝试的重跑。

Docker 管理调用现在有 30 秒界限，超时后回收本进程组；这本身不能证明 daemon 已清理容器。最终清理另行核对租约，日志失败仍继续 stop/rm，身份无法确认则记录未确认并拒绝通过。四项管理 helper 回归通过；子 Agent 只读核对两项清理修复，无模型或容器复演。评测脚本通过独占根目录、started/result 记录阻止同名隐式重跑。

Kea 后续完整捕获 25574 项、234315900 字节；先记录生产 React 环境下 45 失败、111 通过，再显式设置 `NODE_ENV=test` 与 `BABEL_ENV=test`，33 个公开 Jest 套件、156 项测试全通过，产物无改写、清理已确认。没有修改业务代码或测试。这些公开测试不同于官方独立评分的 151 个位置。

具体结果、失败位置和证据哈希见 [Linux 校准证据](linux-gateway-20260928.json)。这些是工程接入证据，不能视为正式题 reward、模型准入或 Supervisor 优于 Goal/Plan 的结果。

## 下一项接入

独立检查需要宿主拥有受限的检查执行能力，而官方 Agent 容器不能取得全局 Docker 管理权限。下一项适配必须同时验证实际产物捕获、运行器调用、原生进程生命周期、后台服务、任务截止与独立评分。题库或参考 adapter 更换本身不能证明这些条件成立。通过后再冻结 runtime/profile/image/order 并准入四组真实模型运行。
