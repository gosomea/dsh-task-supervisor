# 最新 Supervisor：单题开发验证

本轮按用户要求只执行 Kea `kea-atomic-signal-selectors` 一个 case，使用 DeepSWE v1.1 的正式题目及官方独立评分器。它是最新插件的单题开发验证，不属于此前冻结的 16 个配对位置，也不足以得出对 Goal 或 Plan 的优劣结论。

## 本轮固定的输入

- 插件：`2eb079789a03dbd8a4c8d94dba8098f187f52587`。
- 主 Agent 与审查者：CodeBuddy `deepseek-v4.1-flash`，输出上限 32000，推理设置跟随 provider 默认。
- 计划形成审查、输出截断恢复开启；正式计划通过覆盖审查后按 profile 预授权自动批准。
- 主任务最多 10800 秒，独立评分最多 1800 秒；Agent 容器限制为 2 CPU / 8192 MiB。
- 进展观察点为 24 次工具调用、5 分钟或连续 3 次错误；暂停后不追加外部救场。
- 仅提交 Agent 自己已 commit 的 `base..HEAD` 补丁。未提交或未跟踪的文件不由评测程序补交。

完整配置与产物校验摘要见 [protocol.json](protocol.json)。本轮 Supervisor 条件读取原生 Session 证据，没有启用独立产物检查运行器；完成后另用官方独立环境评分。

## 环境与范围

此前冻结评测的虚拟机无法连接，本轮使用可用的 `colima-dsh-eval-rosetta`，保留旧批次。该 VM 为 4 CPU / 8 GiB，操作系统也占用其内存，因此本轮不声称符合旧批次的完整资源准入证明。

准备时的 TMP 路径挂载失败及容器 lease 冲突均发生于题目投递前，未产生模型评测尝试；原证据保留。本轮实际题目只投递一次。

## 结果

本轮 **1/1 个位置已封口**。主 Session 在约 109 分 40 秒后由 Supervisor 自主裁决完成，六个 DAG 节点均通过阶段审查，未触发暂停或人工救场。随后只提取 Agent 已提交的补丁，在另一独立环境运行官方评分器。**官方 reward 为 0**；151 项测试中 149 项通过、2 项失败，评分过程没有基础设施故障。Supervisor 的完成裁决因此是一次误验收，不能把“6/6 节点通过”当成题目成功。

| --- | --- |
| 主任务 | `native-complete`；未超过 10800 秒截止；主 Session 与审查 Session 均走固定的 CodeBuddy `deepseek-v4.1-flash` 路由 |
| 授权与恢复 | profile 预授权记录 1 次，外部批准 0 次，外部救场 0 次；3 个主模型输出达到 32000 token 上限后都有后续回合，持久恢复预约 2 次 |

官方失败的两项均属于新功能测试：

1. `hybrid engine can be enabled and disabled`：测试在创建 logic 后开启 `atomicSelectors`，期望 `logic.selectorHealth` 是函数，实际为 `undefined`。提交代码在新 context 中注册该字段，但已有 logic 包装器没有获得它。
2. `stable identity across remounts`：同一 logic 卸载再挂载后，测试期望 `selectorHealth().selectors.userName.evaluations` 仍为 1，实际为 2。提交代码虽然按稳定 ID 保留记录，但重建的 selector 又执行一次并递增了计数。

这两处解释是依据官方测试断言和提交补丁的代码路径作出的定位，尚未在本轮修改或重新评分。它们说明阶段与完成审查没有充分验证 context 切换和重挂载这两条用户路径。本条件的审查者只读取原生 Session 证据，没有独立产物检查运行器；官方评分是在任务结束后才独立运行。无盲审标注的纠偏收益与误暂停率保持 `null`。本轮只有一个已公开题目、一个 Supervisor 条件，不能据此比较 Goal、Plan 与 Supervisor 的总体表现。

可复核的机器摘要见 [result.summary.json](result.summary.json)。包含原始 Session、模型输出及评分日志的私有缓存未提交。

## 运行中发现的审查问题

前两次正式计划审查把未显式提供 `dependsOn` 判为“没有依赖边、不能保证阶段顺序”。该意见与当前执行语义不符：`src/graph.ts` 的 `dependencies()` 将省略值解释为前一个阶段，工具 schema 也说明省略保留相邻顺序。因此该部分是审查误判，不应算作有效纠偏。审查者对早期阶段承担最终 commit 验收的意见则有实际依据。后续需让审查上下文呈现归一化后的依赖关系，并明确兼容语义。

本轮保留原插件版本完成评分，没有在运行中修补审查提示或改变计划准入规则。最终正式计划有明确依赖边并获得通过；初始两次误判增加了计划修订和审查等待，但本单例无法量化其因果耗时。
