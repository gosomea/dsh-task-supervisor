# Agent Note: 规划期间监督、截断续行与可选自动批准

Status: proposed

[English](2026-09-29-planning-supervision.md) | 简体中文

## Problem

Supervisor 必须帮助任务形成可执行计划。当前 `src/index.ts` 的 `observeStep` 只观察 `active`；空闲续行也只准入 `active`，规划期间尚未提交计划时没有对应的监督与续行。部分由插件启动的规划轮次结束后还会解除运行准入。`task_submit_plan` 提交后才触发覆盖审查，无法处理提交前的停滞。

[前七个评测位置的分析](../../../../eval/deepswe/results-20260929-7/analysis.zh.md)记录了正常调用模型、最终生成达到单次输出上限的情况。对应原生结束原因是 `max-tokens`，末次响应只有 reasoning 内容，没有最终正文或工具调用。Supervisor 的规划位置没有提交计划或启动审查。此证据支持补齐规划续行；尚不能证明增加续行就能完成题目，也不能把这一现象归为独立验收能力不足。

用户希望截断后由旁路提醒继续，并监督计划形成过程，同时提供自动批准执行的选项。提醒需要带进度和下一项产出；单独追加“继续”可能重复推理。模型长时间运行也可能一直产生有效勘察，经过多久、用了多少工具都不能独自证明跑偏。

## Proposal

在插件内扩展同一个控制器，负责规划观察、截断恢复和执行授权。复用 DSH 原生事件、Session、消息队列和维护任务接口；主 Agent 提出并实施计划，独立审查者提供证据与建议，控制器裁决状态并交付下一步。本文定义拟议行为，不提供已可安装的配置。冻结中的对照评测不修改运行时或插件；新行为通过隔离验收后另立对照版本。

### 用户设置与默认行为

| 设置 | 建议默认 | 行为 |
| --- | --- | --- |
| 生成截断后继续 | 开启 | 当前受督导任务获准继续规划或执行时，处理真实 `max-tokens`，交付有上下文的有限续行。 |
| 规划过程监督 | 开启 | 在安全边界按观察条件检查目标覆盖、勘察进展和待解决问题；不会每次工具调用都启动审查。 |
| 执行批准 | 手动批准 | 可选择“计划通过独立审查后自动执行”，在当前任务中记录用户预授权。 |

这三个设置分别控制恢复、观察和授权。全局关闭现有 `automaticContinuation` 时，不自动开启下一轮，包括截断恢复。用户可关闭规划观察而保留一次截断恢复；连续无进展的恢复仍有停止限制。执行自动批准不能解除暂停，也不能把任务直接判为完成。

### 一、截断后继续

订阅 `session/event` 记录原生 `turn/end`，在 Agent 真正空闲后重新核对日志和队列。`agent/status=idle` 仅是检查时机，不是恢复证据。确认当前最近轮次对应 `max-tokens`、步骤和工具义务已结清、没有待处理用户输入或其他队列项，才考虑恢复。原生 `max-tokens` 标记在同一轮内具有保留语义；还需检查最后实际请求与后续活动，不能用旧截断事件覆盖后来的成功提交。

恢复必须满足当前任务 ID、要求版本和状态修订一致，督导启用且本次运行仍获准继续，没有必要审查或用户决定待处理。`planning` 可继续勘察与提交计划；已获执行授权的 `active` 可继续当前节点。`awaiting-approval`、`reviewing`、手动暂停、关闭、完成、清除、宿主重启后的等待均不自动恢复。`aborted`、`error`、`interrupted` 和 `blocked` 分别保留原因，不作为生成截断处理。

控制器先保存恢复记录与待交付消息 ID，再经同一调度入口交付。记录绑定任务、要求版本、原生轮次及结束事件 seq，并保留状态修订、触发原因和次数。重复回调核对同一记录、原生消息及 inbox，不能再次开启同一次恢复。用户编辑、暂停或关闭使尚未交付的动作失效；若崩溃后不能确认是否交付，等待手动恢复并展示证据，不猜测执行结果。记录写入或 flush 失败时不发送消息。

第一项恢复由确定性控制器生成，不必先请求另一个模型回答“继续”。续行包包括任务语言与原始约束、已确认的勘察或节点进度、证据 seq/可读产物引用、尚未完成的具体产出、执行权限及下一步。只概括有记录支持的事实；不把被截断的推理当作工具已执行或文件已修改，也不重放未确认效果的调用。上下文有界，省略部分明确标注并提供现有 Session 读取入口。

示例续行内容如下；实际节点、seq 与发现必须来自当前日志：

> Supervisor · 继续规划：上一轮达到生成上限，尚未提交计划。已完成入口和配置读取，证据见本次续行所列事件；合并优先级仍未确认。请保留已有勘察，先核对这个问题，然后提交包含依赖和验收证据的计划。若现有证据已足够，直接提交，不重复读取。当前仅授权规划，尚未批准实施。使用本任务的中文响应。

暂定连续两次恢复未带来有效进展后暂停，等待手动恢复；次数可配置，需用真实任务校准。有效进展包括新的相关事实、解决一个未知项、可验证的草案改进、成功提交计划或可核实的节点产出。工具数增加、Token 增长和同一句摘要不能重置计数。启用规划观察时，第一次恢复后的再次截断触发规划进展检查，帮助确定更小的下一项产出；关闭观察时，仅用可直接核实的产出判断进展，不明确时保留无进展计数。必要审查失败不能按默认继续处理。恢复次数不替代任务截止或外部评测限制。

### 二、监督计划形成

新增独立的“规划进展”检查类型，区别于提交后的“计划覆盖”以及执行阶段的“进展”。任务可以尚无 DAG；此时不能要求当前节点、把临时想法当作批准的计划，或评价不存在的节点是否完成。保留 `planning` 主状态，通过规划摘要与审查作业记录表示勘察、草案形成和待澄清等子状态。

观察条件优先复用已有配置：累计 24 条工具结果、存在已完成工具活动且经过 5 分钟，或连续 3 次工具错误，在下一次 `agent/pre-step` 检查；真实截断可在空闲边界提前触发。初始值沿用当前观察默认值，规划是否适用需验证。正常 `completed` 轮次已结束、仍未提交计划且没有待答用户问题时，也在空闲边界检查下一步：有未审查的新活动则进行规划进展审查，证据支持继续时交付具体产出；不能把这个分支记为截断恢复。条件只请求检查。无新增活动时不反复审查同一截止点，不把必要研究强制缩短为固定几轮。

审查者读取当前用户要求、项目规则的实际读取证据、上次已审查区间之后的工具输入输出与公开回答，按需向前分页。检查目标关键要求是否保持、勘察是否缩小未知项、草案依赖是否合理、何时证据足以提交，以及是否有只有用户能决定的问题。每项发现附来源和证据截止点；没有报告不等于没有进展。审查结果可以仅记录、交付有事实支持的下一步，或暂停请求用户决定，不能添加用户没有要求的产品范围。

规划摘要区分“已确认事实／待核对假设／未知项／下一项产出”，绑定要求版本和证据截止点。主 Agent 可提供摘要或草案，但审查者必须核对原始证据；不能为监督强制多加一个每轮必调的工具。摘要保存在现有任务投影对应的 Session 记录中，随压缩保留事实引用与读取入口，不形成另一个任务要求或计划数据库。

在 `agent/pre-step` 边界完成审查后，将必要纠偏以插件来源消息交付；在空闲状态通过统一调度入口续行。纯模型长生成期间，首版仅观察可获得的状态，不能保证中途打断并让模型改变已进行的生成；截断或下一步骤才是交付边界。不得通过任意取消工具实现干预，也不新增逐工具封禁。规划仍使用原生权限，提示主 Agent 在批准前不实施交付物。

审查作业绑定任务、要求版本、证据截止点和状态修订。作业期间新用户输入或状态变更使控制结论过期；存下历史发现，但不应用旧结论。规划审查的内部超时、协议缺失、模型请求失败保留为内部故障，通过已有有限恢复规则处理；恢复耗尽展示审查故障，不能伪装为用户不同意或自动通过。规划过程的正常观察不能替代提交后的完整计划覆盖审查。

### 三、可选自动批准执行

提供任务设置“计划通过独立审查后自动执行”。用户在创建任务、讨论形成任务或等待批准时显式选择，控制器记录预授权来源、任务 ID、要求版本、授权范围及撤销记录。profile 可以配置偏好；启用自动批准的有效选择及继承来源必须在任务界面清晰呈现并记入授权记录，不能从模型的“用户应该同意”推断许可。

正式计划须通过结构、依赖和要求来源验证，再由独立审查者确认覆盖原目标。自动批准要求有效的覆盖审查 `pass`，即使普通手动流程允许关闭 `planCoverageReview`；实现时对冲突设置明确拒绝或强制此项必要审查。计划未提交、审查失败、`revise`、`needs-user` 或审查故障，均不批准。超时不能转换为 `pass`。

控制器验证授权未撤销、任务与要求版本相符、计划版本与本次审查输入相符、用户的新指令已处理且没有必要决定待处理，然后复用与手动批准相同的执行转换和只读轮次限制。保存批准来源为用户预授权策略，并关联授权事件 seq、计划版本与审查作业；不伪造用户消息，不让 `task_approve` 绕过它现有的直接用户批准校验。自动批准与用户点击竞争时只能保存一次执行转换、交付一项执行输入。

授权只覆盖当前任务和这版要求的首次执行批准。目标实质编辑、要求新增、任务切换或 fork 使原授权不再适用；不能把旧任务的策略传给下一任务。已获批任务的计划修订沿用独立的修订协议，不能只凭 `everApproved` 掩盖范围变化。暂停、关闭督导、重启和完成后返工仍遵循[任务生命周期](../../../../docs/task-lifecycle.zh.md)及[每次点击确认修复](../../../../docs/completed-task-repair.zh.md)。自动批准不会授予额外文件、网络、沙箱或外部发布权限。

### 展示、记录与开发顺序

主 Session 保留原生主 Agent 输出，旁路用独立短通知展示“继续规划”“规划进展审查”与“按你的设置自动批准”。任务小框显示规划当前产出或正式 DAG 进度；侧栏显示发现、证据、恢复次数和批准来源，并提供暂停、关闭及撤销自动批准。自动消息的实际正文可查看，用户能看见它为何继续及继续做什么。语言跟随任务语言，不随英文工具输出变化。

| 开发批次 | 交付与验收 | 原因 |
| --- | --- | --- |
| 1 | 原生截断分类、有限恢复、上下文与持久交付核对；隔离验收后提交并推送 | 先消除已经观测到的规划停住问题，保持执行批准边界。 |
| 2 | 规划进展审查、摘要与安全边界纠偏；隔离验收后提交并推送 | 检查下一轮有否帮助计划形成，限制重复研究与无依据暂停。 |
| 3 | 任务预授权、自动批准、UI 与竞争处理；隔离验收后提交并推送 | 在形成有效计划之后减少人工等待，保留可核查的授权来源。 |

批次 1 可先默认手动批准验证；批次 2–3 再做联合真实模型验证。新增持久字段、记录版本、旧日志重建和 Host/Client 读取器在同一批次更新并按 DSH 持久化规范确认。实现模块可在本插件内拆分规划观察、恢复决策和执行授权，统一由当前控制器注册事件与调度；不修改原生 Goal/Plan 驱动，也不为截断新增宿主循环补丁。

## Alternatives considered

**只把输出上限调高。** 当前数据证明请求达到配置的上限，但没有证明更高额度或模型参数可用。即使可用，也仍会有生成截断与提交前停滞；模型路由调整应另做实验，不能替代状态与恢复协议。

**每次空闲都发送“继续”。** 空闲也可能是等待批准、用户暂停或必要审查失败。缺少结束原因、上下文与重复交付核对，会启动未获批准的执行或重复已有工作。

**仅在提交计划后审查。** 现有机制不能发现长时间没有形成计划的问题，因此保留正式覆盖审查，并新增形成期间的观察。

**让审查 Agent 直接指挥主 Agent。** 这会引入第二个续行所有者。审查者提出建议，控制器核对版本、授权与队列后统一调度，保持现有职责。

**默认自动批准所有任务。** 用户需要保留选择，且当前项目约定首次计划由用户确认。推荐手动默认；自动批准是显式预授权的扩展，实施时必须同步修改授权约定及其测试。

## Acceptance criteria

- 真实模型出现只有 reasoning 的 `max-tokens` 后，在同一主 Session 自动继续规划，最终提交计划；没有预授权则等待批准，不提前写入交付物。记录每次实际请求与恢复消息。
- 重复结束或空闲通知只产生一次续行；用户输入、暂停、关闭、clear、版本变更、未结清工具、队列中已有工作及必要审查均阻止不适当续行。崩溃后不重复投递，重启保持手动恢复。
- 已截断轮次后来形成有效提交时，不凭旧结束原因再唤醒。正常完成、取消、请求错误、宿主中断和审查内部截断有各自路径；本批次主 Agent 恢复不能暗中自动重跑审查者。
- 规划持续有相关进展时继续；重复无新事实、遗漏原要求或重复工具错误时产生可追溯的建议。只看时间或计数的测试不能被当作有效纠偏证据。纯长生成只在支持的边界干预。
- 两次恢复无有效进展时停止自动续行并解释原因；有效事实可使计数重置。分页、省略、压缩和不同语言条件不丢失原约束或证据引用。
- 自动批准的正例具有用户预授权、有效正式计划及覆盖审查通过。负例覆盖过期授权、目标变更、审核修订、用户决定、内部故障、撤销与权限限制。手动与自动同时批准仅执行一次；记录真实来源，原 `task_approve` 不能伪造授权。
- UI 区分主 Agent 与督导、临时规划与正式 DAG、执行授权与最终验收。完成后缺陷修复仍展示影响范围并等待用户点击确认。
- 新版对照沿用相同题目、主模型与评分协议，单列版本、恢复次数、首次有效计划时间、批准等待、有效事实增量、提交与已提交补丁率、独立奖励、总耗时及所有 Session Token。现批原结果不改写；无盲审标注时，纠偏收益和误暂停保持未测量。

## Risks

更多续行与审查会增加 Token 和耗时，且模型可能再次用满单次输出额度。有限恢复只是容错；能否转化为计划与实现必须用独立奖励验证，不能以恢复次数或提交成功代替任务成功。

规划摘要可能遗漏事实或误报进展。原始 Session 仍是权威，审查保留证据截止点与分页读取，不能让摘要取代原始要求。暂定次数和观察频率不是已验证的最佳策略。

自动批准改变首次执行的授权契约。功能实现前需要将本项目 AGENTS 与任务生命周期中的手动默认、显式预授权例外及撤销规则同步落地；当前代码仍按已有手动批准行为运行。现有用户确认修复和重启等待的约定不在本提案变更范围内。

本提案补充现有[审查策略](../../../../docs/review-policy.zh.md)与[督导会话设计](../../../../docs/session-runtime.zh.md)。本项目此前没有 Agent Note 树；检查到相关设计为局部扩展关系，保留这些记录及其生命周期约定，不归档或覆写它们。
