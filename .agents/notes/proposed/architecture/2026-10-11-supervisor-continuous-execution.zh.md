# Agent Note: Supervisor 持续执行、审查预算与开发回归

Status: proposed

[English](2026-10-11-supervisor-continuous-execution.md) | 简体中文

## Problem

此前八次 Supervisor 执行均未完成整体验收。问题包括审查反复取得 600 秒预算、检查发现未及时保存、裁决确认与持久记录不一致、计划修订后续行受阻，以及实现产物没有形成完整交付。

目标是：DAG 获批后，由一个 Supervisor 控制器持续推进节点、独立审查、有限恢复及原要求内修复，直到整体验收与交付完成；必须停止时留下明确原因与操作入口。

## Proposal

### 1. 计划落盘与决策锁定

用户于 2026-10-11 授权实施。本 proposed Note 是全部验收门槛通过前的唯一决策所有者；英文 counterpart 与配对记录同时更新。现有评测导航和相关文档链接到它，不复制另一套计划。保留[旧规划监督 Note](../../implemented/feature/2026-09-29-planning-supervision.zh.md)，并交叉引用仍有效的职责。

锁定以下决策：

- 节点逐个验收；进展审查由异常触发；默认串行推进，保留已有显式 Worker 委派。
- 检查发现逐项持久化，由控制器汇总要求级结果。
- 分阶段预算、提前收束；预算按工作量确定，600 秒为默认值。
- 原始要求内允许自动修复及重规划；要求变化重新授权，完成后重开仍确认影响范围。
- 整体验收复用身份、范围和依赖关系仍有效的证据。
- 完成必须包含全部节点通过、整体验收通过及用户要求的交付动作。
- 主 Session 显示活动、预算及下一步，保留完整报告和独立折叠的原生过程。
- 先通过确定性与跨产物闭环，再运行原四题各两次，共八次 Supervisor 开发回归。

### 2. 持续执行与裁决交接

控制器执行统一链路：批准 DAG → 调度就绪节点 → 主 Agent／Worker 实施 → 提交审查 → 独立检查 → 封存发现 → 对照汇报 → 持久应用裁决 → 继续、修订或整体验收。

- 提交工具快速返回；审查由插件控制器运行。裁决先保存并确认落盘，工具才能确认提交；提交与有效应用分别记录。
- 应用前核对 Task、要求版本、计划版本、节点尝试、证据截止及产物身份。
- 调度动作先持久预留，交接后确认；结果未知时核对原动作，不能再次投递。
- 修复计划恢复判断：pass 进入批准或执行；revise 返回规划；needs-user 等待用户。规划续行不授予实施权限。
- 空闲时核对运行实例、未确认动作、用户待决事项和就绪节点；存在遗漏调度时幂等补齐。
- 用户暂停、关闭、新要求、Task 截止优先于旧回调；宿主重启等待人工恢复。

进展审查由连续工具错误、持久无进展或明确偏移、新缺陷触发。已有审查或节点提交覆盖同一问题时合并处理，避免叠加审查。规划监督保留已有触发机制。

### 3. 工作量预算与 600 秒治理

新增 reviewBudget 配置，支持工作量策略及上下限。首轮默认采用三个预算档：

| 档位 | 判定 | 总预算 |
| --- | --- | ---: |
| 轻量 | 最多 4 项去重检查、仅读取、预计读取不超过 256 KiB | 120 秒 |
| 常规 | 最多 8 项检查、预计读取不超过 1 MiB、命令预计累计不超过 120 秒 | 300 秒 |
| 复杂或未知 | 超过上述范围，或成本无法可靠确定 | 600 秒 |

判断依据是检查范围与方法，不是任务类别。缺少可信成本信息时使用 600 秒。默认自动上限为 600 秒；更高上限必须显式配置。作业准入时固定最大截止；初始检查方案明确后可以缩短预算，但必须保留至少 60 秒用于收束与提交。追加检查、内部重试、更换 Session 和协议补交不能延长原截止。

- 前 70% 获取证据、逐项保存发现；70% 停止扩展检查、整理覆盖与缺口；最迟 80% 进入对照和裁决；100% 停止新工作、取消运行实例并拒绝迟到裁决。
- 600 秒预算对应 420 秒收束、480 秒进入裁决。阶段切换由控制器在公开执行边界交付；当前请求越过边界时取消并等待结清，再进入收束轮。
- 区分请求超时、命令超时、审查截止和 Task 截止。请求或命令故障可在剩余预算内恢复；审查截止不能重新获得一份预算。
- 命令超时取配置上限与剩余检查时间的较小值。截止后的资源清理单独显示、计时；清理无法确认完成时记录资源故障，禁止启动替代实例。

### 4. 增量发现、证据复用与恢复

新增逐项检查结果提交工具 task_review_check_result，关联检查 ID、结果、实际证据、覆盖范围与局限。保留旧批量工具兼容。

- 单项成功后立即持久保存；修改保留历史。控制器从检查方案与逐项发现生成要求级汇总，减少重复填写。
- 尚未完成的项标为未验证；必要要求未满足或未验证不能通过。实际成功读取的内容取得引用资格；摘要、失败调用和模型自述不算证据。
- 独立发现封存前，不能读取主汇报、实施日志或历史裁决。恢复使用已保存发现和真实读取资格；无法可靠继承的证据补读。
- 验证缓存绑定产物身份、方法、范围和依赖；缓存命中不自动扩大证据覆盖。

恢复默认保留一次读取纠正、一次裁决补交及一次内部故障恢复机会，分别记账。内部恢复优先原 Session；无法可靠继续时允许一次替换，替换计入同一恢复限额和作业预算。

审查记录升级为版本 9，保存预算、阶段、增量发现、Session 继承链、裁决确认与故障历史。继续读取版本 1–8；旧记录不补造证据、预算或授权。

### 5. 修复、交付与状态

原要求内的修复及重规划必须记录原因、影响节点和许可来源。新计划通过覆盖审查后继承仍有效的原要求授权，不伪造用户批准。

新增持久修订计数：同一 Task 自动重规划最多 3 次，同一节点自动返工最多 3 次；连续两轮没有新增相关产物或验证结果时停止自动循环。重试、重规划、重启和人工恢复不清零计数。

整体验收绑定当前整体快照，重查变化、接口关系和遗漏要求。复用此前证据必须重新核对身份及适用性，不能直接累加节点通过结论。完成判定同时要求：

1. 当前全部 DAG 节点有效通过。
2. 当前整体产物验收通过。
3. 要求中的 commit、推送、导出或文件交付实际完成。

主 Session、DAG 和侧栏共享活动解释，显示当前节点、执行者、具体活动、最近活动、剩余预算、恢复次数及下一步。提交、应用、失效、故障、等待用户和资源清理分别展示。主 Agent 回答保持原生输出。

### 6. 严格实施顺序

| 步骤 | 交付 | 放行门槛 |
| --- | --- | --- |
| 0 | 完整工作树、Notes、基线和验证协议 | 使用 2edbbc3 建立完整工作树；src／内核基线核对为 44b2a42，保留其他未提交改动 |
| 1 | 持久裁决、幂等应用、计划修订续行、遗漏调度修复 | 取消竞争、重复回调及断开响应回归通过 |
| 2 | 工作量预算、阶段收束、固定截止及清理 | 可控时钟证明恢复不续期，迟到结果不应用 |
| 3 | 增量发现、汇总、读取资格继承、证据复用 | 正反例与两阶段隔离回归通过 |
| 4 | 自动修订、交付核对及统一 UI | 多节点完整闭环和浏览器验收通过 |
| 5 | 冻结包及八次 Supervisor 开发回归 | 干净安装、准入及独立评分控制通过 |
| 6 | 机器结果、中英文说明及中文报告 | 全部分母、缺失数据和失败原因可追溯 |

每步必须先更新证据和中英文现状，再单独 commit、push、核对远端。证据包含提交身份、检查命令、退出码、结果位置和剩余限制。未达到门槛不得进入下一步。只有经过验证的行为可以标为已实现；全部完成后才将 Note 移入 implemented/architecture/，改写为实际决策与后果。

## Alternatives considered

**固定每次 600 秒并延长重试。** 用户选择按工作量配置，重试共享总截止，避免同一作业重复领取预算。

**最终一次提交全部检查结果。** 用户选择逐项保存，减少末尾校验失败导致整场发现无法落盘。

**整体验收全部重跑或只累计节点通过。** 用户选择有效证据复用，同时重新检查变化、接口及遗漏。

**每次修订都要求确认。** 用户选择原要求内自动修复与重规划；要求变化和完成后重开仍需要授权。

**默认自动并行调度。** 本轮默认串行完成闭环，保留已有显式委派，减少并发写入与快照失效。

**只运行少量公开回归或改用未见题。** 用户选择原四题各两次，优先核对已出现的失败路径。

## Acceptance criteria

- 确定性测试覆盖持久确认、重复应用、预算不重置、阶段切换、暂停、重启、产物变化、证据继承及清理。
- 正确的多节点夹具完成全部节点、整体验收和交付；错误产物不得误通过，无关偏好不得阻断正确产物。
- 跨产物真实模型覆盖静态文档、数据计算、行为遗漏、误导汇报和能力缺失；故障注入单独标记。
- Host／Client 严格类型检查、内核回归、构建、打包及普通 DSH 干净安装通过。
- 浏览器覆盖真实活动、完整报告、窄屏、长日志、多 Task、刷新及历史订阅释放。
- 原四题各两次仅运行 Supervisor，使用新批次、干净基线、原始题目、冻结配置、一次初始批准及官方截止；不追加救场。
- 官方评分只提取 Agent 已 commit 的补丁；八次均有不可覆盖的终态或未投递原因。
- 报告 reward、严格成功、控制器终态、审查总墙钟及各阶段、超过 600 秒和超过配置预算的原因、覆盖、故障、恢复、重复工作、用户动作与可取得的全部 Session token。
- 确定的实现或评分缺陷暂停新投递，修复后另建版本与批次；普通任务失败继续后续位置，结果不得覆盖或混算。
- 全部代码、协议与脱敏证据已提交推送，未执行项目逐项说明。未验证完成不得宣称计划验收通过。

## Risks

预算收束可能增加未验证结果，必须同时检查验证覆盖和正确性。外部请求或资源取消可能延迟，必须保存真实清理耗时，不能把界面停止等同资源释放。

原八题位置已曝光，重跑仅作为开发回归；成绩不能证明未见题表现或优于 Goal／Plan。没有人工标注的误验收、误暂停和纠偏收益保持 null。

改动限于 Supervisor 插件及现有评测适配，复用 DSH 公开接口、快照和检查运行器。日常 3080 的在途任务保持运行；独立浏览器执行器和新的自动并行调度不纳入本轮。
