# 检查命令的独立副本

2026-10-09 的长程开发用例发现：审查者在隔离目录运行 CLI，生成 `report.json` 后，这个新增文件使同一快照的下一次检查及裁决被拒绝。该运行按检查基础设施故障停止，保留原 Session、产物和日志；reward 为 `null`，未重新投递原位置。正式 24 次对照尚未投递。[English](check-invocation-isolation.md)。

## 修复

每次命令从已核对的快照种子和审查探针建立新的可写副本。容器只挂载此次副本；快照种子、控制记录、源工作区、凭据和 Docker socket 不在挂载中。

- 修改、删除或替换已捕获的交付文件仍记入 `changed`，不能用于验收。
- 新增文件记入 `generated`，与 `isolation: fresh-copy` 一同保存。路径元数据本身不授予已读证据资格；审查者仍须读取实际 stdout／stderr，并判断断言覆盖范围。
- 命令生成的报告、缓存和探针目录改动不进入下一次调用。需要运行后核对输出时，在同一次探针内完成生产与断言。
- 原有记录保持原语义，不把历史 `changed` 改为可引用。源码快照新鲜度和两阶段隔离不变。
- 容器移除得到确认后才清理此次副本。确认丢失时保留副本及持久容器身份；恢复仅清理绑定到本快照的资源。

## 已执行验证

真实 Docker／原生 subprocess 的 22 项检查通过，覆盖生成报告后再次检查、捕获文件修改、探针目录污染、越界与网络拒绝、超时、取消、容器清理及重启恢复。另有快照与裁决准入回归，验证新增报告可保留运行证据，修改交付物仍不可引用。Host／Client 严格类型检查通过。
