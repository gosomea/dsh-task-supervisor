## 截断恢复

原生 Agent loop 回归覆盖生成截断后的规划续行、提交后等待手动批准、重复无新事实时暂停以及关闭自动续行。检查真实 `turn/end` 和原生用户消息 ID，而非只检查内部函数返回。恢复判定与完整 Supervisor 回归共 108 项通过，另有 1 项已有 Docker 条件用例未运行；宿主与客户端严格类型检查及构建通过。交付回归还覆盖第二次 flush 失败及交付期间用户暂停：原生维护任务释放前撤回精确输入 ID；禁用自动续行后仍可手动恢复规划。

状态记录版本从 11 新增为 12，投影状态版本从 12 新增为 13。新增可选 `recovery`，保留原回合、结束 seq、无进展次数、证据 seq、工具产出指纹、消息 ID 和续行正文；`pauseReason` 增加 `recovery-stalled`。版本 1–11 的旧记录仍按原字段读取，不补造恢复事实；旧读取器没有版本 12 准入时拒绝驱动，不能忽略这项控制状态。

待交付输入先与任务快照持久保存，再经原生维护任务交付并 flush。交付前重新核对状态修订和 inbox；失败解除运行准入。重启移除旧插件输入且等待手动恢复，不从旧结束事件自动重投。所有检查使用隔离 Session 存储，不改日常 profile 或冻结评测。

隔离真实模型案例使用日常第一 CodeBuddy 路由（`deepseek-codebuddy/deepseek-v4.1-flash`），以明确标注的 256 token 测试上限制制造截断。Session `session-ba240d3b-b5fe-4da6-9a72-2e6441a3b387` 在 seq 19/28/37 记录原生 `max-tokens`；两条不同续行输入在 seq 20/29 持久保存，各在 seq 25/34 仅消费一次。没有新工具事实时，seq 38 以 `recovery-stalled`、计数 2 暂停；没有人工救场、批准或工作区写入。此案例证明真实截断与有界恢复，不证明成功提交计划；原生脚本模型回归覆盖提交和等待手动批准。私有证据保留在已登记 TMP 环境 `supervisor-planning-recovery-20260929`；该候选早于最后的 flush 竞态与手动恢复修复，后者已独立复现并通过确定性的原生 loop 回归。
