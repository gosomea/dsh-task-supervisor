# V2 来源与证据读取验收

## 交付范围

第二批的第一个提交增加标准来源与日志分页。新提交的每项标准必须提供 `provenance`：用户要求（当前 objective 或直接用户消息）、项目约束（成功工具结果中的适用项目规则）、实现选择（解释必要性）。来源类型和 seq 在宿主检查；所引内容是否真实支持该标准、项目规则是否适用，仍由独立计划审查判断。既有夹具或可选增强不能自动成为任务要求。

记录版本为 4，兼容读取版本 1–3。旧计划缺少来源时不会被伪造为“用户要求”；详情显示来源未标注，审查必须从原始记录重建依据。主会话与侧栏显示同一份标准来源。

`read_task_evidence` 返回摘要、`totalChars`、`truncated` 和 `nextOffset`；`read_task_text` 读取已见事件的正文，`read_task_call` 分页读取调用参数；`read_task_context` 读取固定任务的完整目标、标准、阶段、报告与历史失败。字符分页最多 6,000 个 UTF-16 单元，先脱敏再分页，沿返回的 offset 继续。审查仍限定在启动时的 Session cutoff 内；模型不能靠猜测 seq 越界读取。

这些工具恢复的是 Session 已保存的文本。若原工具本身只保存部分输出，不能恢复未保存的部分。非文本块只报告类型，本提交尚未提供图片像素读取；提示要求视觉证据不足时明确无法验证，不声称已完成视觉审查。

## 自动验证

37 项测试通过，严格类型检查和独立副本构建通过。新增真实 DSH 服务配合脚本模型的测试覆盖：摘要后读取长工具结果末尾的失败、读取 6,500 字符之后的硬约束、拒绝未先读取页面的正文访问、拒绝截止点外访问、区分直接用户来源与工具来源。分页测试确认跨页脱敏不泄漏凭据且能拼回完整已保存文本；旧记录继续可读，新计划不能省略来源。
