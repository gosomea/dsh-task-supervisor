# PTC 任务完成后的工具入口

## 问题

2026-10-07 的日常 Session `session-d7c2d2d9-b4d4-48cd-834e-215c60c24387` 在完成任务后产生七次工具错误：四次来自完成情况问询，三次来自明确的新任务请求。PTC 向模型只暴露 `run_code`；完成门禁拒绝该任意程序入口，因此内部的 `read`、`task_status` 和 `task_create` 均未执行。新任务调用还缺少 `user_message_seq`，当时被外层错误掩盖。

## 行为

完成的 PTC 或混合呈现 Agent 临时使用公开 `tools.presentAs('native')` 提供直接工具 schemas。Session 的 preset ID、权限设置和沙箱不变，不注册新的模式。开始下一项任务规划、清除任务或确认修复后释放覆盖，恢复原 preset 的工具呈现。已完成状态隐藏不允许的继承工具，避免模型看到 `bash`、写入或实施控制入口后再被拒绝。公开过滤器不限制 Agent 自己注册的本地工具；这类自定义组合仍由执行门禁保护，不能宣称其所有不可用 schemas 均已隐藏。标准模式没有这项覆盖。批准后要求只读轮次时，同样提供直接读取入口；成功读取且该轮完成后恢复 PTC。未完成或中断的轮次不解除写入限制。

- 普通问询可直接读取产物及 Task 状态，不新建任务或修改旧任务。
- 明确的新任务请求先调用 `task_status`，取得最新真实用户消息序号，再调用 `task_create`。创建后继续规划和独立计划审查，等待初始批准。
- 原目标的缺陷继续通过修复提案展示影响范围，等待用户点击确认。
- 文件写入和任意执行器仍由完成门禁拒绝。没有因为外层程序声称“只读”而允许执行；文件读取工具可用，但不意味着任意 shell/git 命令均可用。

覆盖在 Agent 生命周期与任务持久状态变化时同步，在第一次模型请求组装前生效；重启从现有任务投影重建。清理仅作用于对应 Agent，不改写历史日志或其他 Agent 的呈现。

## 验证

控制器所属测试文件：113 项通过，1 项原有 Docker 测试跳过。新增回归覆盖第一次请求的直接 schemas、只读查询、真实用户序号绑定、下一任务恢复 PTC、重启、清除任务、批准后只读轮次和其他 Agent 不受影响。现有完成后写保护和修复确认回归继续通过。Host/Client 严格类型检查、构建及打包入口检查通过。

真实模型验证结果记录在[机器证据](completed-ptc-controls-checks.json)。这是一项工具准入回归，不代表长程效果评测，也不增加审查者的独立执行能力。

## 保留的独立故障

首个真实模型用例在修复只读入口后提交节点审查，外层 `run_code` 使用默认 120 秒预算，审查尚未结束就被程序结束信号取消。持久作业记录 `cancelled`、`retryable: false`；`/task retry-review` 拒绝重试，普通恢复也要求先解决审查故障。这不是完成后的入口拦截，本轮未修改审查作业生命周期或原生 PTC 预算。

另一次完成后问询成功读取了状态和文件，但模型对仍可见的 `bash` 发起额外哈希检查，得到一次拒绝。该记录保留；随后加入继承工具过滤，并在重启后再次验证问询。

后续用例在审查调用上显式使用原生支持的 `timeoutMs: 600000`，未改 Host、profile、模型路由、输入或验收标准。因此成功结果只能证明该预算下的目标流程；不能将默认预算下的中断记录算作通过。后续需要让持久审查与外层程序预算协调，并区分用户取消和外层超时，提供正确恢复入口。
