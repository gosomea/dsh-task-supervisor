# 原生审查过程与恢复

## 主对话中的审查

每个持久审查作业在实际介入位置生成一个独立节点，包含 Supervisor 身份、检查类型、节点名称和尝试次数。覆盖规划、计划、进展、节点与整体验收，不依赖主 Agent 已结束轮次的尾部。

展开时绑定审查 Session 并复用原生聊天视图；实时回复、工具组、错误、耗时和历史都由 DSH 展示。没有第二个输入框，也不改写主 Agent 回答。模型返回的思考内容沿用原生设置。

插件从公开 shell 插槽持有渲染入口，用 React portal 将原生视图放入主对话锚点，避免递归调用同一对话工厂。读取使用持久父子地址；新审查记录原生子级 descriptor，但不授予通用子 Agent 续行权限。没有 descriptor 的旧审查仍可通过兼容读取接口查看；不会因查看历史而修改日志或投递模型。

正在运行的过程默认展开，结束后收起。用户主动收起后，同一活动期间的流式更新及组件重建保留这个选择；进入下一次活动才恢复默认。这份有上限的界面偏好在插件卸载时清理，不写入任务历史。历史展开才读取，收起后释放 Session 引用。排队期间等待审查 Session 建立，不用读取历史启动模型。刷新后从持久记录恢复同一个作业；重试不会创建第二张作业卡片。

收起过程后，标题仍显示审查类型、节点名称和状态，使用 DSH 原生展开控件及主题颜色区分进行中、恢复、异常、失效与裁决。失败作业显示中文或英文原因；当前任务允许重试时，摘要直接提供“重试审查”。历史故障没有当前任务的操作按钮。展开后仍可查看原始错误。

## 实施与验证状态

第一步接入原生对话节点。第二步区分排队、生成回复、读取证据、运行检查和裁决应用，显示当前工具、最近记录时间与截止时间。工具失败单独计数，不算成功读取；同时运行的工具未全部结束时继续显示剩余动作。

主 Agent 本轮是否结束从真实轮次事件判断。DAG 小框在审查中不再把上一个节点的通过结论当作当前进展。侧栏入口定位主对话中的同一审查作业，旧 JSON 读取接口只保留兼容，不作为主要展示。

未在审查时，DAG 摘要将此前结论标为“上次审查”，同时注明所属节点或检查类型。原生审查摘要保留实测耗时、故障重试和裁决补交次数；这些计数不表示任务已通过。

## 控制器恢复与证据继承

正式提交与手动重试都先持久记录，再快速返回。公开生命周期接口在主轮次或命令收敛后运行审查。内部超时、可识别连接问题、请求超时、限流和临时服务错误默认重试一次；认证、配置和未知故障不自动循环。每次尝试在旧审查完全停止后启动，使用原 Session、模型、要求版本、节点尝试、证据截止点和产物快照。协议补交另计次数，不延长当前尝试截止。

原生轮次完成但缺少有效裁决时，可在同一作业有限补交。已被后续成功调用纠正的读取错误不阻止补交，旧错误仍保留在审查 Session 中；轮次最后仍是读取失败时，保存实际工具名称、结果序号和脱敏错误，等待恢复。补交不放宽引用资格：索引摘要或失败调用不能支持通过结论。

原许可、恢复策略、已用次数、故障历史写入第 7 版审查记录。原执行批准及版本仍有效时可自动续行；用户暂停、关闭、宿主重启、needs-user 或缺少许可的旧记录仍等待手动恢复。`resumeAfterReviewRecovery: false` 保留审查结果，等待手动续行。恢复不生成批准，首次计划通过仍按原策略批准。

恢复从原生审查 Session 中配对的成功工具结果重建读取资格。保留实际事件序号、文件哈希、读取范围与截断标记；索引只提供定位资格，失败调用和模型自述不提供引用资格。独立模式保留原检查方案、快照和阶段边界；不能可靠恢复的旧读取须补读。产物变化拒绝旧裁决。关闭、暂停与卸载打断恢复等待，定时器清理等待原工作停止。

## 配置

| 配置 | 默认 | 范围与含义 |
| --- | --- | --- |
| reviewFaultRetryAttempts | 1 | 0–3，同一作业的自动故障重试上限 |
| reviewFaultRetryDelayMs | 3000 | 0–60000，重试等待毫秒 |
| resumeAfterReviewRecovery | true | 只沿用原有效执行许可 |

规划与进展审查频率保持原值。本轮不新增浏览器执行器、不改变 PTC 超时或原生沙箱。0.1.3 发布验收通过 405 项内核测试、跳过 13 项，以及 Host／Client 严格类型检查；官方隔离 Host 跑通同一 Session 两个 Task，浏览器确认原生流式过程、工具失败及刷新后六个作业无重复。独立模式实际运行快照检查，并验证一次注入的 503 与一次真实审查超时均在同作业恢复后继续。干净安装及公开包核对记录在[0.1.3 发布验收](releases/0.1.3.zh.md)。

后续的读取纠错与折叠摘要回归记录在[10 月 9 日诊断与验收](postmortem/2026-10-09-review-repair.zh.md)。该轮验证日志审查和原生展示，不新增独立执行器，也未发布替换包。
