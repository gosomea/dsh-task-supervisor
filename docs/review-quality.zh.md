# 通用独立审查增强

## 摘要

审查围绕原始要求、实际证据和适当的方法展开。步骤 0–3 已实现并分别提交，源码门禁与跨产物真实模型夹具已验收；完整静态任务已通过控制器完成；Kea 官方回归已封口，reward 为 0，冻结版本在正式计划审查超时，后续协议修复另行验收。[验收记录](../eval/independent-verification/generic-quality-20260930/README.zh.md)保留成功、内部超时与适配故障。

## 完成口径

主 Agent 的声明、主 Session 的执行记录和审查者实际获取的证据分别保存。独立 Session 不等于独立验证；日志审查只能声称检查过所引用的日志。

原始用户要求是验收依据，计划标准用于组织工作。审查者先制定检查，再独立获取证据，最后对照汇报；推导假设与明确要求必须区分。

## 实施顺序

0. 统一审查策略、实现状态和中英文文档。本页不宣称尚未实现的能力。

1. 新增 `reviewVerification: log | independent`，明确有效模式和能力范围。旧配置保持行为；读取任务不依赖命令运行器，必要能力缺失明确报错。计划审查使用归一化依赖。

2. 新增持久 `task_review_check_plan`，先记录要求来源、方法、预期结果与覆盖，再读取交付物。可追加检查并保留修订；裁决绑定本作业实际证据。使用新审查记录版本兼容旧作业。

3. 新增截止点绑定、可筛选分页的 `read_task_evidence_index`。索引不代替原始证据读取。侧栏展示制定检查、独立检查、对照汇报和裁决；统计成本，不同时修改审查频率。

每步完成针对性验收后单独 commit、push 并核对远端。改动限于插件和既有评测适配，不修改主循环或原生沙箱。

## 能力边界

本轮复用产物快照读取和隔离命令运行。行为要求需要实际执行或复现；静态要求可通过读取验证。独立浏览器观察尚不可用，不能伪造通过或静默降级。

需求明确时先检查必要能力；宽泛目标允许先讨论规划，确定验证需求后在实施批准前检查。最终验收取当前快照，节点此前通过不能推出整体通过。

## 验证与评测

夹具覆盖静态文档、结构化产物、数据计算、测试全绿但行为遗漏、正确交付、误导汇报、能力缺失、补交重启与产物变化。错误交付不得完成，正确交付不得被无依据偏好阻塞。

执行内核测试、双端类型检查、构建和打包检查，再在登记隔离环境做真实模型正反例。冻结版本后仅以增强 Supervisor 从干净环境重跑 Kea 一题，遵循一次授权、固定截止、不救场和官方独立评分。

报告 reward、F2P/P2P、独立证据覆盖、误验收、内部故障、耗时与全部 token。没有盲审标注的指标保持 null。Kea 已用于分析，仅是开发回归，不计未见题，不据此宣称优于 Goal 或 Plan。
