# C：持久督导对话与草案

督导对话现在绑定主 Session，跨多个任务沿用同一原生对话。无任务时可讨论宽泛目标、整理标题、完整要求及未决问题；草案记录在主 Session，可重建。旧版绑定单任务的对话仍可读取，不能控制后续任务。状态记录写版本 9，保留版本 1–8 的读取。

保存草案不授予执行权限；未决问题、过期版本、正在执行的另一任务都阻止创建。模型创建需要展示草案后的明确用户确认，UI 创建确认在主日志中持久化。每个动作保存来源 Session 与用户事件；创建身份用于核对中断后的结果，并发和重复请求不会创建第二个任务。重启不会自动推进，旧用户授权不能重放。首次计划批准仍然保留。

新增真实 DSH 日志测试覆盖无任务讨论、明确确认、并发去重、当前任务隔离、草案修订、重启旧授权拒绝，以及创建后中断的核对恢复。压缩沿用原生 Session 机制，授权来自直接用户事件，不从摘要重建。不存在的宿主 clear API 没有假定为已验证；草案跨新 Session 自动迁移不在本阶段提供。

门禁采用受支持的 Node 24.19.0 与隔离 seam 源码。A、B 不可变归档另在 Node 24 上补跑通过；原始导出保留。真实模型及客户端交互待 F；源码验收不等于部署验证。
