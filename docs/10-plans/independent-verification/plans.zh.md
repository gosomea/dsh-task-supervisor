# 独立验收与完成后返工增强方案

**状态：步骤 1 已通过隔离验收；步骤 2 的快照与原生运行器实验已实现，正在改为插件内运行时；步骤 3 已有未提交原型，尚未完成真实模型验收；步骤 4–5 待开发。更新：2026-09-28。** 本文统筹独立产物验收与完成后回原 DAG 修复。当前能力以[实现状态](../../implementation.zh.md)、[完成后修复协议](../../completed-task-repair.zh.md)和[验收记录](../../completed-task-repair-validation.zh.md)为准。步骤 1 部署在登记的 61454 实例；59909 用户实例与冻结的 60 次公开题对照未替换。

## 摘要

增强审查者实际读取产物、分析实现、独立运行检查和体验关键用户路径的能力。节点与最终验收采用独立验证；进展观察保持轻量。审查者先形成自己的发现，再对照主 Agent 汇报。主 Agent 负责实施，审查者负责验收，确定性控制器负责状态、授权与续行。

完成后发现同一目标中的缺陷，修复回到原任务、原 DAG，保留此前完成与验收记录。**用户已确认：每次重开先展示影响范围，点击确认后才重开。** 对话中说“修复”生成提案，不代替这个按钮确认；目标扩展形成新任务草案。

## 现状与问题

现有审查能读取主 Session 的文本、工具输入输出和图片证据，已有审查恢复、节点返工与显式开始机制；读取日志和主 Agent 测试报告不能替代对当前产物的独立检查。完成后重开已按步骤 1 实现；步骤 2 基础代码已通过原生服务测试，正式审查接入与两阶段工具待步骤 3；浏览器待步骤 4。详见[独立验收验证](../../independent-verification-validation.zh.md)。

游戏案例中，任务已显示完成，主 Agent 诊断出生位置与水中行动问题后调用返工工具，得到 `task is not executing`。截图提供待验证的缺陷线索；本方案不把截图中的每项诊断直接认定为已独立复现。

直接原因在 `src/index.ts`：`task_rework_node` 描述可重开节点，执行却只允许 `active` 且已获续行准入的任务。`task_status` 未提供可用动作与拒绝原因，`src/task-context.ts` 的常规节点提示也没有完整的终态修复分支。应修正工具契约与上下文，并新增明确的重开流程；仅放宽这个 guard 会绕过确认、历史与多任务准入。

## 完成后的问题与重开

### 适用边界与确认

| 情况 | 处理 | 状态影响 |
| --- | --- | --- |
| “为什么在水下”、普通问询或新缺陷线索 | 可以读取代码、诊断并记录发现；不自动修改交付物 | 保持完成，显示有待处理发现。 |
| 明确请求修复原目标内缺陷 | 展示重开提案，点击确认后回原 DAG | 同一任务进入新的验收轮次。 |
| 加入新玩法、改变平台或扩大目标 | 在督导对话形成新草案，按新任务流程创建和批准 | 原任务的历史完成保留。 |

完成表示特定任务版本与产物版本曾通过验收，不代表以后不会发现缺陷。发现、重开提案、实际执行、再次验收分别记录。Agent 自己发现疑点可以提出修复，但不能自行点击确认或调用工具伪造用户收据；用户未确认时不自动开启下一轮。

提案显示任务名称与身份、此前完成时间、缺陷证据和复现状态、拟修复范围、受影响节点及下游、保留的通过项、需要重新验收的项目。提供“确认重开修复”和“暂不修复”；后者保留发现并维持完成。按钮布局与 DSH 原生决策控件一致，主 Session 只显示简略摘要与入口。

确认绑定具体提案版本、任务修订和产物身份。提案后目标、计划、相关文件或影响范围变化时，旧按钮失效，展示更新后的提案重新确认。确认同一提案只应用一次；重开后的普通执行续行沿用该授权，不能每轮再弹确认。若需扩大目标或新的重开，须重新走对应流程。

### 回原 DAG 的状态转换

拟议流程为 `complete → repair-proposed → 用户确认 → active（新验收轮次）→ 必要节点独立复验 → 整体独立验收 → complete`。`repair-proposed` 是待决提案，不必新增任务 phase；提案期间原任务仍完成。步骤 1 保留 `complete` phase 并使用独立提案与验收轮次字段，详见完成后修复协议。

保留稳定 `taskId` 与原目标；同目标修复不冒充新要求版本。新增单调递增的验收轮次标识，任务修订同步递增；计划未改时保留计划版本。此前完成记录绑定旧产物快照、审查和时间，作为历史里程碑；重开通过追加事件使旧结论不再代表当前产物，不修改或删除旧日志。

根据缺陷证据和实际文件职责选择一个或多个返工根节点，计算受影响下游的并集。这些节点增加尝试次数并等待重新执行、验收；其他通过项只有在相关产物未变化时才继续有效。未知文件归属或共享模块变化应明确扩大复验范围并解释原因，不能仅凭阶段标题认定互不影响。

截图中主 Agent 选择 n3 不一定覆盖完整责任：出生入口可能在集成节点，水中物理也可能属于世界核心节点。先核对实际模块、依赖与验收项，再确定根节点；必要的实现缺陷修复不得偷偷增加新玩法。原标准遗漏的验证路径可以在同一标准下补充；改变需求须走新草案或明确计划修订。

全部必要节点复验通过后，重新做当前产物的整体验收，尤其检查缺陷复现路径和可能回归的用户路径。旧完成、修复发现与本次完成可以连续追溯；未修复时不显示“再次验收通过”。

### 任务工具、授权与历史

步骤 1 提供 `task_propose_repair`、`supervisor_propose_repair` 和认证面板重开动作，不注册模型可调用的 `task_reopen`。提案工具记录范围与依据，没有执行权限；控制器核对任务身份、预期修订、提案版本、产物身份、原生点击确认收据和幂等键。模型不能提供任意用户消息编号替代按钮收据。UI 与工具共用状态转换，但模型工具不能成为确认的旁路。

`task_rework_node` 继续用于执行中的节点返工，描述明确前置条件。`task_status` 补充当前任务、所选历史目标、可用动作与阻塞原因；完成态上下文提示先提案再确认，不再直接指导执行返工。优先按宿主能力过滤不可用执行工具，同时保留确定性检查；若只能静态注册，则使用准确描述、状态提示与结构化拒绝。

拒绝返回稳定错误类型与下一项合法动作，例如任务已完成、提案过期、未确认、督导关闭或执行名额冲突，并附正确任务身份。不得用泛化错误让模型猜测反复重试。确认提交后先持久化，才允许准入执行；响应丢失时查已有收据，不能重复增加轮次或节点尝试。

| 边界 | 拟议处理 |
| --- | --- |
| 同一 Session 已有另一活跃任务 | 提案绑定历史任务，确认前提示名额冲突；不覆盖、切换或自动暂停当前任务。首版等待名额释放后再确认，不借本功能实现隐形队列。 |
| 督导关闭或用户暂停 | 展示不能续行的原因；重开请求不暗中启用督导或撤销暂停。 |
| 重启、响应丢失或迟到回调 | 恢复提案与已提交的轮次，执行仍等手动恢复；旧轮次审查与续行不得应用到新轮次。 |
| 已 clear 或取消的任务 | 不通过完成后修复入口复活；可明确复用要求形成新任务。 |
| 原任务产物已经被其他工作修改 | 对照历史产物身份重新确定影响，标注证据缺口；确认不能证明旧通过仍适用。 |

历史投影按稳定任务身份组织多次验收里程碑，不能将同一任务第二次完成插成两个无关联任务，也不能在切换历史任务时覆盖新任务。审计 `src/state.ts` 的任务历史收集、返工窗口与版本恢复；投影可重建，完整历史留在原生日志。主 Session 展示“修复中／第 2 轮验收”、原因与 DAG 进度；侧栏展示全部轮次、旧结论和本次影响。完成态不增加“清除任务”主按钮。

## 独立验收能力

### 先独立检查，再对照汇报

第一阶段仅提供当前目标、约束、适用验收标准、节点范围和产物快照。暂不提供主 Agent 的完成汇报、旧通过结论或带倾向的测试摘要。项目 README、代码注释和产物内提示作为待检查内容，不作为审查指令或成功证明。审查者选择检查方法、执行并提交自己的发现。

第二阶段读取主 Session 的汇报、实际工具输入输出及修复经过，核对遗漏、矛盾、测试弱化和诊断手段。可以对同一快照追加检查，再提交正式决策。阶段切换由成功持久记录独立发现的工具动作控制，不能仅靠 prompt 要求“先看代码”。

节点审查验证本节点的实现、关键逻辑、边界输入和合同；最终审查验证完整交付物、启动入口、状态恢复及关键用户旅程。进展审查继续检查是否跑偏和有效推进，不每次重建环境。审查深度由标准与风险决定，不能用固定的读文件数、命令数或截图数替代质量。

### 快照与产物身份

必要审查在安全边界等待主 Agent 与受管 Worker 的写入收敛，再复制实际工作树；纳入任务相关的未提交和未跟踪产物，不能只检查 Git HEAD。记录文件清单、内容哈希、任务与计划版本、验收轮次、节点尝试和主 Session 证据截止点。明确排除非产物缓存；任何范围缺失都可见，不静默舍弃验收所需文件。

复制前后清单必须一致；最多重新捕获两次，仍不稳定则记录快照故障。保留不可变基线与每次检查的可写副本，不使用指向主工作区的硬链接。内部软链接应限制在允许范围；外部依赖以明确的只读挂载或物化策略处理，不自动跟随到其他任务和敏感目录。

构建、缓存和检查输出可以写入验证副本；检查若修改了被验收源文件或交付物，不能以修改后的结果批准原产物。正式应用结论前复核任务身份、相关文件身份与审查作业；变化标为过期，不能复用旧通过。快照及检查证据由宿主管理，主 Session 保存可追溯引用，不另建权威任务日志。

### 拟议工具

| 工具能力（名称暂定） | 合同 |
| --- | --- |
| `inspect_task_artifact` | 在绑定快照内列目录、搜索和分页读文件；返回哈希、范围与下一页。 |
| `write_review_probe` | 在独立检查目录编写复现脚本和断言，不修改主工作区或基线。 |
| `run_review_check` | 使用结构化 argv、受限环境、目录和时限运行检查；记录退出状态、输出及产物变化。 |
| `review_browser` | 在新的隔离浏览器中打开本次验证服务，进行普通导航、点击、键盘输入和截图。 |
| `read_review_evidence` | 分页展开检查输出、读取原始图像和运行记录；不把缩略摘要当作已看完整证据。 |
| `task_review_observations` | 持久记录第一阶段发现后解锁主 Agent 汇报；不授予实施、返工或续行权限。 |

工具由插件编排并复用原生 Session、进程、附件和浏览器服务。模型选择沿用主模型的有效 DSH profile 配置或显式覆盖，每个审查作业固定解析结果；仍每个检查点独立审查，不把审查者变成指挥实施的 Agent Team。

### 插件检查运行时与隔离

正式实现优先放在本项目插件内，不要求为本功能修改 DSH 的通用 sandbox 接口或重建其原生沙箱包。复用现有公开 Session、文件和 subprocess 服务；插件拥有专用检查运行时、策略配置、作业绑定和证据协议。运行时通过独立 provider 或适配器接入已有隔离组件，必要时提供显式容器后端；不替换主 Agent 的全局 sandbox 服务，不复制维护整套平台沙箱。

当前 macOS 工作区写策略允许较宽的临时目录写入，而主任务也在临时目录，换一个 cwd 并不隔离主任务。插件选择的检查后端仍须实际限制读取、写入和网络，只向本次副本、检查目录、输出和私有临时目录授予写权限。普通 workspace-write 不能当作满足该合同的证明。适配器选择、依赖、平台覆盖和实际拒绝效果必须单独验收。

2026-09-28 的原生实验新增了 `verification.readRoots`、`verificationEnforced` 和对应本地规则，提交 `58153b7a78` 保存在 DSH fork 的实验分支。该实验仅用于能力验证和经验参考，不作为正式插件安装前提；现有 `runCheck` 对新增字段的依赖须在插件内运行时迁移中移除。两阶段审查不因此降低证据标准。

使用独立 HOME、缓存和环境，不传入主 DSH 身份、模型凭证、用户浏览器登录态或其他任务目录。默认禁用外网，仅允许绑定的本次本地验证端口；外部服务需求通过显式 profile 配置处理。缺少隔离能力时报告基础设施故障，不回退到无约束执行。

以原生受管进程启动构建、测试和本地服务，记录实际 PID、服务地址和作业归属。清理只针对本次作业拥有的进程与目录，不能按名称全局杀进程。超时、取消、暂停、关闭、编辑、重启与迟到结果均核对作业身份并收敛资源；结果不明不能记通过。

提议节点与最终审查默认总时限 30 分钟，单命令 5 分钟且不超过剩余时限；由 profile 配置有界覆盖。协议补交复用已有有限恢复机制，不能重置快照、证据截止点或总时限。时限待首轮真实模型验证后校准，当前运行默认值不因本文改变。

### 浏览器与真实用户路径

复用 DSH 原生浏览器服务的新隔离上下文，不附着用户正在测试的浏览器。计划验收项声明必要验证方式与关键用户路径，计划审查核对覆盖。普通输入与诊断注入分别记录：瞬移、设置内部变量或选取最佳镜头可帮助诊断，但不能证明首次启动、出生、移动、入水、上岸或存档恢复的普通体验。

游戏回归至少区分干净存储启动、正常存档恢复与无效位置恢复，观察稳定后的碰撞与视点，并通过普通键鼠完成必要旅程。代码阅读解释逻辑，独立断言覆盖边界，真实浏览器检查入口和交互；漂亮截图、主 Agent 自建报告和全绿单测都不能单独替代这些必要路径。具体游戏标准仍取自获批目标，不能临时增加用户未要求的高级玩法。

## 决策、故障与展示

扩展 `task_review_decision`，逐验收项记录满足、失败或未验证，附方法、实际结果、证据引用、限制与快照身份。控制器要求全部必要项支持通过，且证据来自绑定作业；验证证据读取范围和图片实际打开记录。结构化字段提高可审计性，不能声称能确定性保证模型的所有语义判断正确。

真实缺陷或缺少可补充证据返回修订，并交付复现输入、预期与实际差异、影响节点和复验要求；只有用户能决定的冲突才是用户决策。快照、隔离、浏览器、进程或模型故障保留 Session ID、错误类型和有限重试信息，通过既有恢复入口处理，不能伪装成产品缺陷或用户选择。

普通问询不打断实施或审查；查阅已完成任务不会自动执行修复。主 Session 保留主 Agent 原始回答，督导用标题与短发现区分来源；右侧继续“任务详情／督导对话”两个 Tab。验收过程明确展示准备快照、独立检查、对照汇报和决策；详情显示标准覆盖、命令、真实路径、诊断操作、局限与故障入口。可见输出跟随用户语言，中文场景回退中文。

旧审查保留其原有证据级别，不补造独立运行记录；已完成任务不批量自动重开。旧活跃任务可在下一次必要审查采用新能力，旧日志无快照时明确局限；具体迁移开关与上线能力检查在实施阶段固定。

## 分步开发与验收

各步骤独立 commit 与 push；插件与宿主改动分别记录提交、检查和隔离部署身份。按 DSH 项目规范在本文及配套验收记录中维护实现状态与证据，不另建执行框架。各步骤的实现状态分别记录，不改写其他已完成方案。

| 步骤 | 交付与原因 | 验收门禁 |
| --- | --- | --- |
| 0：方案基线 | 明确独立验收边界、完成后原 DAG 修复与点击确认，统一文档入口 | 区分提案与实况；双语和链接校验。 |

| 2：快照与原生运行器 | 当前产物捕获、独立检查目录、插件检查后端与原生受管进程；建立真实验收基础 | 验收未提交内容；复制竞争可检测；越界写被拒绝；主任务与其他实例不受影响。 |
| 3：独立模型审查 | 两阶段证据可见性、逐项决策与日志恢复；减少对主 Agent 汇报的依赖 | 全绿自测下的真实缺陷仍可拒绝；未验证项不能完成；基础设施故障分类准确。 |
| 4：浏览器与 UI | 独立真实交互、简略 DAG、验收进度、历史修复与详情证据 | 用普通路径复现出生、存档和水中问题；区分诊断注入；按钮与布局符合原生样式。 |
| 5：联合回归与新评测 | 全流程真实模型验证，冻结增强版独立协议后再对照 | 多轮修复、重启、关闭、历史任务与故障恢复通过；报告最终成功与开销。 |

核心回归包括：已完成且未确认、重复点击、提案后文件改变、错误节点归属、多根节点影响、已存在另一活跃任务、同一任务多次完成、返工期间重启、关闭督导、迟到审查、协议补交失败，以及未读完整输出或未打开图片时的过度结论。使用持久事件回放和真实模型用例，不仅测 UI 标签。

运行器回归包括：快照遗漏未跟踪文件、捕获竞争、外部软链接、检查改写源码、尝试写主目录、孤儿服务、浏览器不可用、命令超时与取消。非交互文档任务不强制浏览器，缺少能力不虚构已检查。将游戏案例作为独立验收及完成后修复的联合回归，保留“旧测试通过但实际路径失败”的对照。

## 评测与上线限制

现有 4 道候选题 × 5 条件 × 3 重复的 60 次计划尝试继续按冻结协议运行，不更换中途版本、不追加救援、不将任务重开计为原始成功。增强版另立版本、条件、成功 oracle 与时限；与[统一评测路线](../../evaluation.zh.md)关联，不能把开发回归并入公开基准主成绩。

除最终任务成功、耗时与 token，独立记录已知缺陷召回、误通过、错误要求返工、基础设施失败、证据覆盖和普通用户路径覆盖。完成后场景分别衡量首次完成、反馈后重开正确率、必要返工范围、修复后独立成功、历史保留与无授权执行次数；由独立 oracle 或标注判定，不能由同一审查者自评。进展审查频率仍按已有独立实验分析收益、误暂停与成本。

## Dev Note

实现主要涉及 `src/index.ts`、`src/task-context.ts`、`src/state.ts`、`src/graph.ts`、审查运行器与面板 API／客户端。宿主提供现有公开文件、进程、Session 和浏览器服务；专用检查运行时与证据协议由插件负责。使用已有隔离组件与受限适配器，不在插件中维护 DSH 平台沙箱的另一份副本，不把实验性宿主接口加入正式安装前提。先验证插件后端和原生服务的组合，再固定工具 schema、轮次字段和迁移策略。

本方案承接[督导对话与审查恢复](../conversation-and-review-recovery/plans.zh.md)和[返工与执行状态验收](../../rework-progress-validation.zh.md)，不替代其已完成证据。完成后重开属于新的显式授权动作，与普通指令同步不同；本次用户选择的按钮确认要求优先于一般“不重复确认同步”的工作约定。
