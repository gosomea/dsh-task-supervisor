# 架构提案

**状态：设计提案。** 项目目前没有可运行插件。本文负责记录拟议的任务生命周期与组件职责。[审查策略](review-policy.zh.md)负责介入行为；[评测](evaluation.zh.md)负责比较结论。

## 摘要

同一个 DSH 会话承载用户请求、后续指令、Agent 行为和工具结果。督导为该会话维护持久任务状态，决定何时续行、暂停或完成。主 Agent 执行工作；独立审查者检查已记录的证据。

## 任务职责

| 角色 | 职责 |
| --- | --- |
| 用户 | 设定目标与约束，首次自主计划确认一次，并处理明确暂停的决策。 |
| 主 Agent | 提出和更新计划，在绑定会话中执行，记录结果，申请完成。 |
| 督导控制层 | 拥有持久任务状态、有效计划版本、轮次准入、审查决策执行和任务终态裁决。 |
| 轮次审查者 | 默认每个检查点独立运行，返回有证据引用的发现与建议动作。 |
| 专项审查者 | 只有具体发现需要聚焦核查时才运行。 |
| 最终验收器 | 独立核查完成申请所依赖的会话证据和工作区结果；在隔离副本执行验收检查。 |

控制层执行确定性的状态转换。模型审查者提供发现与判断，不直接修改主工作区或控制状态。默认拓扑是“持久任务状态＋每个检查点新的独立审查者”；连续审查者会话是可配置的替代模式。

## 共同证据与状态

绑定的主会话日志是用户指令与已观察执行行为的事实来源。同一会话中的新用户指令经正常任务状态更新路径生效；用户不需要为 Agent 与审查者之间的人为同步再确认一次。插件为任务理解、计划版本、审查发现、用户决策、续行和最终裁决记录自己的持久事件。重启后通过可回放投影重建控制状态；进程内存不能是唯一记录。

审查者从最近一个已完成轮次开始，缺少上下文时向前翻页，之后用增量事件游标跟进。其读取工具绑定主会话，不能任意选择 session ID。工具返回结构化边界和事件 ID；更长的消息正文、工具输入或输出须按需展开并脱敏。每条发现引用支持它的事件 ID。[审查策略](review-policy.zh.md)负责访问与介入规则。

## 生命周期

```text
用户请求
  → 任务理解与初始计划
  → 自主多轮执行前由用户确认一次
  → 执行一轮
  → 动作前轻检与独立轮次审查
  → 续行、修订计划，或暂停请用户决策
  → 必要时进行里程碑审查
  → 主 Agent 申请完成
  → 独立最终验收
  → 完成、继续，或等待用户
```

控制层为短任务选择单轮路径，为较长任务选择自主续行，并可随证据变化切换。工作未完时可以开启下一轮。完成申请在最终验收通过前只是提议。确认停滞后暂停并请用户决策。宿主重启后恢复状态，但执行保持暂停，直到用户手动恢复；不得静默开启新轮次。

## DSH 集成方向

计划通过 DSH 插件注册与 effect 清理、持久 session event 与 projection、Agent 生命周期钩子和原生客户端扩展点实现。目标 DSH 配置档针对绑定任务替代原生 Goal 与 Plan 控制，避免两个轮次驱动器竞争。现有 [Goal 包](../../../deepseek-harness/packages/goal/README.zh.md)、[Plan 模式](../../../deepseek-harness/packages/plan/plan-mode/README.zh.md)和 [DSH 架构](../../../deepseek-harness/docs/architecture.zh.md)是实现参考，不默认继承其行为。[Jev 验证原型](../../dsh-jev-verifier/README.md)可提供部分解析、重复动作检测、结构化审查和 UI 思路；其内存状态与每轮固定三名审查者不定义本项目架构。
