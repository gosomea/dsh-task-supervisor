# 架构提案

**状态：产品设计。** 已有依赖隔离 DSH 宿主扩展的有限原生原型；[实现状态](implementation.zh.md)区分已运行能力与剩余设计。本文负责组件职责与集成方向。[任务生命周期](task-lifecycle.zh.md)负责任务状态和控制。[审查策略](review-policy.zh.md)负责介入行为；[评测](evaluation.zh.md)负责比较结论。

## 摘要

同一个 DSH 会话承载用户请求、后续指令、Agent 行为和工具结果。督导为该会话维护持久任务状态，决定何时续行、暂停或完成。主 Agent 执行工作；独立审查者检查已记录的证据。

## 任务职责

| 角色 | 职责 |
| --- | --- |
| 用户 | 设定目标与约束，首次自主计划确认一次，并处理明确暂停的决策。 |
| 主 Agent | 提出和更新计划，在绑定会话中执行，记录结果，申请完成。 |
| 督导控制层 | 拥有持久任务状态、有效计划版本、轮次准入、审查决策执行和任务终态裁决。 |
| 检查点审查者 | 默认每个检查点独立运行，返回有证据引用的发现与建议动作。 |
| 专项审查者 | 只有具体发现需要聚焦核查时才运行。 |
| 最终验收器 | 独立核查完成申请所依赖的会话证据和工作区结果；在隔离副本执行验收检查。 |

[督导会话模块](session-runtime.zh.md)负责持久记录、回放、恢复和证据引用；它复用原生 Session 日志，联合审查会话形成审计视图。模型选择复用 DSH profile 配置，具体策略见[审查模型](review-model.zh.md)。

控制层执行确定性的状态转换。模型审查者提供发现与判断，不直接修改主工作区或控制状态。默认拓扑是“持久任务状态＋每个检查点新的独立审查者”；连续审查者会话是可配置的替代模式。

## 与 Agent Team 的关系

主 Agent 仍是任务执行者。Supervisor 是由独立模型审查辅助的确定性任务控制器，不增加一个将整项任务委派给 Worker 的通用 Lead。Team 已提供持久协作，得到明确指令的 Lead 也能审查和纠错。Supervisor 必须通过强制检查点、独立完成权限和一致恢复语义证明价值。确切边界与竞争对照见[首个原型与 Team 对照](prototype.zh.md)。

## 用户入口

Supervisor 使用独立命令命名空间，暂定 `/task`。用户可从创建任务或先规划开始，二者进入同一套任务生命周期。插件在规划、持久目标、续行和完成裁决的功能上提供 Goal 与 Plan 的替代选择；原生命令仍归原插件所有。入口不固定任务时长，控制层可依据任务证据选择单轮或自主多轮。

| 命令 | 拟议的督导行为 |
| --- | --- |
| `/task new <objective>` | 创建任务并提出初始计划；自主多轮执行前取得一次用户确认。 |
| `/task` | 在 Supervisor 展示任务列表、所选任务、审查发现和可用的下一步。 |
| `/task edit <objective>` | 更新所选任务目标并记录新的有效版本；主 Agent 根据同一会话证据修订计划。 |
| `/task pause` | 停止自动续行，同时保留任务状态。 |
| `/task resume` | 明确恢复已暂停任务，包括宿主重启之后。 |
| `/task clear` | 结束当前任务，并保留其持久历史。 |
| `/task plan [request]` | 携带请求时创建草案，无请求时打开所选任务规划；获批工作进入同一套执行生命周期。 |
| `/task plan off` | 退出规划，不把未获批草案当作执行许可。 |
| `/task off` | 关闭 Supervisor，保留任务状态并停止其执行与审查。 |
| `/task on` | 启用 Supervisor；任务仍须明确恢复。 |

命令与右侧面板控件进入同一督导请求路径。有限列表、所选任务、JSON 快照、关闭按钮及命令恢复规则见[任务生命周期](task-lifecycle.zh.md)。后续用户指令或 `/task edit` 不是人为的第二次同步审批；主 Agent 与审查者读取同一会话记录。只有审查策略明确暂停，或宿主其他审批要求适用时，才需要新的用户决策。

## 共同证据与状态

绑定的主会话日志是用户指令与已观察执行行为的事实来源。同一会话中的新用户指令经正常任务状态更新路径生效；用户不需要为 Agent 与审查者之间的人为同步再确认一次。插件为任务理解、计划版本、审查发现、用户决策、续行和最终裁决记录自己的持久事件。重启后通过可回放投影重建控制状态；进程内存不能是唯一记录。

审查者从最近一个已完成轮次开始，缺少上下文时向前翻页，之后用增量事件游标跟进。其读取工具绑定主会话，不能任意选择 session ID。工具返回结构化边界和事件 ID；更长的消息正文、工具输入或输出须按需展开并脱敏。每条发现引用支持它的事件 ID。[审查策略](review-policy.zh.md)负责访问与介入规则。

## 生命周期

```text
用户请求
  → 任务理解与初始计划
  → 自主多轮执行前由用户确认一次
  → 执行一轮
  → 检查是否触发阶段审查或进展兜底
  → 阶段内续行、修订计划，或暂停请用户决策
  → 已完成阶段进入下一阶段前独立审查
  → 主 Agent 申请完成
  → 独立最终验收
  → 完成、继续，或等待用户
```

控制层为短任务选择单轮路径，为较长任务选择自主续行，并可随证据变化切换。工作未完时可以开启下一轮。完成申请在最终验收通过前只是提议。确认停滞后暂停并请用户决策。宿主重启后恢复状态，但执行保持暂停，直到用户手动恢复；不得静默开启新轮次。

## DSH 集成方向

实现使用 DSH 通用插件注册与 effect 清理、持久 session event 与 projection、Agent 生命周期钩子和客户端扩展点。Supervisor 拥有自己的命令、模型工具、状态服务、投影、续行驱动器和右侧面板。安装时不覆盖 `/goal`、`/plan`，不接管原生 `get_goal`、`create_goal`、`update_goal`、`exit_plan_mode`，不要求卸载 Goal 或 Plan，也不读写它们的私有状态。模型工具的确切名称与 schema 待定；主 Agent 的完成操作只能提交验收申请。

同一 DSH 安装可以同时具备原生工作流和 Supervisor。首版支持在专用 Agent preset 和新的督导会话中运行；该 preset 组合通用执行工具与督导自己的任务工具，避免主 Agent 在受督导轮次中又启用另一套任务控制。单个会话同时由两个控制器续行不属于支持场景。已有原生任务需要先由用户停止其续行，或换一个会话开始督导任务；插件不自动接管旧任务。工具可见范围和 preset 准入方式必须在隔离宿主验证，不能仅凭命令不同就声称两套流程可以安全混跑。

关闭 Supervisor 只停止它拥有的工作，不自动启动原生 Goal 或 Plan。宿主依赖限于 DSH 通用能力；Goal 与 Plan 可作为行为和源码参考，不能成为督导运行的必需服务。安装组合、模型工具可见性和客户端加载需要证明原生插件可保留、独立使用，且 Supervisor 也可在未挂载原生 Goal 与 Plan 服务时运行。参考 [DSH 架构](../../../deepseek-harness/docs/architecture.zh.md)；[Jev 验证原型](../../dsh-jev-verifier/README.md)提供可选择移植的经验。
