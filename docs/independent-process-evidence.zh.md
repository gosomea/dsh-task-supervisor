# 独立审查的流程证据边界

## 状态与原因

这是待实现的插件契约。2026-09-29 的[真实校准](../eval/deepswe/control-independent-calibration-20260929-1.json)验证了独立读文件、执行检查和先观察后对照，但没有完成节点与最终审查。检查目录不包含 `.git`，也不包含主方 `/eval/node24`。替代 Node 测试通过，不能证明主方执行了指定程序；工作树正确，不能证明它已经提交。

程序不存在和错误目录属于可纠正调用；检查副本被修改、容器身份失效或原生清理不确定，仍阻止验收。错误分类修复不补造缺失的流程证据。正式公开题保留原 Git 提交要求，准入保持关闭。

## 已实现的管理员接口

`dsh-task-supervisor/process-provenance` 提供进程内管理员 API。世界、审查范围和流程收据使用严格结构；范围包含任务版本、计划版本、节点尝试、证据截止点及产物摘要。世界包含确切容器、管理员租约与截止时间。

收据独占创建并刷盘。读取核对可信 seal、完整范围、世界身份和存储目录身份；任务版本变更或范围失效后，旧收据继续保留，但不能支持当前裁决。重启恢复必须由可信部署端提供收据 ID 与摘要，不会扫描目录后自动认可 JSON。无可信捕获能力时保存 `unavailable`，不会生成通过证据。

此接口尚未安装为模型工具，也未接到当前评测实例。provider 的独立身份核对与捕获屏障仍须由管理员部署实现。文件权限和摘要不能隔离拥有管理员文件访问权的模型；当前主 Host 与模型执行工具位于同一容器、同一文件权限，不能借可读 socket、Session 字符串或配置 secret 认证控制器来源。后续模型读取工具须提供公开投影，不能输出完整私有 world。

13 项无模型测试覆盖持久恢复、外来任务及产物范围、变更的容器身份、篡改收据、失效期间的捕获、并发重复恢复、存储目录替换和异步过期。它们验证收据接口，不代表原生 Docker 捕获或真实模型审查已经验收。

同一管理员入口还提供 `analyzeGitCapture`。它将已捕获的 Git 数据复制到新的私有计算目录，使用原生 subprocess 与 Git plumbing 计算 HEAD、tree、父提交、index 和快照原始内容之间的关系。源仓库 config、hooks、filters、外部 diff 和对象重定向不会被执行。未提交、暂存、工作树及未跟踪差异分别返回；排除了 `.git` 以外路径时，整个工作区干净状态为 `null`。

11 项真实临时 Git 仓库测试覆盖提交后变更、正确但仅暂存的产物、unborn 仓库、恶意配置与过滤器、pack objects、文件模式与链接、损坏数据和额外排除。此计算模块不负责证明原世界已被冻结、Git 二进制已冻结或捕获来源已认证；调用方必须满足这些前提，不能用多次哈希相等代替写入屏障。

`withPausedWorld` 在独立管理员执行世界中提供 Docker 捕获屏障。它核对确切 main/admin 容器、owner、镜像 config ID、独占命名卷及管理员只读挂载；检查额外可写挂载，确认主容器已暂停后才调用捕获。它只释放自己取得的暂停；捕获失败也要确认释放。越过截止时，通过外部截止权限停止确切原容器并确认不再运行。未知拓扑、外来 owner、原先已暂停、权限失效和不确定清理均拒绝返回有效屏障。

18 项无模型模拟原生接口测试覆盖这些分支，包括 unpause、释放租约和最终返回期间越过截止。真实 Linux/Docker 验收尚待完成。`acquire` 与 `withCutoffAuthority` 必须由可信部署提供真实独占权限和外部截止控制；接口上的布尔值不是权限证明。镜像 config ID 与 pull manifest digest 分开绑定。当前评测实例尚未部署新增的独占工作区卷、只读管理员挂载及可信范围注册；主 Host／控制器与模型工具共享权限，控制器来源也未得到认证。因此生产 profile 未启用该屏障。

原生测试 probe 保留限长、限深和脱敏的嵌套错误诊断；`AggregateError` 的捕获与清理原因分别可见，不导出任意错误属性、控制对象或私有路径。失败尝试与清理证据保留在独立目录，不因诊断改进而重写。

`publicProvenanceReceipt` 提供稳定证据 ID，并省略完整私有 world 的租约、daemon、owner 与容器绑定。`createProvenanceConsumer` 提供收据及输出分页、完整读取跟踪和显式流程要求校验；每次可信读取前后重新核对完整当前范围，输出核对管理员捕获 ID 与原始摘要后才脱敏展示。阅读记录只在消费者内存保存，重启必须重新完整读取；模型不能提交自报阅读范围。

流程要求显式区分 Git 与实际执行，不从验收文字猜测。Git 可要求当前产物与 HEAD、index 及工作树一致，以及可确认的整个工作区干净状态；执行要求核对实际 runtime、程序与依赖摘要、argv、cwd、未变更产物和完整双流输出。缺收据、未知清洁状态、超时、取消和不完整执行均不能通过；产物行为仍需原有独立文件或运行检查，流程收据不能替代。19 项无模型消费者测试覆盖有效、外来、过期、部分读取、被修改和未知证据，以及 JSON 输出和序列化 argv 的命名 API key 脱敏。脱敏覆盖已识别的格式，不代表任意秘密都可识别；原始摘要不使用展示文本计算。

此消费者尚未安装为模型工具或接到现有裁决门禁。结构化主验证执行、运行时依赖闭包冻结和可信部署仍未完成，正式评测准入保持关闭，当前为 0/16。

## 三类证据

| 类型 | 能证明什么 | 来源 |
| --- | --- | --- |
| 产物 | 当前文件的实现、行为和约束 | 不可变快照、完整文件读取、独立检查及其输出。 |
| Git 流程 | 提交身份、父提交、干净状态、提交内容与当前产物的对应关系 | 插件管理员捕获、可信 Git 独立计算的收据。 |
| 执行流程 | 实际执行的程序、参数、目录、退出结果与产物版本 | 可信原生进程执行边界生成的收据。 |

主 Agent 的总结和 shell 输入文本可以作为调查线索；它们自身不能证明提交与实际执行。版本号一致不能证明二进制一致。独立组应同时报告产物验收覆盖和流程验收覆盖，缺失项保持 `unverified`。

## 插件契约

沿用现有管理员网关与私有存储，不修改 DSH 原生沙箱。模型只能按当前任务读取收据，不能指定主容器、宿主路径、Git HEAD 或管理员执行命令。收据绑定任务版本、节点尝试、快照 ID 与产物摘要、主执行容器确切身份、证据截止点和捕获时间。

当前检查请求中的 `sessionId` 是客户端字符串，仅用于记录，不能作为新增流程收据的授权。可信启动器应先注册执行世界：Docker daemon、确切容器 ID 与 owner label、工作目录、主 Session 和租约；任务控制器再绑定任务版本、节点尝试、截止点与产物摘要。模型仅引用不透明绑定 ID。管理员自行核对身份，不接受客户端任意上传的“成功收据”；生产收据的通道或 capability 与模型可用的检查 socket 分开。

现有原生 `subprocess.spawn` 返回受管 handle，没有通用的 spawn 审计事件；Cordis 的 `intercept` 合并配置，不能直接充当进程方法中间件。shell 通常只暴露 `bash -c`，PTC 的内层 `child_process` 和动态导入也不经过插件可见的直接调用边界。拟实现的结构化主验证工具声明 `coverage=top-level-direct`，通过原生 spawn、done、输出收集与 waitForExit 记录结果。它不能替普通 shell／PTC 内部调用背书。二进制路径解析后还需取得实际文件摘要，并冻结只读文件及依赖，避免哈希与启动之间被替换。

Git 捕获在主方受管写入收敛后进行；捕获前后核对 HEAD 和工作树摘要。管理员私有副本计算已提交内容、父提交关系、已跟踪及未跟踪文件状态。禁止执行仓库提供的 hooks、别名、外部 diff、过滤器与配置；不能直接在管理员环境信任任意仓库 Git 配置。`.git` 不进入普通模型可写检查目录，也不向模型导出凭据、远端认证信息或完整历史。无 Git 的任务返回明确的不可用状态。

执行收据在真正启动程序的原生边界产生，记录解析后的可执行文件摘要、结构化 argv、cwd、开始与结束时间、退出结果及输出摘要。仅记录 `sh -lc` 字符串不能证明其中每个程序实际执行。无法观察内部执行时明确记录覆盖不足；必要时提供插件拥有的结构化验证执行工具，不能用未经验证的 shell 文本生成成功收据。

检查复验使用管理员配置的相同冻结 runtime；只读挂载的可执行文件与依赖闭包都进入 release。主方执行过指定命令与独立方重新执行成功分别保存，不互相替代。运行器配置不由模型提供。

拟提供 `inspect_task_provenance`，分页读取当前绑定收据并返回稳定证据 ID。验收器检查证据类型、版本、完整读取与当前产物绑定，Git 标准不能引用 README，执行流程标准不能仅引用版本号。先独立产物观察、再读取主报告的两阶段门禁继续保留；流程收据由管理员产生，可以独立检查，但不能携带主方成功总结。

## 部署接入要求

可信 Host、Session 存储和范围注册须位于主方执行容器之外。DSH 的 SSH、远程 filesystem、subprocess 和 sandbox provider 可通过插件组合使用；管理员另用不注册模型工具的本地执行 context 访问只读工作区卷、Git 与 Docker。工具注册 context 必须取得远程 PTC/runtime，不能只替换 Agent 的执行 service 却继承本地工具注册器。当前 `prepareVerification` 依赖 Host 本地 filesystem，仍需接入管理员快照 provider；单纯更换全局 filesystem 或 subprocess 不完成这一接入。

跨平台部署要处理 Host 绝对路径：现有文件搜索工具按 Host 平台定位 `rg`，不能把 macOS 路径发送到 Linux；可在独立 profile 中使用远程 shell 的 `rg`。SSH helper、PTC bootstrap、Node 及完整依赖闭包须冻结并只读部署，远程原生范围的清理能力须实际验证。整容器截止停止与每条命令的范围收敛分别记录；未知或降级的进程范围不能产生 `rangeQuiescent=true`。这些要求尚未完成部署验收，也不改变日常 profile。

## 开发与验收顺序

1. 定义收据结构与适用标准，区分产物行为、Git 提交和主方实际执行。
2. 完成管理员捕获、版本一致性与私有持久化；无模型测试覆盖未提交、未跟踪、提交后变更、外部 Git 配置和错误容器身份。
3. 接入只读工具及确定性裁决校验；拒绝外来、过期、部分读取或不同产物版本的收据。
4. 使用新的校准 Session 验证有效节点与完成裁决，再冻结正式运行版本。原失败 Session 保留，不追加恢复提示或更改截止。

测试需含真实负例：工作树正确但未提交、已提交但当前文件不同、同版本号的不同二进制、只有 shell 声明却未运行，以及快照与 Git 捕获期间发生写入。只有证据本身通过这些验证，才可进入正式 16 个位置；可用产物检查不等于全部流程义务已验收。
