## 任务与执行时间线

用户要求创建一个完整的 Three.js 博丽神社微缩场景，包括正方形底座、居后的神社建筑、开阔前院、第三人称旋转缩放、无 UI 的三渲二风格，以及丰富但克制的环境细节和微动画。前院还需要像素灵梦：使用受光二维面片，低帧率扫地，几轮后轻跳换位，表现起跳预备、腾空和落地缓冲，并正确处理脚底高度、地面阴影、落叶互动和停顿时的朝向切换。

这是一项多模块视觉交互任务。运行超过两小时本身不足以证明异常；判断重点在于是否有新增成果、是否持续遵守要求，以及 Supervisor 是否能在需要时发现并纠正偏移。

### S8 的长耗时包含具体修复

S8 一轮包含约 121 次工具调用：4 次写入、43 次编辑、53 次命令执行、4 次文件读取、16 次图片读取和 1 次阶段汇报。日志记载的修复包括扫帚像素绘制被裁切、扫帚穿地、下蹲导致脚底沉入地面、图集写入覆盖其他帧、二维面片侧向相机导致角色变成细线，以及扫帚被裙子遮住或配色不易辨识。

## 偏离预期与设计缺口

### 单个长轮次避开了进度审查触发条件

已确认：自动进度检查位于 `agent/status` 的 `idle` 分支内，依据 `roundsSinceReview` 与配置阈值判断是否开展进度审查。主 Agent 没有结束当前轮次时，这个分支不会执行。实现位置见 [自动续行逻辑](../../src/index.ts)。

本次 S8 的约 47 分钟阶段中，主 Agent 长时间停留在一个轮次里。它通过自己的调试和图片检查解决问题，Supervisor 主要等到阶段汇报后才介入。期间没有独立进度审查记录。

因此，“最多若干轮未汇报就审查”没有限制一个轮次内的工具调用数或耗时。主 Agent 是否愿意结束本轮，实际上影响了 Supervisor 能否及时检查。这是与“长程执行中适时纠偏”直接相关的机制缺口。

这里不能进一步推出每个长轮次都应该被打断。S8 确有产出，现有资料也不能证明更早介入一定能缩短耗时。可以确认的是：当前触发方式没有提供这次需要的观察机会。

### 旧 CSV 小题被纳入神社计划

执行工作区原有 README 要求使用 `data.csv` 并保持 `data.csv`、`verify.mjs` 不变；验收器读取 `report.json` 并核对 CSV 数值的数量和总和。这与神社场景目标没有直接关系。

主日志 seq 62 显示，主 Agent 已识别该工作区只有 CSV、验收器和 README，并明确描述其与当前目标无关。然而计划 C13 仍要求“data.csv 与 verify.mjs 保持不变且 verify.mjs 通过（附 report.json）”，并将其带入最终验证阶段。计划审查没有拒绝该项。

问题同时涉及两层：测试工作区混入旧任务材料；计划生成和审查没有将旧材料与本次目标区分开。保留现有文件可以是合理约束，但把旧题的输出要求变成本次成功条件，需要额外依据。

用户随后批准了整体计划，因此这不是批准之后擅自修改计划的证据。缺口发生在计划提出和审查环节。CSV 工作本身可能很短，不能把它说成两小时耗时的主要来源；它更直接地反映了任务范围污染。

### 审查证据无法表达视觉质量

已确认：[审查实现](../../src/reviewer.ts)中的 `contentText` 只提取文字块。审查者允许调用的工具是 `read_task_evidence`、`read_task_call` 和 `task_review_decision`，没有图像查看或工作区浏览能力。`read_task_evidence` 返回截断后的文字证据，`read_task_call` 返回有长度限制的工具参数。

主 Agent 能看图，审查者无法看到同一张图。对当前任务，审查者可以核对测试执行记录、部分工具参数及主 Agent 对截图的描述，却不能直接判断角色是否可辨识、扫帚是否可见、画面风格是否一致或动画是否自然。

阶段通过因而包含能力边界：行为和执行证据受到一定检查，视觉质量主要依靠主 Agent 自查。不能从全部 `pass` 推出审查毫无价值，也不能把这些 `pass` 解读为完整的视觉独立验收。

### 计划审查对要求来源的检查不足

审查提示要求覆盖原始目标、检查遗漏和矛盾，并强调顺序约束；实际计划却接受了无关 CSV 验收和用户未明确要求的独立只读轮。来源、必要性和范围扩张的判断没有得到可靠体现。

其他计划内容还把部分实现选择变成了验收要求，例如本地 vendored Three.js、特定轮廓渲染方式及自动化断言方案。这些选择不一定错误，也可能利于交付，但需要与用户直接要求区别对待，否则后续审查容易把“符合既定实现计划”当成“满足用户目标”的全部含义。

本案例足以支持改进要求来源和范围审查，不足以证明提示词措辞是唯一原因。模型能力、工作区背景、证据展示方式及计划批准流程都可能影响结果。

“监督不足”和“实现困难”在本例同时存在。Supervisor 没有及时提供判断返工是否仍有价值的机会；与此同时，复杂像素角色与 3D 场景结合确实产生了需要解决的问题。没有对照运行时，不能断言换成 Goal 或 Plan 就会更快。

## 与长程评测的关系

这次神社任务提供了真实的长轮次、视觉证据、返工和自动续行案例，可用于提炼评测场景。它不是正式比较试验：缺少固定的外部验收器，没有对齐其他控制方案的运行条件，任务仍未结束，也没有可比较的最终成功判定。

280 条自建测试可以支持局部实现检查，但测试由被评测 Agent 编写和修改，不能担当独立成功率指标。审查全部通过可以描述控制器行为，不能直接作为目标达成率。

如果将本案例用于改进插件，应将其标记为开发案例。正式比较仍需另保留真实任务，固定初始仓库、用户请求、环境、约束和预设变更触发点，并让验收器独立于 Agent 工作区。比较对象和既定评测边界见[评测设计](../evaluation.zh.md)。

本案例特别提醒：除了总成功率，还要观察长轮次中纠偏机会的覆盖情况、无关要求进入计划的比例、审查结论可被哪种证据支持，以及发生重复失败后能否恢复有效推进。这些指标的定义和阈值仍需讨论，不应直接从本次结果倒推有利于 Supervisor 的指标。

## 结论与未确认事项

| 问题 | 本次结论 | 边界 |
| --- | --- | --- |
| 是否在正常推进？ | 有持续、可见的有效推进 | 没有完整独立验收所有成果 |
| 是否卡在自动续行死循环？ | 观察范围内没有发现 | 不覆盖观察截止后的行为 |
| 是否出现不符合预期的过程？ | 有：范围污染、长轮次缺少审查、视觉证据不足 | 不代表所有长耗时都不必要 |
| 是否与 Supervisor 设计有关？ | 是，触发机制和证据能力存在明确缺口 | 主 Agent 的实现与调试问题也贡献了耗时 |
| 是否完成了用户任务？ | 检查时尚未完成，仍在 S9 | S10 和最终完成裁决尚未观察 |
| 是否证明优于 Goal/Plan？ | 不能 | 缺少同条件对照和独立验收 |

整体结论是：自动续行和阶段推进已经能够支撑较长任务；当前设计对执行期间的偏移和低效发现得不够及时，对视觉任务的独立质量判断也不充分。下一步设计重点应落在“何时能看见问题”和“凭什么判断通过”，而不是仅增加自动继续的能力。

## Dev Note：待讨论的改进建议

本节为未实施的建议，不表示已经批准修改产品行为。优先级表达本次诊断对讨论顺序的建议，不构成项目排期。

### 优先讨论：覆盖单个长轮次的进度检查

建议在现有轮次阈值之外，支持可配置的经过时间、工具调用量或重复失败信号。触发后在宿主支持的安全边界建立固定证据截止点，判断自上次检查以来是否有实质进展。长时间不应自动等于失败；有效推进时允许继续，重复无效操作时提出具体调整，需要改变用户要求时才请求决策。

实现前需确认宿主有哪些可用的步骤边界，以及检查与执行能否重叠、迟到结论如何失效、关闭 Supervisor 后如何取消挂起检查。应沿用单一续行控制器和持久 Session 事实来源，避免额外计时器形成第二个调度者。

验收应包含单轮连续大量调用但不结束的场景、持续有效推进的长阶段、重复失败阶段，以及用户关闭或修改任务时迟到审查不再生效的场景。阈值应可配置，不根据本次 47 分钟单独硬编码。

### 优先讨论：让要求来源可检查

建议区分用户直接要求、仍适用的项目约束、主 Agent 的实现选择及与当前目标无关的历史材料。计划审查同时检查缺失要求和无依据新增要求；源文件保留约束不应自动推出需要完成旧文件描述的任务。

这些来源应引用现有 Session 事件或项目文件，不维护第二份必须人工同步的目标历史。验收场景可复现本次“旧 CSV 工作区＋新视觉任务”，检查是否仍错误要求生成 CSV 报告。

### 优先讨论：按任务类型提供足够证据

视觉任务需要让审查者查看与阶段绑定的截图，必要时查看关键动作帧或可重复的短时序结果。图片应具备明确来源、时间或版本对应关系，沿用受限只读访问；无需为了视觉审查给审查者工作区写权限。

审查输出宜区分已直接检查的结果、仅有执行者自述的结果和证据不足的要求。验收场景应包含“结构测试通过但角色不可见”“动画参数正确但画面表现异常”等情况，检查是否仍无条件通过。

### 后续讨论：减少重复调试和证据负担

可探索稳定的截图姿态、连续时间步回放、诊断脚本复用及按问题选择关键帧，减少执行者反复编写有缺陷的临时检查脚本。应先测量重复诊断与图片重试的实际成本，再决定是否需要专门工具，不把新的测试基础设施变成每道任务都必须完成的附加目标。
