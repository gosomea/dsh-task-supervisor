# 读取纠错后的审查补交与折叠摘要

## 现象与原因

2026 年 10 月 9 日检查日常实例中的 DSH Go 长任务：M8 节点审查有两次读取错误，但随后成功读取了证据；审查者以普通文字结束，没有提交 `task_review_decision`。控制器把轮次中任意一次失败都当作结束故障，误判为读取失败，阻止原本允许的一次裁决补交。

这次异常不是 PTC 120 秒取消。前一节点曾发生审查超时，并在同一 Session 重试后续行；本次 M8 的原生结束原因是 `completed`。读取错误纠正和有效裁决是两件事：成功读取不能代替裁决，缺少裁决也不能把已纠正的旧错误当成最后的失败。

原生审查节点收起后只有“查看过程”入口，缺少醒目的状态和恢复动作。DAG 摘要还可能显示上一个节点的通过结论，用户难以分辨当前活动与之前结果。

## 修复行为

| 边界 | 当前处理 |
| --- | --- |
| 早先读取失败，后续工具成功，原生轮次完成但没有有效裁决 | 同作业有限补交一次，沿用审查 Session、证据截止点与当前截止时间 |
| 最后一次工具仍是读取失败 | 保留实际工具名、结果序号和脱敏错误，显示恢复入口 |
| 补交仍只有文字，或引用未实际读取的证据 | 保留故障并暂停，不无限补交，不以索引摘要代替证据 |
| 用户暂停、关闭或版本变化 | 沿用既有取消和失效规则，不新增执行授权 |
| 收起审查过程 | 保留 Supervisor 身份、类型、节点、状态、实测耗时和恢复信息 |
| 当前任务允许重试 | 摘要提供原生“重试审查”按钮；历史故障不提供当前任务动作 |

读取工具的说明补充索引页上限 50，以及先定位序号再读取原文的顺序。故障重试和裁决补交继续分别计数，原错误保留在实际审查 Session 中。

用户主动收起后，同一活动的流式更新及组件重建不会重新展开；活动结束后默认收起，新的活动默认展开。界面偏好有上限并在插件卸载时清理。展开仍使用公开原生对话工厂，只在审查区域隐藏原生输入座位，主 Agent 回答和输入框保持原生。只有已应用的裁决显示续行或完成提示，失效及失败作业不暗示执行已获准。

## 验证结果

针对性回归共 **124 项通过**：72 项覆盖审查补交、展示状态、事件映射、任务状态及引用清理；另 52 项覆盖控制器恢复、暂停和证据继承。后者使用名称筛选，117 项未被选择。Host／Client 严格类型检查、构建和打包通过。先运行旧代码上的负例，确认纠错后补交被错误拒绝，再修改实现并验证通过。

官方 `@deepseek-ai/dsh@0.2.0-rc.2` 隔离实例使用当天 CodeBuddy `deepseek-v4.1-flash`，同一 Session 完成两项只读数值核对任务，每项只批准一次。第一项通过测试代理注入确定性边界：计划审查最后一次读取失败；手动重试后由真实模型提交裁决；节点审查先出现两次读取错误，再成功读取，却以文字结束。控制器只补交一次，真实模型随后成功提交有效裁决，并自动完成整体验收。第二项使用普通路由，无故障注入，也完成节点与整体验收。

注入用例不计为自然发生的故障。真实模型还曾引用尚未读取的证据，工具拒绝后它补读并重交；通过结果没有绕过引用准入。这轮使用日志模式，不把读取主 Session 计为独立产物验证。

浏览器确认：异常摘要可直接看到故障与重试按钮；同一作业重试不生成第二个节点；实时更新期间主动折叠保持有效；展开保留实际工具错误而没有第二个可见输入框；760×900 窄屏摘要无横向溢出。刷新后两项任务对应六个不同的审查节点，历史展开不启动模型。浏览器验收发现一份候选包的原生插槽组合与发行版不兼容，已撤回该组合并重新安装最终候选包验证。
