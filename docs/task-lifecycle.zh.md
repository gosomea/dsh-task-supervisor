# 任务状态与控制提案

**状态：设计提案。** 本文负责容量、存储、命令路由和恢复。以下默认值是实现起点，尚未经过实测，也不是已发布的配置字段。

## 摘要

每个会话维护有限任务列表，同时只有一个执行名额。建议默认最多五个未结束任务，可配置为其他正整数。草案、排队、暂停和等待用户的任务都占名额；完成或 clear 的任务进入历史。任务内部的阶段不额外占名额。达到上限时明确拒绝新增并说明原因，不静默移除未完成任务。

右侧 Supervisor 面板展示所选任务、当前执行任务、阶段、证据、最近审查和下一步。选择卡片只改变命令目标，不切换正在执行的任务。另一任务须等当前执行释放名额后才能开始。命令提交时记录所选任务 ID 和版本，防止之后的 UI 选择将命令转交给另一任务。

## 一份状态文件

每个会话在宿主管理的会话存储中保存一份 `supervisor.json` 快照，放在主 Agent 工作区之外。JSON 便于严格校验、稳定 ID 和版本检查。Markdown 可作为生成的阅读导出，不作为第二份可写任务存储。确切的宿主存储 API 和位置仍需验证。[督导会话设计](session-runtime.zh.md)负责外部事件接入、持久化屏障、恢复时清理旧队列及控制器缺失时的执行限制。

现有 DSH 会话日志仍是用户指令、执行证据和督导持久事件的权威来源。先将接受的状态变更提交到日志，再准入依赖该状态的工作；JSON 快照和面板从已提交的日志前缀生成。JSON 包含 schema 版本和来源事件游标，采用原子替换，缺失或过期时可重建。这样不必另建事件日志，也不会让写到一半的文件成为权威。外部文件编辑不会自动导入。

| 快照内容 | 用途 |
| --- | --- |
| 会话身份、schema 版本、修订号、事件游标 | 绑定来源，识别过期更新。 |
| 督导启用状态、所选任务 ID | 恢复可见控件，不据此授予续行权限。 |
| 有限任务记录 | 保存稳定 ID、来源、目标、约束、验收标准、生命周期状态和排队顺序。 |
| 当前计划与阶段 | 保存版本、阶段目标、预期证据和阶段状态。 |
| 审查与决策引用 | 指向日志中的发现、待处理用户决策和证据游标。 |

完整会话内容和旧计划版本保留在会话日志中。快照只保留当前视图与引用，不无限复制历史。即使快照显示督导已启用，进程或会话启动时也必须先停用自动续行权限。

## 命令统一交给 Supervisor

斜杠命令和面板控件提交同一种持久控制请求。右侧面板确认收到请求、展示待应用状态，并显示处理结果。即使面板折叠或没有 GUI 连接，服务端仍会处理请求。请求携带幂等身份和任务版本，重试不能重复创建任务或重复执行控制动作。

`/task new <objective>` 创建任务；另一任务占用执行名额时进入队列。`/task plan <request>` 在同一容量限制下创建规划草案；裸 `/task plan` 打开或修订所选任务的计划。排队草案不向另一任务的活跃轮次注入指令。该任务获准执行后，由主 Agent 规划。已批准任务可跨轮续行；另一个排队任务开始执行前，需要自己的获批计划，以及明确启动或预先授予的队列启动授权。仅加入列表不授予这两项权限。

`/task edit` 立即记录用户更新、增加任务版本，并使基于旧版本的排队续行与审查决策失效。Supervisor 在下一个受支持的 steering 边界将更新交给主 Agent。主 Agent 提出修订计划；仍适用的已完成阶段和证据继续保留，只重开受影响的验收项。用户不需要确认人为的同步步骤。已经开始的工具副作用仍是日志中的事实，不能追溯取消，也不能标成新计划下的工作。

`/task plan off` 退出规划、撤销待处理的计划审批，并保留最新草案与历史。再次进入规划时，可在核对当前指令后复用草案。退出既不批准执行，也不静默恢复此前的执行阶段；该任务等待明确启动或恢复。如果任务的首次计划尚未批准，自主执行前仍须取得批准。

## clear、重新创建、fork 与重启

| 操作 | 拟议效果 |
| --- | --- |
| clear 所选任务 | 标记为已取消，从未结束列表移除，使其排队工作与决策失效，取消督导为它发起的执行轮次，并保留历史。不记为成功完成。 |
| clear 或完成后重新创建 | 分配新的任务 ID 和初始计划。复用旧文本或产物须明确进行，不静默继承旧批准与完成证据。 |
| 暂停任务 | 停用续行，并通过宿主取消机制停止督导发起的执行；保留部分结果和计划。 |
| 恢复任务 | 先核对更新的用户消息与工作区变化，再准入工作；尚未完成的首次计划批准与必要用户决策仍然有效。 |
| fork 会话 | 从选定持久前缀复制任务状态，给子任务新身份并记录父任务引用；未完成的子任务保持暂停，继承的待处理审批请求、计时器和在途审查工作失效。父会话不变。 |
| 重启或重新打开会话 | 重建状态，将未结束工作显示为等待手动恢复，并核对中断的执行。不能仅因为没有记录结果，就重放工具调用。 |

fork 不复制运行中的进程或外部副作用。已获批计划保留历史批准记录；手动恢复为子会话授予自己的执行权限。子审查者只能在获准的会话前缀内读取继承证据；完成检查必须针对子会话当前工作区。fork 会话本身不隔离工作区，因此子任务恢复执行前必须核对工作区使用情况。

## 关闭 Supervisor

面板提供明确的**关闭 Supervisor**控件，与**暂停任务**、**清除任务**及折叠面板分开。关闭会持久记录禁用状态、停用续行、取消审查工作和督导排队工作，并使待触发超时动作失效。督导发起的在执行轮次通过普通宿主取消机制停止；停止完成前 UI 显示“正在停止”。已发生的副作用不回滚，不取消无关的用户直接发起工作。

重新打开面板只展示状态。明确启用 Supervisor 后恢复控件，但任务仍需手动恢复。禁用时输入新的任务创建或规划命令会记录请求并显示督导已关闭，不静默开启执行。督导关闭期间仍可普通对话。

## 下一轮准入

只有督导已启用并明确开启续行、任务已取得执行授权、主 Agent 空闲、新用户输入已处理、没有待完成的必要审查或决策、任务状态已持久化时，控制层才能开启下一轮。它针对当前任务版本预留一次续行，并在准入时再次核对版本。编辑、暂停、clear、关闭或新的用户请求都会使旧预留失效。审查时机由[审查策略](review-policy.zh.md)负责。

下一轮指令包括当前目标与约束、当前阶段、已接受证据和一个具体下一步。指令进入日志并归属于任务。执行结果不明、确认停滞或审查失败时进入明确恢复状态，不能产生空转的自动轮次。暂时性审查失败的重试次数须在隔离宿主验证。

## Dev Note

完成后发现同目标缺陷，拟回原任务与原 DAG，保留此前完成；每次先展示影响范围并等待用户点击确认。重开提案、验收轮次、历史任务准入和工具约束由[独立验收与完成后返工方案](10-plans/independent-verification/plans.zh.md)负责。此流程尚未实现；取消任务不经该入口复活。

固定 schema 前需验证 DSH 存储 API、事件注册、活跃会话 steering、取消边界和 fork 前缀引用。初始任务容量为五，之后按实际使用校准。UI 文案和队列启动授权需要原型反馈。首版创建自己的任务；导入原生 Goal 或 Plan 状态属于未来可选工作，不是启用条件。
