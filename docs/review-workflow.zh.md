<a id="controls"></a>
## 用户动作

审查异常表示没有有效裁决；revise 表示发现不满足要求；needs-user 表示需要用户决定。界面保留原因和适用动作。

| 动作 | 含义 |
| --- | --- |
| 重试审查 | 原身份及期限有效时接续同一作业，不重置预算。 |
| 重新审查 | 新建作业并重新绑定产物，原故障保留。 |
| 跳过本次审查并继续 | 用户放行当前故障、修订或等待决策检查点；后续审查继续。 |
| 跳过审查并批准当前计划 | 一次动作批准当前完整计划，无第二次批准。 |
| 结束任务，未通过最终验收 | 仅最终检查点可用；进入 closed，不计为成功，不能直接恢复原任务。 |

放行不改写原结果，不伪造 pass，不改变宿主权限或容器限制。按钮绑定 Task 版本；动作保存作业、版本、节点尝试、时间及来源。模型没有放行工具。

<a id="budgets"></a>
## 预算与尺度

十分钟衡量模型投入，不是测试的自然最长时长。必要测试仍需审查断言、执行路径、产物身份和实际输出；静态要求可阅读验证，行为要求需要执行或复现。

| 配置 | 新作业默认值与边界 |
| --- | --- |
| reviewBudget.modelMs | 600000 ms；有效进展可延长 extensionMs=300000，至 modelMaxMs=1200000。重复读取、轮询和同一发现不提供延长资格。 |
| reviewBudget.reserveMs | 默认 60000 ms，短预算按十分之一缩短；用已有证据完成裁决，不启动新取证。 |
| independentVerification.commandDeadlineMs | 每条默认 300000 ms；管理员可配置至 7200000 ms，模型请求不能超出。 |
| reviewBudget.checksMs | 累计默认 1800000 ms，最大 7200000 ms；单条及累计限制同时生效。 |
| reviewBudget.wallMs | 总墙钟默认 3600000 ms，最大 10800000 ms，覆盖准备、模型、检查与恢复。 |

显式 reviewDeadlineMs 保留日志审查原总期限并禁止模型延长；显式 independentVerification.deadlineMs 保留独立审查原总期限。旧记录继续使用原截止与协议。外层更早的截止与取消优先；配置变化不迁移在途作业。

<a id="findings"></a>
## 发现与裁决

本场适用标准由控制器确定；覆盖错误一次列出 missing、extra、duplicate。日志模式用 record_review_requirements 逐项保存发现，最终可引用 result_ids；独立模式用 record_review_observations 保存部分发现，再用 task_review_observations 完成独立阶段，之后才能读取主汇报。

有效阻断项可提前返回修订或用户决策；未检查要求显式标为未验证。pass 仍要求适用原始要求及必要检查满足。连续三次相同裁决错误且无新有效进展会结束本轮，保留错误与发现；reviewInvalidDecisionLimit 配置该界限。

同作业重试复用原 Session、读取资格、快照和部分发现，不重置预算。跨作业不自动复制通过结论；产物、要求或环境变化后需重新取证。最终验收始终覆盖整体。

<a id="jobs"></a>
## 检查与恢复

新协议运行前持久保存 UUID、Session、快照、argv、cwd 和预算。工具返回 queued 并结束模型轮次；控制器等待原 Promise，再把收据送入原审查 Session。每份可变检查副本同时只运行一条命令。

网关 v2 保存准入与收据；collect 只收集，不创建命令。重复 UUID 必须保持请求完全一致。连接断开后执行仍受管理员原租约限制；显式取消等待清理确认。重启后优先读取原收据；缺少可靠收据保持 unknown，不自动重跑、不猜测结果。

完整、实际读取且绑定正确产物的输出才可支持验证。超时、取消、不完整输出、产物被修改和基础设施失败不能变成通过。

<a id="persistence"></a>
## 持久化兼容

新审查记录版本 9、qualityProtocol=1，增加预算、部分发现、错误进展与检查请求；Task 记录版本 16，增加用户放行历史、user-released 节点和 closed 终态；投影缓存版本 22。旧记录只读兼容，原日志不改写。旧插件不支持新状态，降级时保留日志并用旧实例查看旧 Session。

## 可选专项执行（D）

D 保持关闭。控制器后续可针对能力缺口选择一个有界执行器：静态检查、测试或浏览器验证。并非每次审查都创建团队。

| 契约 | 设计要求 |
| --- | --- |
| 输入 | 作业和要求身份、不可变快照摘要、标准 ID、允许能力、截止时间和取消信号。 |
| 输出 | 逐项发现、原始证据引用、已执行检查 ID、局限和耗时；不能修改 Task 状态。 |
| 调度 | 必须满足剩余模型／检查／墙钟预算和显式并发限制；专项执行器不能获得另一份预算。 |
| 冲突 | 发现冲突时由所属审查者检查原件，解决前保持未决；投票不能产生通过结论。 |
| 恢复 | 投递前保存执行器身份，收集原收据；未知结果保留，不自动重新执行。 |
| 启用 | 开放 profile 设置前补齐能力准入、拒绝、取消、崩溃恢复和证据冲突测试。 |

## Dev Note

后续跨作业缓存必须验证要求、产物及环境身份并保留来源链。D 专项接口应接收 scope、snapshot、capabilities、budget、AbortSignal，返回证据引用、发现、局限和耗时；当前未注册该执行器。
