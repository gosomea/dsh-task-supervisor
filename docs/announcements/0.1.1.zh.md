# dsh-task-supervisor：给 DSH 长任务加上督导、DAG 进度和阶段验收

我做了一个 DSH 插件 **dsh-task-supervisor**，想解决一个实际问题：Agent 连续工作时，计划有没有漏掉要求、当前执行到了哪里，以及它说“完成”时有哪些证据支持这个结论。

主 Agent 继续在原生 Session 中规划和执行。Supervisor 保存任务状态，在规划、阶段和完成检查点启动独立审查 Session，再由控制器决定继续、退回修订或等待用户。主 Agent 的回答保持原生输出，审查意见单独标明来源。

目前可以体验：

- **计划覆盖审查**：正式计划先对照原始要求，再等待用户批准；也支持明确预授权，在审查通过后执行。
- **DAG 与返工进度**：主会话看简略进度，侧栏看阶段详情、参与 Agent、审查依据及尝试次数。节点返工时保留原因和下游影响。
- **督导对话**：在侧栏讨论目标、询问进展，或明确要求暂停、恢复和关闭督导。
- **完成后修复**：先展示影响范围，经用户点击确认，回到原任务与 DAG，保留此前验收记录。
- **持久任务与历史**：重启后任务记录可以恢复，执行等待手动继续；同一 Session 完成一项后可以新建下一项任务。

*这是此前隔离验收的界面示例，展示节点从已通过进入新的返工尝试，以及受影响的依赖节点。*

**0.1.1 已发布到 npm，当前是开发预览版。** 已验证安装环境为 Node 24 与官方 DSH `0.2.0-rc.2`，可以安装到未经修改的 DSH，无需 Host 补丁或自行构建。沿用已有 Web profile 和模型配置：

```sh
dsh plugin --profile web add dsh-task-supervisor@0.1.1
dsh web
```

在空白 Session 第一轮模型对话前输入 `/task new <目标>`；如果要先讨论目标，在发送第一条消息前选择 Supervisor 模式。计划通过审查后，默认使用 `/task approve` 或侧栏按钮批准执行。已经开始的普通 Session 需要另建督导 Session。

想先做一个小体验，可以准备 `input.txt`，两行分别写入 `8` 和 `12`，然后输入：

```text
/task new 读取当前工作区 input.txt 中的整数，计算总和，用中文报告，保持文件不变。
```

默认审查读取主 Session 日志；**独立 Session 本身不等于独立验证产物**。需要审查者自行读取产物、复算或运行行为检查时，需显式配置独立验证模式和相应能力。独立浏览器观察还未实现，也尚无足够的长程对照数据支持“优于 Goal 或 Plan”的结论。当前版本若检查命令改变捕获的产物树，证据失效且后续检查会被拒绝；这项恢复能力仍在后续开发。

欢迎 DSH 用户试用，尤其希望收到计划遗漏、过早完成、误暂停、返工和恢复方面的具体反馈。反馈时请附 DSH／插件版本、复现步骤、预期与实际行为；日志请先去掉凭据和认证链接。
