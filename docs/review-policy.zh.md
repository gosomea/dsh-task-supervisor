# 审查与介入提案

**状态：设计提案。** 本文负责任务审查、检查点时机、证据访问和介入。建议阈值是暂定值，需要用真实任务校准。

**原型实况（2026-09-27）：** 计划提交已触发独立覆盖审查；阶段、进展、完成仍各用新审查 Session。原型增加 `read_task_call` 核对工具参数，并可在计划中声明 `read_only_turns_before_write`，对“批准后先完成只读轮次”实施写入门禁。下文的任意任务时序约束检查、用户配置超时等仍是设计目标。

## 摘要

审查任务目标、约束、阶段进展和完成证据。主要检查点是计划就绪、阶段切换和最终验收。普通工具调用不需要模型审查。DSH 继续负责基础工具权限；当前原型针对计划明确声明的只读轮次顺序增加确定性的写入门禁。其他动作约束仍交给审查者判断。

## 审查时机

| 检查点 | 用途 |
| --- | --- |
| 初始计划就绪 | 用户审阅前，检查计划对目标、约束、阶段和验收标准的覆盖。 |
| 声称阶段完成 | 核对预期证据，判断能否进入下一阶段；主 Agent 的声明本身不充分。 |
| 目标编辑或实质计划修订 | 核对受影响的要求与阶段；用户授权的变更无需再次确认同步。 |
| 最终完成申请 | 按当前产物和证据检查每项验收标准。 |
| 缺少进展或阶段持续过久 | 即使主 Agent 一直不报告阶段切换，也触发独立审查。 |

普通轮次边界由控制层检查任务状态和是否到达审查条件，不一定调用审查模型。暂定兜底窗口为：距上次接受的审查达到三个执行轮次或二十条工具结果，任一先到即请求审查。长轮次内在下一个受支持的安全步骤边界交付。只做低成本事件计数，不逐工具审查。重复失败检查可以提前触发，但重复本身不能证明停滞。确切阈值与边界支持需要验证。

必要检查点在受支持的边界挂起新的任务步骤，直到审查结束；已开始的工具允许收敛。新用户指令优先，使过时的审查决策失效。同一任务版本和证据截止点的多个触发条件合并成一次审查。默认每个检查点启动新的审查者；只有具体未决问题才调用专项审查者。审查者不能独立调度主 Agent。输出标明任务与计划版本、证据截止点、发现和建议的下一步。

审查默认跟随主 Agent 的有效模型选择，也可指定当前 DSH profile 中的模型；每个作业固定其解析后的配置，规则见[审查模型](review-model.zh.md)。恢复时使用[督导会话](session-runtime.zh.md)核对旧作业，不把重启或读取历史当作新审查许可。

## 每次审查判断什么

审查者检查四件事：工作是否仍符合当前指令，这个阶段是否产生有效进展，预期证据是否存在，以及建议下一步是否由证据支持。阶段结论可以是通过、需要修订或需要用户输入。缺少验收结果需要处理；超出用户标准的风格偏好不能成为让已完成任务继续运行的理由。

| 发现 | 建议默认响应 |
| --- | --- |
| 不需要行动的一般观察 | 仅记录。 |
| 有证据的跑偏、证据缺失或可恢复的失败方法 | 自动交付纠偏建议，由主 Agent 修订下一步。 |
| 相互矛盾的要求或只有用户能做出的选择 | 暂停并明确展示需要决定的事项。 |
| 尝试纠偏后确认停滞 | 暂停，等待用户手动恢复或调整方向。 |

保留三档可配置策略：仅记录、自动提醒、暂停请用户决策。严重度规则可以提升档位。每条发现引用指令或计划版本及支持它的事件 ID。暂停要解释具体后果和可选动作，不能凭空增加验收标准。

## 暂停与超时

计划、节点和整体验收由工具持久提交，Supervisor 在当前轮收敛后独立运行，见[审查作业生命周期](review-queue.zh.md)。审查自身超时是内部故障，不能自动放行、批准或完成任务。

阶段审查通常挂起下一次续行或阶段切换，不挂起任意工具调用。用户可以继续建议的下一步、接受建议让任务重新规划，或停止。自动提醒通过进入日志的主 Agent 指令交付。纠偏后的续行必须改变下一步或补充有用证据；反复发送同一提醒不算进展。

对配置了超时的普通审查提示，保留已商定默认值：超时允许原本挂起的下一步，并记录自动继续。具体时长仍待确定。续行前必须重新检查任务版本、督导启用状态、执行权限和新用户输入。过期超时不能复活已编辑、停止或 clear 的任务。

首次计划批准、不可缺少的用户决策、确认停滞后的恢复、手动暂停、重启以及关闭督导，不适用这项超时许可。超时不能将任务标为完成，也不能授予独立的 DSH 权限。接受审查建议会取消挂起的续行，并向主 Agent 交付具体重规划指令。

## 证据访问

会话读取工具绑定主会话。首次视图为最近已完成轮次；审查者向前展开，或从持久游标读取，覆盖整个尚未审查的区间。阶段跨越多轮时，只返回最后一轮并不足够。每次审查固定证据截止点，保留稳定事件引用，并在推进游标前读完缺失分页。较长的脱敏消息、工具输入或输出按需展开。

后来的用户编辑会使基于旧任务版本的控制决策失效。后来的执行证据留待下一次审查；发现可以作为历史观察保留，但不能批准超出其证据截止点的工作。工具不能选择任意会话，也不能写入主会话。读取任务状态不能替代读取原始证据。

## 最终验收

最终验收器按原始用户要求检查实际工作区结果；当前计划标准用于组织检查，不得削弱或遗漏原始要求。隔离副本必须包含任务相关的已提交、未提交和未跟踪产物；只检查仓库 HEAD 可能验收了另一份结果。记录产物身份、执行命令、输出和局限。结论绑定任务版本与已检查的产物快照；之后的相关变化会使它失效。此前节点通过不能自动推出组合交付物满足整体要求。

验收器返回通过、需要补做或需要用户证据。只有所有必要标准都有支持的通过结论，控制层才记录完成。基础设施失败或缺少凭证不能证明验收失败或成功，应产生明确的未决结果。验收器可要求修复未满足的标准，但不能用可选优化扩大范围。其检查不能修改主工作区。

## 决策记录

通过会话事件持久记录审查输入、输出、游标推进、介入和已交付消息。每项决策具有身份与版本检查，重复回调不能应用两次。审查报错或输出格式错误不算通过。必要审查在尝试恢复期间挂起续行；恢复失败后等待用户。重启行为遵循[任务生命周期](task-lifecycle.zh.md)。

本轮通用增强按[实施方案](review-quality.zh.md)推进：区分声明、日志记录和独立证据；审查者按原始要求选择验证方法。独立 Session 本身不能证明独立验证。

## 已实现的通用协议

`reviewVerification: log | independent` 明确选择实际验收模式。省略配置保留旧作业行为，不为其补造独立证据。独立模式公开快照读取和隔离命令运行范围；独立浏览器观察当前不可用。已知必要能力通过 `requiredVerification` 在投递前准备；规划审查声明的需求在实施批准前准备。只需读取不依赖命令运行器，缺少必要能力不能静默降级为通过。

独立审查先读取完整目标、必要的原始输入和适用约束，再列出产物与能力，以 `task_review_check_plan` 保存要求来源、需要确认的事实、方法、预期和覆盖。明确要求与推导假设分开；初始方案记录前不能展开交付物或运行检查。允许追加检查并保留修订，不按任务类别套用固定清单。

`task_review_observations` 保存每项检查的结果、实际证据、覆盖与局限后，才开放主汇报、执行日志与历史结论。对照阶段调查差异，`task_review_decision` 引用本作业实际读取或运行的证据。明确失败或未验证阻止通过，无用户依据的偏好不能阻断正确产物。退出码、文件存在或测试数量不能单独证明要求。

`read_task_evidence_index` 提供截止点内可筛选、分页的脱敏定位索引，关联工具调用与结果并标记错误、截断。正式引用仍须读取原事件；索引不替代证据。侧栏展示四阶段及逐项要求，指标记录工具调用、重复读取、阶段耗时、实际运行与全部 Session token。本轮保持既有进展审查频率。

审查记录 5 与投影缓存 16 兼容旧日志；新作业绑定固定产物快照，检查补交与恢复保持同作业身份。实际证据与能力边界见[验收记录](../eval/independent-verification/generic-quality-20260930/README.zh.md)。
