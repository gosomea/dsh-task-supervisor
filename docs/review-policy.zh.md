# 审查与介入提案

**状态：设计提案。** 本文负责审查时机、证据访问和介入语义。插件尚未实现这些行为。

## 摘要

督导检查主 Agent 是否仍在推进用户任务，以及完成申请是否有证据支持。每类问题都有可配置的响应档位。审查者必须引用会话证据，才可中断执行。

## 审查时机

| 检查点 | 用途 |
| --- | --- |
| 工具动作前 | 对明显且即将发生的规则命中做轻检；不在每次工具调用前运行完整独立审查。 |
| 执行轮次结束 | 新的独立审查者检查进展、偏离和建议的下一步。 |
| 里程碑或提前出现停滞信号 | 深入检查有效计划，以及是否需要更换方法。 |
| 申请完成 | 独立验收器检查证据和工作区验收结果，控制层才可结束任务。 |

控制层可针对狭窄问题调用专项审查者。其发现进入同一决策记录；专项审查者没有独立的续行或暂停权限。

## 问题类别与档位

| 类别 | 审查者要回答的问题 |
| --- | --- |
| 目标或约束偏移 | 下一动作是否仍符合绑定会话中用户当前的指令？ |
| 停滞或重复尝试 | Agent 是否在缺少新证据或进展的情况下反复使用同一方法？ |
| 缺乏证据的完成申请 | 是否缺少必要的验收证据，或仍有明确约束未满足？ |
| 高影响动作与副作用 | 拟执行动作的后果是否根据配置策略需要更强的检查？ |

每类问题可选三档：**仅记录**、**自动提醒**、**暂停请用户决策**。配置的严重度规则可为具体发现提升档位。暂停需要具体证据：引用的事件 ID、当前指令或计划版本、存疑动作和可能后果。证据不足的发现只记录下来供后续检查，不升级为暂停。

在提醒档，控制层向主 Agent 交付发现并记录交付，以便回放；主 Agent 随后决定如何修改计划或动作。在暂停档，用户可继续原动作、接受审查建议或停止该动作。接受建议会取消待执行的原动作，将控制权交回主 Agent 重新规划；审查者不能直接修改工作区。

用户可配置暂停超时。已商定的默认行为是超时后继续原动作，并记录“超时自动继续”。具体时长与各类别默认档位仍待确定。超时规则不取代 DSH 工具权限、沙箱检查或宿主要求的其他审批。

## 证据访问

审查者读取插件提供的绑定主会话视图，从最近已完成轮次开始。它可以请求更早的分页，也可以按需展开选定的脱敏消息、工具参数或工具结果。后续审查使用增量游标。工具返回稳定事件引用和轮次边界，使发现可以回到原始记录核验。工具不能接受调用方任意提供的 session ID，也不能授予主会话写权限。

最终验收器还读取工作区结果。需要执行验收命令时，它在隔离副本运行，并将命令、观察结果及局限性报告给控制层。主 Agent 的总结不能单独充当充分证据。

## 决策记录

每个审查检查点记录输入游标、发现、档位、控制层决策，以及已交付的提醒或用户选择。待执行动作和超时需要持久身份，避免回放时重复应用选择。宿主重启后重建这份记录，并按[架构](architecture.zh.md)要求等待手动恢复。

## Dev Note

待定策略：各类别默认档位、严重度阈值、暂停时长、提醒文案、模型调用预算、误报抑制、待执行工具动作与用户回复之间的竞态顺序，以及 DSH 暂停决策的传输方式。固定读取工具 schema 前，需要对照 DSH 会话存储验证脱敏与事件引用行为。
