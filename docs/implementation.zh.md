## 独立产物检查与两阶段审查

本节描述快照与运行器配置。显式 `reviewVerification: independent` 启用当前通用协议：先制定要求检查方案，再按需要读取或运行，发现持久化后对照主汇报。仅有旧 `independentVerification` 配置时保留旧协议。计划与进展仍为日志审查。当前证据见[通用验收](../eval/independent-verification/generic-quality-20260930/README.zh.md)，早期验收见[原记录](independent-verification-validation.zh.md)。

| 配置 | 含义 |
| --- | --- |
| `storageRoot` | 必填私有绝对路径，实际 Docker VM 必须可挂载；不得位于原任务目录中。 |
| `container.context`、`container.image` | 运行检查时必填本地 Unix Docker context 与已缓存不可变镜像 ID/digest；仅需读取时可省略。镜像含 timeout 和必要工具链，不自动拉取。 |
| `container.cpus`、`container.memoryMiB`、`container.pids` | 必填资源上限；模型不能改，部署选择由配置校验。 |
| `excludedPaths`、`maxFiles`、`maxBytes` | 默认仅排除 .git，10000 个条目、256 MiB；超限或越界链接失败，排除项进入快照。 |
| `runtimeLinkTargets` | 默认空。管理员可声明精确的绝对运行时链接目标；只捕获链接字符串，不读取宿主目标。原生文件读取仍拒绝越界，检查容器按自己的根目录解析。 |
| `commandDeadlineMs`、`commandOutputBytes` | 默认每条检查 300000 ms、每流 1 MiB；超时、取消或不完整输出不能验收。 |
| `checkGatewaySocket` | 可选私有 Unix socket；由独立管理员 profile 固定检查镜像、资源、产物租约和截止，任务容器不取得 Docker 管理权限。 |
| `deadlineMs` | 本增强审查总期限默认 1800000 ms，覆盖快照、检查和协议补交，不使用普通日志审查的 10 分钟默认值。 |

静态读取只消费现有 Host 文件系统；运行检查才查询 subprocess 与 Docker 能力。不把运行器增加为所有部署的必需依赖，也不依赖新增 sandbox 字段。Docker 后端要求本地 Host 文件映射、Docker 和匹配任务环境的镜像；跨平台生产覆盖尚未验证。检查副本只挂载 /check、网络关闭、根文件系统只读，不包含主目录、凭据或 Docker socket。缺少能力及清理故障明确记录为内部故障；不回退到宿主无约束执行。

可选管理员入口 `dsh-task-supervisor/check-gateway` 注册私有检查通道，不注册模型工具。网关将租约目录中的固定快照重新捕获到管理员私有目录，再挂载这个副本；任务传入的路径不直接成为 Docker 挂载源。取消请求等待原生进程和容器清理确认，重启按私有记录恢复，失去确认仍记为内部故障。macOS 的正式插件安装、原生 profile 加载与实际检查已通过；公开题的 Linux 分离容器部署另行准入，详见[接入记录](../eval/independent-verification/README.zh.md)。

旧协议以 `text` 标注静态标准、`runtime` 标注运行行为。新版由审查者按原始要求选择读取或运行，不仅依赖主 Agent 的 `evidenceKind`；独立视觉要求在浏览器能力完成前不能通过。本版不声称已独立验收游戏的出生、存档或水中行动。该独立验收迭代新增任务记录 11、审查记录 2 和投影缓存 12；旧日志证据级别不升级。读写分页、作业身份、原产物变化和检查源码改写由控制器准入，模型判断仍需外部 oracle 检验。

## 有限协议补交与手动恢复（B）

协议缺失或无效决策在同 reviewer Session 默认补交一次，可设置 `reviewRepairAttempts` 为 0–3；默认总时限 `reviewDeadlineMs` 为 600000 毫秒，允许 1–3600000，补交不重置时限。该默认值是开发起点，尚非最优频率或正式长程成绩。模型服务/读取故障不走协议补交循环；有效决策成功记录后，结束钩子错误不会覆盖它。

耗尽后 `/task retry-review` 核对原作业并恢复相同 Session、模型与截止点。显式手动重试开启新的有界恢复窗口，并记录尝试；它不批准计划或自动恢复暂停的执行，成功后按状态批准计划或 `/task resume`。旧作业过期、取消、编辑或关闭时不能应用迟到结果。证据见[步骤 B](10-plans/conversation-and-review-recovery/evidence/b.md)，恢复故障由确定性原生宿主夹具验证；联合真实运行及其边界见步骤 F。

## 原生集成

宿主入口是 [`src/index.ts`](../src/index.ts)：注册 `/task`、任务模型工具、生命周期监听器、工具执行保护和可选的 Web 路由。Web 客户端位于 [`src/client/index.tsx`](../src/client/index.tsx)，挂载到 DSH 右侧边栏标签，通过 Connection 已认证的 `/api/task-supervisor` Fetch 路由读取和控制绑定任务。主 Agent 的文本、Markdown 与附件继续由原生会话渲染，插件不复制成卡片。检查点成功落盘后允许一次无工具的模型收尾回答；这一步仍写入原生 assistant 事件，下一节点等回答结束后由唯一控制器调度。审查摘要单独标注 Supervisor，并从“查看审查”打开右侧对应全文。该路由不另开监听端口，返回由 Session 派生的状态。已关闭的 Session 可用有界的持久层分页读取；控制操作需要存活的 Agent。

任务记录保存在主 DSH Session 的原生 `agent/inbox/spliced` 事件中。带插件来源的内部消息在同一同步调用内插入并取消交付，payload 保留在持久日志，不进入模型对话。`src/session-records.ts` 为状态投影提供只读归一化视图；不写新事件类型，不伪造用户指令，不标记 `ignorable`。审查、草案、修复和督导绑定复用这一载体，原 seq 与时间保持不变。

`src/standard-host.ts` 将门禁挂到 Agent 作用域，不改变原生 preset；`task_create` 绑定真实用户消息，规划后等待 Task 批准。可选公开 Goal 服务解除原生自动续行，Goal／Plan／Todo 继续可用但不代替 Task 验收。默认无新模式；旧 0.1.1 preset 使用显式兼容配置。热卸载和装有插件的重启有门禁，插件冷缺失不保证拒绝。详见[原生模式中的任务督导](native-task.zh.md)。0.1.0 旧扩展日志仍用原 Host。

## 控制行为

初始计划需要一次明确批准。`task_submit_plan` 先发起独立的计划覆盖审查；未覆盖原始目标时退回主 Agent 修订，不提交为待审批计划。等待批准期间，主 Agent 可再次调用该工具替换整份待审批计划；批准始终作用于最新计划版本。规划勘察沿用 DSH 原生权限，不按工具名设白名单；批准前不实施交付物由规划提示约束。`/task <目标>` 持久记录原始命令为原生用户消息；`/task new` 保留为别名。单独 `/task` 等待下一条用户目标，不请求模型或批准执行。之后 `/task edit` 使旧计划失效并要求主 Agent 提交完整修订，不重复请求批准。计划可选填 `read_only_turns_before_write`，让控制层在批准后要求完成指定数量的只读模型轮次才准入写入。计数依据持久 Session 中完成的轮次和成功只读工具结果；中断轮次不算。已批准工作在每轮空闲后继续。`maxAutomaticRoundsWithoutReport` 默认三轮；到期由新的进展审查者决定继续、修订或请用户决策。阶段报告和最终完成申请各启动新审查。只有最终审查的通过裁决才转为 `complete`。

任务状态和督导消息先刷入持久层，之后才唤醒 Agent。重启时恢复投影，移除过期的督导消息；执行仍保持停用，直到 `/task resume` 或面板恢复按钮。中断的审查把已提交证据保存在持久状态中；手动恢复后要求主 Agent 核对当前副作用并重新提交审查。`/task off` 取消自有工作但保留任务记录；`/task on` 不自动恢复。督导清理旧消息时不删除用户输入。

## 当前限制

当前每个 Session 同时只执行一个任务；已结束任务从原生 Session 事件按需读取，可在同一 Session 中连续新建任务。尚无 `/task plan` 快捷入口、五任务队列、完整的 fork 产品协议、用户决策超时配置或独立浏览器用户路径验收，也未测出优于 Goal、Plan 或 Team 的长程优势。审查者可引用 Session 证据并裁决完成，但模型裁决不等同于独立基准评分。一次真实运行证明仅强化审查提示仍不足：模型先拒绝同轮读写，随后把历史违例误当作可通过重做修复。现有写入门禁只覆盖计划明确声明的“批准后先完成只读轮次”规则；其他不可逆约束仍缺少通用的确定性表达和执法。远端请求进行中的取消、Web 控件覆盖每种 Session 生命周期以及正式长任务留出集也尚未验证。隔离宿主扩展尚未成为标准 DSH 的公共接缝。

## V2 第一批：语言与续行上下文

任务记录版本 2 新增可选 `responseLanguage` 与阶段 `description`；读取器继续读取版本 1，不重写旧日志。新任务按正文识别中、英、日、韩文，或使用插件配置 `responseLanguage` 的明确 locale；无法判断时 `fallbackLanguage` 默认 `zh-CN`。模型系统提示、续行及独立审查均带语言策略。续行保留完整目标及当前验收标准，并加入当前阶段、通过节点和限长的最近审查摘要；摘要截断时提示通过 `task_status` 读取完整内容。第一批真实模型运行已验证中文输出，其他语言尚未实测。

## V2 第一批：用户决策与当前任务界面

任务记录版本 3 保存最近一次批准对应的计划版本和真实用户消息序号，继续读取版本 1、2。`task_status` 提供可用批准消息的引用；`task_approve` 校验任务、计划和直接用户来源，重复调用不重复续行。初版识别明确的“批准”“批准当前计划”等短句，含否定、引文或附带修改的消息不能作为批准；按钮和 `/task approve` 使用同一个批准转换。面板动作绑定任务 ID 与状态修订号，过期点击拒绝执行。

主会话通过原生 `conversation.input.dock` 显示简略 DAG、实际参与 Agent、当前任务摘要、通过节点数、最近审查短标题和动作；“查看详情”打开右侧完整计划。侧栏的“任务详情”和“督导对话”分为两个 Tab，独立滚动正文，底部操作栏保持可见。双方共用同一状态仓库与控制请求，重连重新取状态，旧查询不能覆盖新动作结果。动作来自宿主准入状态。审查历史保留最近 50 项；超出窗口的历史链接明确提示读取原始日志，不显示另一条审查。

第一批累计 34 项测试通过，包括模型轮次内批准后只续行一次、直接用户来源检查、过期动作拒绝、双击合并和挂载切换时轮询收敛。真实 CodeBuddy 任务验证了中文计划与独立审查、文字批准、关闭侧栏后的内联暂停/恢复、两个阶段及最终完成；工作区外复跑 5 个 Node 测试通过。原始模型推理仍可能为英文，不能由插件保证内部推理语言。详细环境及证据见[第一批验收](v2-batch1-validation.zh.md)。

## V2 第二批：来源与可分页证据

新计划标准必须标注用户要求、项目约束或实现选择，并提供可核对的来源。主会话与侧栏显示相同来源标签。记录版本 4 兼容版本 1–3；旧计划的缺失来源保留为未知，不自动升级为用户要求。

审查日志摘要标出截断与后续偏移；`read_task_text`、扩展后的 `read_task_call` 和 `read_task_context` 可继续读取固定截止点内的正文及完整任务上下文。独立审查检查来源是否支持标准，排除无关夹具；来源引用的结构校验不能替代语义判断。长轮观察与图片读取见下文；来源验证详见[来源与证据验收](v2-evidence-validation.zh.md)。

## DAG 状态与尝试身份

记录版本 5 增加节点依赖和独立执行记录。`dependsOn: []` 表示独立根节点；省略依赖的旧计划保持相邻依赖链。`stageIndex` 仅作为当前选择，不再代表通过数量。阶段报告可选择任意依赖已通过的节点，审查通过才释放后继，最终完成要求全部节点通过。

`task_rework_node` 使指定节点及其后继的验收失效，增加尝试编号，并保留无关分支。重新提交报告须携带当前 `attempt`；旧尝试不能用于新节点结果。暂停或中断的活动节点恢复后也进入新尝试，需要先核对副作用。新增宿主回归验证独立分支反序提交、汇合门禁和返工失效；图形界面、并行委派与集成真实模型验收仍在后续模块。

## 长轮观察

原生 `agent/pre-step` 安全边界按工具结果数量、经过时间或连续工具错误触发独立进展审查，不另建定时续行循环。默认阈值为 24 次工具结果、300000 毫秒或 3 次连续错误，可用 `observationToolCalls`、`observationIntervalMs`、`observationConsecutiveErrors` 配置，`observeLongTurns: false` 可关闭。无新工具活动不因墙钟时间触发。

通过或修订意见持久化后作为同一轮的原生用户消息进入下一模型步骤，不接受节点、不另开执行轮次。需要用户时暂停。观察回调必须匹配任务修订号，关闭或编辑会取消它。脚本模型回归覆盖活动量和受控时钟触发、不中断有效工作、关闭后的过期结果；真实模型验收与第二、三批集成一起进行。

## 原生图片证据

记录版本 6 保存视觉验收类型、节点尝试证据起点和已查看的图片序号。独立审查的 `read_task_image` 只能读取已分页查看、在本次截止点及节点尝试范围内的原生图片；附件存储校验内容后，以原生 image block 进入模型请求。视觉标准未读取图片时禁止通过。模型未声明图片输入能力、附件不可用或证据过期时，返回错误并要求审查者选择无法验证。

47 项内核检查通过，新增用原生附件存储验证图片进入审查模型请求、文本模型不能通过视觉验收、旧尝试图片被拒绝；这些检查不证明实际模型的视觉判断质量。

## DAG 图形界面

侧栏按持久依赖边绘制 DAG，同层节点纵向排布，汇合节点居中。节点只显示短标题和状态；悬停或键盘聚焦显示说明与验收标准，点击选中节点后可持续阅读完整详情。窄侧栏横向滚动。颜色、边框与背景复用 DSH Web 主题变量。主会话使用同一图组件的紧凑模式，进行中默认展开，完成后默认收起；显式展开选择按任务保留。节点与参与 Agent 点击后打开右侧对应详情。

## 持久督导对话

`/task consult` 或侧栏“打开督导对话”复用绑定当前主 Session 和任务的原生 Session。侧栏通过原生 SessionProvider 和 conversation.content 插槽提供历史、输入框、模型控制及 /compact；不自行实现聊天日志或压缩器。新问题注入带时间、截止点和版本的任务快照，普通问询只读。重启后原绑定继续使用，主任务仍等待手动恢复。

明确的“暂停任务”“恢复任务”“批准计划”“关闭督导”或“修改任务要求：完整目标”可以由 `supervisor_control` 转交同一控制器。工具核对当前直接用户消息和任务版本；主 Session 先保存 received 回执，再保存 applied/failed。重复 user seq 不重复执行；中断留下 received 时需核对现状。旧任务对话及 fork 出的督导对话不能控制原任务，恢复前历史指令不能自动重放。48 项宿主检查通过；原生嵌入、实际压缩和模型问询留待集成验收。

## 受控原生并行

主 Agent 可用 `task_delegate_nodes` 同时委派依赖就绪的节点，默认最多 2 个，`maxParallelNodes` 可设 1–8。记录版本 7 保存原生子 Session、当前尝试、子日志截止点及主会话集成起点。写入范围须为工作区内的确切文件；原生文件系统解析后的目标身份不能重叠，目录范围暂不准入。子 Agent 可读、检索、写入和编辑自己的文件；命令执行及最终集成由主 Agent 完成。控制器不自行产生另一条主任务续行循环。

子任务提交报告后进入“等待主 Agent 集成复验”。主 Session 必须在子任务结束后产生成功的集成工具结果（默认 bash/read_image，可用 `integrationTools` 配置），才能发起节点审查。审查者必须读取绑定尝试的子日志和主会话集成证据，通过后才释放依赖。暂停、关闭、修改任务会取消在途子任务，旧版本不写回结果；恢复时使用新尝试并核对副作用。

50 项检查及分别执行的宿主、客户端严格类型检查通过。原生文件系统测试同时阻塞两个模型请求，确认真实并发；拒绝跨节点文件写入、冲突文件归属及未集成报告，验证关闭后不写文件、不续行。成功的工具结果仅作为准入条件，是否覆盖正确验收仍由独立审查和外部评分判断。该共享目录策略暂不支持子任务运行任意 shell；需要 shell 的节点由主 Agent 串行执行，分工作树的任意工具委派属于后续扩展。

## 联合验收中的规划语义修正

真实模型曾把前置节点的集成验证放在依赖前置节点通过审查的后继节点，并把用户明确要求标为实现选择。独立审查首次漏报；该次运行不能算通过。规划工具与审查契约现明确依赖表示审查通过、验证应在提交节点审查前完成，并要求保留用户指定的节点数和来源分类。50 项内核检查与双端严格类型检查通过；真实模型重跑另行记录。

## 中断审查恢复与压缩配置

只读审查中断后恢复保留该次执行和已完成 worker 的日志截止点，只重新提交审查；尚在执行或需要返工的节点才推进尝试号。回归覆盖保留 worker 证据且后继仍被门禁阻止，51 项检查通过。真实浏览器发现隔离 Web profile 未挂载原生压缩命令，现按 README 配置原生后端；普通文本 `/compact` 被模型误称压缩成功的运行记为失败，并在侧问契约要求原生命令结果。

## Web 作用域集成修正

真实 Web preset 把文件工具注册在主 Agent 作用域；仅读取全局工具目录导致 worker 没有文件工具。委派现从主 Agent 的原生工具视图显式注册 read/glob/grep/write/edit，保留工具执行和文件写入边界。内核测试改为同样的作用域布局，防止根作用域夹具掩盖问题。视觉读取也补齐 Cordis `llm` 服务注入；此前真实审查遇到服务缺失后正确暂停，没有凭主 Agent 描述放行。

## Worker 正常结束与失败收敛

原生 worker 可以通过 `task_worker_done` 或正常结束轮次后的最终文本提交报告；后者使用 DSH 的 `finalAssistantOutput` 规则，只接收正常完成且非空的文本，仍需主 Agent 集成和独立审查。异常/空报告进入暂停并结束当前主模型轮次，不在已暂停状态继续重试。回归包含父作用域文件工具、正常文本报告、空报告及暂停后不再产生模型步骤。
