# 督导对话简化

[English](consultation-layout.md)

## 界面

外层“任务督导”标签承担页面标题。内部顶部仅保留“对话 / 详情”、简短状态和原生更多菜单。历史任务与使用帮助按需打开；计划与要求版本位于详情。删除常驻用途说明、讨论对象、输入模式切换和压缩说明，给原生对话留出空间。

草案通过原生回合尾部插槽展示，来自配对成功的 `supervisor_update_draft` 或 `supervisor_create_draft` 工具结果。创建按钮核对主会话当前草案身份与版本；旧卡片不创建新版本。待确认问题、执行中的其他任务仍阻止创建。顶部仅保留当前草案的一行定位入口。

## 单一入口

普通问询保持只读。宽泛目标可以先整理草案；明确的 `/task <目标>`、“创建任务：完整目标”或“建立任务：完整目标”交给主会话控制器。已有草案可点击“建立任务”或输入“按这份方案建立任务”。“修改任务要求：完整修订要求”走原要求修订流程，保留版本及批准约束。

不根据“继续”等含糊消息授权创建，不从历史、工具结果或督导自己的回复提取授权。完成后的缺陷仍展示影响范围并要求点击确认重开。主 Agent 回答和原生思考／工具折叠逻辑保持不变。

## 旧版本行为变化

旧 `input-mode` 记录继续读取以保留历史，但 `direct` 不再决定后续消息含义。旧 `consult-mode` 请求启用 `direct` 返回明确错误；`discussion` 请求兼容。已有任务、草案、审查、压缩和修复记录不改写。

## 验收

针对性测试覆盖问询与创建区分、旧 direct 记录不授权、草案工具调用与结果配对、失败与非法结果不生成卡片，以及同回合修订。宿主测试覆盖普通问询不创建任务、真实模型保存草案、明确创建、初始计划等待批准。浏览器检查菜单、原生回合草案、展开要求和创建按钮。

机器证据见 [consultation-layout-checks.json](consultation-layout-checks.json)。本项没有调整独立审查策略或自动续行频率。
