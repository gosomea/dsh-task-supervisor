# 独立验收开发与验证

## 步骤 2：产物快照与插件检查运行器

状态：插件内运行器基础已验收。DSH 原生源码保持原有接缝基线，不使用新增 sandbox 字段；用户 59909、61454 和冻结公开题运行器没有更新。正式模型接入状态见步骤 3。

快照包含实际工作树中的未提交、未跟踪文件，默认仅排除 `.git`；排除、文件数和字节上限明确记录。复制前后清单必须一致，捕获竞争最多重试两次；越界链接、指向排除内容的链接及特殊文件拒绝。只读基线和可写检查副本不共享 inode；原产物变化使审查失效，检查改写源文件也不能据此验收原产物。

检查运行器由插件拥有，消费现有 DSH subprocess 服务调用本地 Docker。管理员必须配置本地 Unix context、已缓存的不可变镜像和资源上限；不自动拉取镜像、启动 VM 或修改主 Agent 沙箱。每次检查只挂载当前检查目录，禁用网络，根文件系统只读，移除 capabilities，禁止提权，使用宿主 UID/GID 和独立 HOME/TMP/缓存。宿主原目录、只读基线、凭据与 Docker socket 不挂入容器。镜像必须提供 `/usr/bin/timeout` 和任务需要的工具链。

结构化 argv 不由插件拼接成 shell。DSH 受管进程退出及容器身份核验、删除、确认消失均完成后才发布证据；持久容器记录支持恢复中断后的本次资源。镜像内超时仍约束 Host 退出后的命令。只清理具有匹配名称与快照标签的资源，不按端口或猜测名称结束其他任务。

检查记录分别保存退出码、超时、取消、输出完整性和源码变化，并包含镜像、context 与容器身份。Docker 路径以数值退出码记录结果，不推断 OS 信号，`signal` 为 null。缺失隔离、工具链或资源清理失败属于基础设施故障，不产生任务通过结论。

## 步骤 3：两阶段模型审查

状态：代码已接入，脚本化模型反例通过；真实 CodeBuddy 模型验收正在进行，不能据此宣称完整生产验收已完成。

脚本化反例在首次阶段屏蔽主汇报，通过独立容器断言发现减法冒充加法；先持久记录发现才解锁汇报，最终拒绝错误实现。其他回归拒绝未读完整输出、变化产物、未验证项与用静态阅读批准运行时标准，并独立记录检查基础设施故障。主 Session 原生任务输入与 PTC 勘察回归也通过。

首次真实节点运行暴露插件缺少 subprocess 服务注入，检查未执行成功。已暂停该测试，保留原审查 Session 与失败工具记录；修复可选服务声明及故障后结束轮次，再做真实正反例。此运行不能计入独立执行通过证据。

## 原生沙箱实验记录

此前原生 sandbox 实验仅保存在 fork 的实验分支，未合入上游，也不是插件安装前提。macOS 严格策略及 SDK 适配实验曾出现内核退出等待，SIGKILL 未立即回收；这些进程不计为清理通过。正式插件采用以上容器运行器；此前原生沙箱测试不能替代插件路径验收。
