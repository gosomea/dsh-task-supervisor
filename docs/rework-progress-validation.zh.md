# 返工说明与主节点执行状态验收

## 行为与原因

节点通过后可能在集成中发现缺陷。`task_rework_node` 打开新的尝试并使依赖它的下游尝试失效；此前通过仍是历史事实，不能接受新的尝试。主会话显示短返工通知、节点状态、尝试次数和原因；侧栏保留完整原因、原状态、受影响节点及此前审查。

主 Agent 实施前调用 `task_start_node(stage_id, attempt)`，记录执行 Session、开始时间和 `running`。同一正在执行的尝试重复调用不会增加修订；过期尝试、依赖未通过、已停止任务及另一个主 Agent 节点正在执行时均拒绝开始。委派节点沿用已有执行记录。普通问询和会话忙碌不会被推断为节点开始。

成功的原生返工调用与结果是说明的来源。投影兼容旧结果中的任务快照，新结果额外保留调用时的精确原状态；失败调用不生成返工记录。投影只保留最近 50 项返工与审查，不补造未保留的审查正文。历史任务继续从同一原生日志按需读取。

## 验证范围

这是节点状态与返工解释的验收，不是长程对照测评。第一次准备误将 `/task new` 文本通过普通 prompt API 发给模型，未执行命令；已取消该准备会话并改用原生命令控制器创建有效案例，其诊断过程不作为功能证据。

显式开始依赖主 Agent 使用工具；没有原生开始记录的旧行为不会被界面猜测为执行中。此轮在独立分支和隔离实例验证，不覆盖正在运行的原 59909 部署。
