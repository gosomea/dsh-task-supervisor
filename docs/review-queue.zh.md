# 控制器持有审查作业

本文说明计划、节点与整体验收的提交、取消和恢复。验证范围见[验收证据](review-queue-checks.json)。

## 提交与运行

`task_submit_plan`、`task_report_stage`、`task_request_completion` 在返回前保存审查作业及任务状态：任务与计划版本、节点尝试、证据截止点、审查 Session ID、模型路由和自身截止时间。任务进入“审查中”，工具返回 `queued: true`、作业 ID，并结束本轮。返回成功仅表示提交成功；通过结论必须来自有效且已应用的裁决。显式关闭计划覆盖审查的旧配置保留无审查路径。

Supervisor 等待主 Agent 当前活动收敛，使用公开 `withoutInitiator` 与 `runMaintenance` 运行已保存作业，不持有已结束工具调用的取消信号。审查期间依赖节点不得推进。裁决落盘后，控制器复核任务版本与产物新鲜度，才更新 DAG 并交付下一步或原生文字摘要。计划需要修订时可以继续规划；首次执行仍须原有批准或明确预授权。

原生和 PTC 工具使用同一机制。PTC 默认预算仍为 120 秒；程序正常结束产生的 `run_code settled` 不再取消已交接的审查。

## 取消与手动恢复

| 来源 | 结果 |
| --- | --- |
| 审查自身截止时间 | 保存 `timeout` 和可重试故障，暂停；`/task retry-review` 从同一作业恢复。 |
| 用户暂停或关闭督导 | 取消审查、撤销续行；等待手动恢复。关闭后须先开启督导，不能自动重试。 |
| 主 Agent 在提交后主动停止 | 尚未运行的作业保留为已提交；等待 `/task resume`，不投递审查。 |
| 任务或相关产物变化 | 旧裁决不能应用；修改后的要求或产物需有效审查。 |
| 插件卸载、宿主退出或重启 | 收敛自有运行工作；保留作业与证据。新宿主不自动投递，等待 `/task resume`。 |
| 外层 PTC 正常结束 | 已交接作业继续运行。 |

手动恢复保留原作业、审查 Session、要求、计划、节点尝试和证据截止点，建立新的审查尝试及截止时间。它不授予实施许可；恢复后批准计划或手动恢复实施。已有独立快照仍须通过新鲜度检查。补交协议与独立检查继续使用既有规则。若有效裁决已落盘但尚未应用，手动恢复复核产物后采用原裁决，不再投递模型。

普通取消不可一律变成可重试故障。历史 `run_code settled` 仅在原日志能关联本次嵌套提交与对应根调用的真实超时结果时，追加可重试超时记录；不改写原事件，不自动恢复，不将用户取消升级为超时。

## 持久格式与边界

任务记录 15、审查记录 6 与投影缓存 19 增加控制器归属、排队状态和绑定作业身份，继续读取旧格式，不补造旧产物证据。排队 Map 只管理当前进程准入，不是新的权威状态库。每项控制工作均有生命周期清理，卸载等待其收敛。

本实现留在插件内，复用公开 Agent、Inbox、Session 及已有审查器；未修改 DSH 主循环、原生沙箱或 PTC 预算。进展观察保持既有策略。独立读取、运行或浏览器检查的能力范围不因这次生命周期修复扩大。
