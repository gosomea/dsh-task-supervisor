# 督导交互与长程审查改进提案

## 摘要

本文以神社真实运行校准下一版交互与控制协议。目标是让用户在主 Session 看见工作、审查和待办决策，并让督导在长轮次中发现偏移。第一批已实现并完成两条真实模型验收；第二、三批的来源与证据分页、长轮观察、视觉读取、DAG、持久问询和受控并行均已实现，已完成受控小任务的[联合真实模型与浏览器验收](v2-integrated-validation.zh.md)，完整神社重跑与正式长程对照仍待进行。现有行为见[实现状态](implementation.zh.md)。保留主 Session 的权威控制记录、唯一续行控制器和独立只读审查，增加持久督导对话与真实任务依赖图。

## 语言与续行

持久保存任务 `responseLanguage`，支持 auto 与显式语言。优先级建议为：用户明确语言要求、显式 profile 响应语言、auto 对创建任务的用户正文判断、profile 回退语言（本场景简体中文）。后续明确切换语言才更新；英文代码、引文、工具结果、督导注入消息不改变任务语言。规划、主 Agent 汇报、审查、侧问和续行使用同一策略，压缩后从任务记录恢复。界面 locale 分开管理，路径与协议枚举不翻译。

VS Code 提供 `github.copilot.chat.localeOverride`，默认 auto，可指定回复语言；GitHub Copilot 个人指令支持持久语言偏好。参考“自动＋显式覆盖＋持久注入”，仍需验证模型遵循情况。用户可见解释应使用选定语言；原始推理文本受模型能力影响，不能承诺控制内部思考语言。[VS Code 设置](https://code.visualstudio.com/docs/agents/reference/ai-settings)、[GitHub 个人指令](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-personal-instructions)。

续行包从权威状态和已有报告生成：目标/计划版本、当前节点标题、已验收成果、最近结论、未解决问题、下一步与范围约束、关键产物及证据截止点。摘要有界，溢出内容提供分页引用，不静默截断硬约束。区分“主 Agent 声称完成”与“审查已确认”。续行包进入原生 inbox 并持久化，界面显示摘要和展开详情。

## 主会话与侧栏

主 Session 保留原生主 Agent 回答。当前任务小框显示简略 DAG、节点状态、执行者、参与 Agent、通过节点数、最近 Supervisor 摘要和操作；完整节点与审查详情通过点击打开右侧。节点标题和审查首行由模型生成简短摘要，完整正文保存在原字段中。历史审查单独标注 Supervisor，不再包装主 Agent 提交卡片。通过节点数不冒充工作量百分比。

右侧分为“任务详情”和“督导对话”两个 Tab。详情包括目标、DAG、节点说明、验收标准与审查历史；对话使用独立原生 Session。Tab 切换保留草稿与对话挂载，常用动作置于不随正文滚动的底栏。主会话与侧栏共用同一版本投影和动作服务，重连取快照并拒绝陈旧响应。审查中提供暂停，只有中断或暂停才提供恢复。

成功检查点留下一个无工具的原生收尾步骤，模型生成自己的计划或结果说明；不合成、改写或替换主 Agent 输出。该步骤后才允许控制器调度下一轮。受督导任务不再维护 `todo_write` 的第二份进度清单。实现和真实验证见[界面验收](v2-ui-validation.zh.md)。

## 任务图与并行

节点增加 `description`、`dependsOn`、验收引用和需求来源；执行记录保存状态、尝试编号、执行 Session、时间及证据/审查关联。校验 ID、依赖存在、无环与标准覆盖。旧线性计划迁移为相邻依赖链，不推断不存在的并行关系，不重写旧日志。节点状态区分待依赖、可执行、执行中、审查中、通过、需修订、等用户、失败和取消。执行结束进入审查，通过才释放依赖；返工是同一节点的新尝试，不在 DAG 塞回环。上游产物改变使受影响下游验收失效，并取消或核对其在途执行。

神社任务候选结构：先定公共接口，场景骨架/地形、建筑设施、角色资源分支；环境动效依赖场景构件，角色行为依赖地形、角色和落叶接口；最后汇合集成、视觉验收和交付。这是重新规划建议，不是从十阶段自动还原出的 DAG。先实现依赖与节点状态并保守串行，随后开放主 Agent 的原生子 Agent 委派；控制器检查节点/尝试身份和并发上限，限定模块所有权、串行化冲突写入，必要时分工作树。子产物集成复验后才完成节点，唯一续行权仍归控制器。

## 用户决策

持久决策绑定 `decisionId`、任务/计划版本、节点、原因、选项、来源及处理结果。需要人的节点默认无限等待，不循环调用模型；明确配置的超时规则单独展示，未设置规则不自动批准。初版建议暂停整个任务，未来可显式选择仅阻塞相关分支；重启后仍手动恢复。参考 LangGraph 的持久 checkpoint、interrupt 和明确 resume 语义，继续使用 DSH 原生持久化。[LangGraph Interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts)。

按钮、命令与自然语言批准走同一动作入口。模型工具转交决定时携带待决事项和真实用户消息引用；宿主核对可信输入来源、范围与版本，不能把模型自述、引文或督导提示当作授权。无歧义的“批准当前计划”一次生效，无需重复点击；多个待办或版本变化时明确待选择对象。决定先在主 Session 持久化再准入执行；actionId 去重，编辑、关闭及新控制版本使旧批准、审查和续行失效。

## 持久督导对话

提供与任务绑定的原生 Supervisor 对话 Session，连续侧问、持久消息、独立模型路由和原生压缩；每次独立审查仍使用新 Session。对话 Agent 解释现状并传递用户决定，审查 Agent 对固定证据裁决，界面统一入口并能跳转审查。侧问观点不自动注入独立审查上下文，任务事实仍从主日志读取。

默认问询读取带截止点的任务快照和证据，注明观察时间；不向主 Agent 发消息、不取消审查、不改变执行许可。明确的“暂停”“复查 S8”“修改要求”通过控制工具介入，返回已接收/已应用/失败回执；模式按钮辅助表达，明确文字指令也可生效。对话 Session 保存问题和动作引用，主 Session 保存控制结果，用 actionId 去重及查询回执，避免假定跨日志原子双写。介入在安全边界收敛，未知副作用先核对，修订淘汰旧审查。

压缩复用 DSH，任务状态不依赖摘要；压缩后恢复任务绑定、语言、控制版本、待办和读取游标，按需取历史。默认继承 DSH profile 的有效模型，可在 profile 内覆盖。fork 建立新任务绑定，不能控制原任务；清空对话、重建 Agent、关闭任务语义分开。原生 slot、压缩、恢复和模型路由的具体接入需先验证宿主契约，不另建一套会话日志。

## 审查与证据

保留计划、节点、完成审查，增加时间、工具活动量、重复失败触发的进度观察，在安全步骤边界读取固定日志前缀。时间长只触发查看，不等于跑偏；正常进展不阻断，修订或用户决定经控制器核对版本后介入。每任务限制同时观察数量、合并重复触发，不新增续行循环。

验收标准区分用户要求、适用项目约束、实施选择、可选增强，并附来源。审查同时查漏项和无依据扩项，防止只读轮次、帧数、离线依赖等实施选择变成用户硬要求；已批准内容仍须按版本修订。对工具结果增加截断标记、按偏移分页和相邻事件；当前 700/1,500/3,000 字符限长不替代完整证据。视觉证据通过原生附件提供绑定版本、生成时间的只读图像/产物；动画用多个时刻或视频加行为测量。看不到必要证据返回无法验证，不能从文件名或主 Agent 描述判通过。

审查输出按“结论 → 检查内容 → 问题/不确定性 → 下一步”给中文摘要，证据展开查看。每节点聚焦对应标准，历史顺序约束引用已核查证据，避免反复长篇讨论不相关门禁。最终审查覆盖全局要求和集成产物。

## 实施与验收

| 顺序 | 交付 | 必须验证 |
| --- | --- | --- |
| 1 | 语言、续行摘要、统一决策、主会话任务块与侧栏 | 中英混合任务中文汇报；文字批准一次生效；旧版本拒绝；侧栏关闭仍可操作；审查中不误显示恢复。 |
| 2 | 需求来源、长轮观察、原始与视觉证据 | 长单轮可观察；正常工作不误停；CSV 残留不扩项；未看图不声称视觉已验；关闭后旧回调不续行。 |
| 3 | DAG、持久侧问、受控并行 | 无环与返工失效；两个无冲突节点并行并集成复验；问询不打断，介入绑定版本；压缩和重启恢复问询，执行等手动恢复。 |

第一批已用小任务验证。第二、三批合并开发与真实模型验收：按 DAG 状态、节点审查与视觉证据、持久侧问、DAG 界面及受控并行的依赖顺序连续推进；模块完成后做必要的确定性检查并提交推送，全部接通后复用现有隔离部署统一验收，不逐模块重复启动真实小任务。最后在干净目录运行神社类任务，保留原 Session 为回归样本。新增漏项、扩项、人工等待、长轮停滞、过期审查和缺少视觉证据案例。正式效果对照沿用[评测协议](evaluation.zh.md)，同模型、任务、工具和环境比较 Goal、Plan、Supervisor 与明确审查的 Team，分别报告成功、假完成、偏移持续时间、人工干预、耗时与用量。

### 第一批：让用户看懂并控制任务

**为什么先做：** 这次用户输入“批准”没有落到控制层，中文任务变成英文汇报，当前状态隐藏在侧栏，续行只重复目标。先修通用户意图、控制动作和状态反馈，后续 DAG 才有可靠的交互基础。

**交付范围：** 持久响应语言与统一提示；带当前阶段、通过节点、最近审查和下一步的续行摘要；带任务/计划版本及用户来源的批准入口；主会话当前任务折叠块与侧栏共用状态和按钮；阶段详情及历史审查浏览。模型报告与审查身份继续分开。

**验收：** 中文目标混有英文代码仍注入中文响应约定；重启后语言保留；自然语言批准仅处理当前计划，拒绝过期、引用和自动消息授权；双击不重复推进；关闭侧栏仍可批准/暂停；审查中显示暂停而非恢复。复用现有真实宿主回归，再在干净隔离环境用日常模型验证。

**提交边界：** 可以拆成语言与上下文、控制协议、Web 交互三个可独立验证的提交；每个提交通过对应检查后立即推送，不把未通过的实现混入下一批。

### 第二批：让审查覆盖长轮次与真实产物

**为什么做：** 单轮 121 次工具调用绕过现有进度审查；文字日志无法独立验收视觉产物；旧样例和实施偏好被升级为任务标准。只有持续观察和可读取的证据才能支撑长程纠偏。

**交付范围：** 需求来源及范围检查；安全步骤边界的时间/活动量进度观察，合并重复触发；调用与结果的分页原文读取和截断提示；绑定版本的只读视觉证据；明确区分通过、需修改和证据不足。保留唯一续行控制器和旧审查失效机制。

**验收：** 一个长轮次会触发检查；正常进展不因耗时长被判失败；关闭或编辑后旧观察不生效；日志溢出可继续读取；未看到必需图片不能通过视觉验收；清洁神社任务不会包含 CSV 指标。时间与异步测试使用受控时钟和确定的结束屏障。

**提交边界：** 来源与证据读取、长轮观察、视觉审查分别验收推送；测试报告记录审查能力与仍未验证的模型判断质量。

### 第三批：任务依赖、持续侧问与受控并行

**为什么做：** 线性 stageIndex 无法表达独立分支；一次性审查不提供连续交流；直接并行写文件会引入冲突和错误完成。因此先建立节点身份与依赖，再增加不会打断执行的对话，最后开放执行并发。

**交付范围：** 真实 DAG 与旧线性记录兼容读取；节点尝试、依赖释放及返工失效；主会话实时 DAG 和节点详情；原生持久督导对话、压缩恢复、查询/介入工具；主 Agent 原生委派、并发上限、资源归属、集成复验。不会把新图形界面称为已经支持并行。

**验收：** 拒绝环和未知依赖；旧 Session 可恢复；返工使受影响后继失效；两个无冲突分支真实并行后汇合验收；侧问不取消主执行或审查，明确介入有可追踪回执；压缩后恢复任务绑定；宿主重启不自动执行；人工待办默认无限等待。

**提交边界：** DAG 数据与调度、DAG 界面、持久督导对话、并行委派各形成通过检查的提交并推送；最终用隔离真实任务验收三批集成行为。
