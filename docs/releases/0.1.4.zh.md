# 0.1.4：完整报告与明确审查范围

2026-10-09 完成验收。发布等待 npm 账号认证；本记录区分验收完成与公开可安装状态。

## 变更

主 Session 通过原生 Markdown 默认展开完整持久 `finding`，原生工具过程单独折叠。不追加模型总结，也不伪装成主 Agent 消息。长报告沿主对话滚动；浏览器本地偏好分别保存正文与过程的折叠选择。已提交、已应用、失效、历史及当前被用户取消的审查使用不同状态解释。

新作业固定 Task 身份、要求／计划版本、节点尝试、证据截止点与定位范围。早先约束保留来源与归属不确定性。`read_task_evidence_batch` 最多展开六条已定位原文，逐项返回错误、读取范围、截断与后续位置；摘要与失败读取不能提供引用资格。第 8 版记录继续读取版本 1–7，保留其原协议与许可。

计划、节点与整体验收保存要求级来源、方法、实际证据、状态、覆盖与局限。独立模式复用检查方案与已保存的发现。明确要求未满足或未验证时不能通过；无关推导偏好不能阻断正确产物。最终验收检查当前完整快照。续行包含实际范围、已确认与未完成要求、修订、证据及就绪节点，实际下一步由控制器决定。

改动留在插件中；审查频率、DSH 主循环、PTC 超时与原生沙箱保持原值。本轮未新增独立浏览器或视觉执行器。[审查过程](../review-experience.zh.md)说明恢复与能力边界。

## 配置与升级

`reviewReadCorrectionAttempts` 默认 `1`，范围 `0–1`，同作业跨故障重试累计。它限制审查轮结束于可识别参数、分页或定位错误后，控制器额外投递的纠正轮。普通原生轮内自纠仍留在工具历史，不算额外纠正轮。纠正与协议补交不延长本次截止时间，也不产生新授权。

继续保留临时故障的有限重试与有效原许可续行。用户暂停、关闭、重启及需要用户决定时仍手动恢复。旧作业不补造证据、要求级结果或续行权限。

发布后安装到普通原生模式 profile：

```sh
dsh plugin add --profile <your-profile> dsh-task-supervisor@0.1.4
```

实例空闲后再升级；本轮始终保留日常 3080 的原进程。

## 冻结开发对照

基线 6cccfd3 与候选运行版本 52dcbb0 使用同一官方 Host、提供方、profile 选项、夹具、批准策略、审查频率、固定顺序和 900 秒截止。两种夹具各一次配对重复，共四个位置；暂停后不救场。试验后补了一处纯展示修正：六个后端／运行器 .mjs 与试验包逐字节相同，仅 client.js 变化。最终 tarball 已重新干净安装并用于浏览器验证。

| --- | --- | --- | --- | --- | --- |
| 静态会议记录 | 1 / 1 | 224.114 / 295.120 | 859,816 / 1,377,401 | 57 / 56 | 2 / 9 |
| 数据计算 | 1 / 1 | 242.968 / 272.073 | 1,444,692 / 1,182,938 | 70 / 48 | 3 / 6 |

两版都通过确定性产物／内容核验。候选每场审查保存 5–7 项要求级结果；旧基线没有此字段，表示历史证据缺失，不能解释成零覆盖。候选成本并未稳定下降，较严格裁决校验带来更多轮内纠正的工具错误（配对审查错误均来自裁决提交）。两版内部故障重试与控制器读取纠正轮均为 0；按工具名＋参数的完全重复读取指标均为 0。

独立正例：657.017 秒、4,705,865 个记录 token；反例：283.864 秒、1,399,483 个 token。两者夹具文件均保持不变。反例 oracle 验证拦截与暂停，不表示任务完成。独立审查工具失败分别为 35 与 10 次，包括已轮内纠正的协议／参数尝试；不宣称零错误运行。token 含缓存输入，不等于付费 token；未报告用量的失败请求未知。

更早诊断 Session 已保留，但排除在对照外：运行器在 Agent 忙碌时请求批准，初期误把错误回执记作批准。同 Session 续查保持截止，基线 759.215 秒完成，候选到 902.036 秒截止后暂停。修正后的冻结运行器等待空闲并校验回执。另一次最终测试启动遗漏存储父目录，造成 20 项 ENOENT 夹具失败；创建必要目录后完整重跑 452 项通过，两类事件都未冒充通过证据。

这是本地开发夹具的一次重复，不是公开基准或统计优势结论。没有盲审标签的误验收与误暂停指标保持 null。未验证 Windows、其他浏览器、独立视觉判断及其他 DSH 版本。
