# 0.1.7: actionable requirement-source errors

User-message requirement sources use `source.reference=seq:<message number>`, for example `seq:594`. Quoted user text belongs in `requirement`. The tool schema explains this format before the model submits its decision.

Malformed locators return `INVALID_REQUIREMENT_SOURCE_REFERENCE` with the field index and correction. A valid locator whose source has not been read returns `UNREAD_REQUIREMENT_SOURCE` with the exact seq to read. Correcting a locator does not require reading an already delivered source again. Evidence eligibility and acceptance rules remain enforced.

The live 0.1.6 review exposed repeated quoted-text locators and misleading reread errors. Its original job and deadline are retained. The correction is delivered as a separate 0.1.7 package; it does not patch an active reviewer or inject a rescue prompt.
