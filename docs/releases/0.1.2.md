# 0.1.2 Tasks in native DSH modes

English | [中文](0.1.2.zh.md)

Published on 2026-10-08 to the [official npm registry](https://www.npmjs.com/package/dsh-task-supervisor/v/0.1.2), with `latest` at `0.1.2`. The public tarball matches the validated package byte for byte.

## Changes

Create supervised Tasks without selecting a separate Supervisor mode. Use `/task <objective>`, bare `/task` followed by an objective, or ask the main Agent to create a Task. Native Goal/Plan tools remain available for organization; Supervisor owns Task approval, continuation and acceptance.

The sidebar uses a compact conversation header and inline task drafts. The main Session retains native answers and shows DAG progress, participating Agents and review notices. Review details show actual activity, elapsed time, deadline and the next action; activity counts are not completion percentages.

Formal plan, node and completion submissions persist review jobs and return promptly. The controller runs the review after handoff, outside the initiating PTC call's waiting budget. Pause, close, stale versions, review deadlines and restart retain distinct cancellation and recovery behavior. Completed Tasks support read-only diagnosis, explicit next-task creation and repair proposals requiring confirmation of impact.

## Install and upgrade

```sh
dsh plugin --profile web add dsh-task-supervisor@0.1.2
dsh web
```

Keep active work settled or paused before restarting the Host to load the upgrade. New Tasks use native modes; set `legacyPresets: true` only when restoring 0.1.1 dedicated-preset Sessions. Do not rewrite 0.1.0 private-extension logs; those require their original Host.

## Validation and boundaries

The [release check record](0.1.2-checks.json) records build, strict Host/Client typing, kernel regressions, package contents and installation checks. Existing isolated real-model and UI evidence for this source is recorded in [native Tasks](../native-task.md), [controller review handoff](../review-queue.md) and [review progress](../review-progress.md); a packaging check is not a new model or browser test.

Log review remains the default. Independent artifact reading and isolated execution require explicit configuration; independent browser observation remains unavailable. Reviews can miss defects. This release does not establish superiority over Goal, Plan or Agent Team; see the [README](../../README.md) for the full lifecycle and limitations.
