# 0.1.6: recover expired reviews and read blocked Task state

## Recovery

A paused Task with an expired review offers **Start a new review** (`/task restart-review`). This explicit user action creates a new job, reviewer Session and deadline. The failed job, its evidence cutoff, failure history and original deadline remain unchanged. The new review binds the same requirements, plan, node attempt and submitted evidence; changed bindings or stale control revisions are rejected.

A new review does not grant execution permission. Plan acceptance waits for user approval, and previously approved work waits for manual execution resume. Automatic recovery and `/task retry-review` retain their original job deadline.

## Diagnosis

Paused, reviewing and disabled Tasks expose `task_status` directly, including with PTC presets. Opaque programs and execution tools remain blocked. Status and guard errors identify the phase, fault and available user controls. Leaving the blocked state restores the preset's tool presentation.

## Host compatibility

The reviewer writes the public versioned one-shot descriptor before publication. The current Host's continuable-only descriptor builder is not used for this controller-owned reviewer. Type declarations import the persistence service definition explicitly, and source fixtures mount the current JSONL plugin namespace.

## Delivery

Install the validated local `dsh-task-supervisor-0.1.6.tgz` through `dsh plugin --profile web add /absolute/path/to/dsh-task-supervisor-0.1.6.tgz`, then reload the Host after checking active work. A local tarball deployment does not establish npm publication. Historical regression scores and user Task records retain their original identities.
