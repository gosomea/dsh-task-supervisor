# 0.1.8：审查恢复操作与下一步

按钮与命令共用当前 Task、要求／计划版本、节点尝试、失败作业及截止时间的恢复判断。原作业仍可恢复时提供“重试审查”；任何故障超过原截止时间、明确不可重试或产物失效时，提供“重新审查”。新作业保留旧故障，使用新 Session 和预算；不延长旧作业，也不授予任务执行权限。缺少记录或绑定已变化时，不提供审查恢复，并说明通过 `/task edit <完整目标>` 重新规划会清除原批准。

用户暂停或宿主重启后的中断审查，若已过期，点击“恢复任务”会显示新的故障状态与“重新审查”操作。已持久提交的裁决可继续应用，仍检查产物有效性，不重复请求模型。要求变化、产物检查和执行批准规则继续适用。

仅加载历史记录时，当前任务显示“连接会话”。该操作通过原生会话服务执行 `/task status`，不发送模型 prompt，也不启动审查或任务。历史任务保持只读。连接失败在按钮附近显示错误和命令后备入口。

审查故障按凭据、模型配置、请求服务、产物、快照／运行器或内部错误说明处理方向。提示根据当前操作生成，不把禁止恢复的故障写成“可手动重试”。用户决策暂停提示先在主对话说明决定，再恢复任务。恢复请求失败会在当前审查卡片显示，成功的后台状态刷新不会抹掉该错误；再次操作清除上次错误。

本版本不修改持久记录 schema，不自动重跑已失败的审查，不放宽证据校验，不发布 npm。
